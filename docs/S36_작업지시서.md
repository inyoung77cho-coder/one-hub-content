# S36 작업지시서 — 카카오 로그인 첫 시도 실패

> 작성 2026-09-13 · 계기: 사용자 보고 "카카오 인증 후 '로그인에 문제가 있었습니다', **다시 시도하면 정상**"
> **S35보다 먼저 실행할 것.** 첫 화면에서 나는 오류라 이탈에 직결됩니다.
> U1 촬영에 로그인 장면이 들어갑니다 — 이게 고쳐진 뒤에 찍어야 합니다.

---

## 0. 증상과 원인

### 증상 (사용자 보고)

```
1) /login 화면 → "카카오로 시작하기"
2) 카카오 인증 완료
3) /login 으로 돌아와 "로그인에 문제가 있었습니다. 다시 시도해 주세요."
4) ★ 다시 누르면 정상 로그인
```

**재시도하면 된다는 점이 핵심 단서입니다.** 설정 오류(키·리다이렉트 URI 불일치)라면 매번 실패합니다. 매번이 아니라 첫 번째만 실패한다는 건 **상태가 한 번 유실되고, 두 번째엔 남아 있다**는 뜻입니다.

### 지금 구조

`pages/api/auth/kakao/start.js`
```js
res.setHeader("Set-Cookie",
  `oh_oauth=${state}.${encodeURIComponent(next)}; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=600`);
```

`pages/api/auth/kakao/callback.js`
```js
const savedState = /* oh_oauth 쿠키에서 */;
if (!savedState || savedState !== state) return res.redirect("/login?error=bad_state");
```

**CSRF 방어가 쿠키 하나에 전적으로 걸려 있습니다.** 그 쿠키가 어떤 이유로든 콜백 시점에 안 오면 무조건 실패합니다.

### 쿠키가 유실되는 경로 (후보)

| 후보 | 설명 | 재시도하면 되나 |
|---|---|---|
| **인앱 브라우저 전환** | 카카오톡 앱으로 인증 후 다른 브라우저 컨텍스트로 복귀 | ✅ 맞음 |
| **start 중복 호출** | 링크 프리렌더·중복 탭으로 state가 덮어써짐 | ✅ 맞음 |
| **도메인 불일치** | `www` 에서 시작 → `app` 으로 콜백. 쿠키는 host-only | ✅ 맞음 (단 `next.config.js:32` 에 www→app 리다이렉트가 있어 가능성 낮음) |
| **Max-Age 600 만료** | 카카오 인증 화면에 10분 이상 머묾 | ✅ 맞음 (드묾) |

**어느 쪽인지 단정하지 않습니다.** 대신 **네 가지 모두에서 살아남는 구조**로 바꿉니다.

## 1. 전제 조건


## 배치 FA — 쿠키에 의존하지 않게

### S36-1 · 서명된 state ★핵심

**할 일**

state를 난수 문자열이 아니라 **서명된 토큰**으로 만듭니다. 그러면 쿠키가 없어도 검증이 됩니다.

```js
// start.js
const payload = { n: next, t: Date.now(), r: crypto.randomBytes(8).toString("hex") };
const body = base64url(JSON.stringify(payload));
const sig  = crypto.createHmac("sha256", SECRET).update(body).digest("base64url").slice(0, 22);
const state = `${body}.${sig}`;
```

```js
// callback.js
const [body, sig] = String(state || "").split(".");
const expect = crypto.createHmac("sha256", SECRET).update(body).digest("base64url").slice(0, 22);
if (!body || !sig || !timingSafeEqual(sig, expect)) return fail("bad_sig");
const p = JSON.parse(base64urlDecode(body));
if (Date.now() - p.t > 10 * 60 * 1000) return fail("expired");
const next = p.n && p.n.startsWith("/") && !p.n.startsWith("//") ? p.n : "/pwa";
```

**요점**

- `next` 가 state 안에 들어가므로 **쿠키 없이도 목적지가 복원**됩니다
- 서명이 있으므로 **공격자가 state를 위조할 수 없습니다** — CSRF 방어는 유지됩니다
- 타임스탬프로 재사용·만료를 막습니다
- `SECRET` 은 기존 세션 서명 키를 재사용하거나 `KAKAO_STATE_SECRET` 환경변수를 새로 둡니다. **하드코딩 금지**

**쿠키는 없애지 말고 보조로 남기십시오.** 쿠키가 오면 대조해서 한 겹 더 확인하고, 안 오면 서명만으로 통과합니다. 이게 방어 심층입니다.

```js
if (cookieState && cookieState !== body) return fail("state_mismatch");  // 있는데 다르면 진짜 이상
// 없으면 통과 — 서명이 이미 검증됨
```

**비교는 `timingSafeEqual`로** 하십시오. 길이가 다르면 먼저 거르고 비교합니다.

### S36-2 · 자동 1회 재시도 — 사용자가 오류를 아예 못 보게

**할 일**

S36-1로 대부분 사라지겠지만, 그래도 실패하는 경우가 남습니다. **사용자에게 오류를 보여주기 전에 한 번은 조용히 다시 시도합니다.**

```
callback 실패 (복구 가능한 사유)
  → /api/auth/kakao/start?next=<원래목적지>&retry=1 로 바로 되돌림
  → 사용자는 카카오 화면을 한 번 더 보고 로그인됨 (오류 문구 안 봄)
  → retry=1 인데 또 실패하면 그때 /login?error=... 로
```

**★ 무한 루프를 반드시 막으십시오.** `retry` 파라미터가 이미 있으면 절대 다시 시도하지 않습니다. 이 조건을 빠뜨리면 사용자가 카카오 화면과 앱 사이를 무한히 오갑니다.

**복구 가능한 사유만** 재시도합니다.

| 사유 | 재시도 |
|---|---|
| `bad_sig` · `expired` · 쿠키 유실 | ✅ 재시도 |
| `no_code` (사용자가 취소) | ❌ 그냥 `/login` 으로 |
| `token` · `profile` (카카오 API 오류) | ❌ 오류 표시 — 재시도해도 같습니다 |
| `server` | ❌ 오류 표시 |

## 배치 FB — 실패해도 품위 있게

### S36-3 · 문구를 사유별로 나누고, URL을 정리

**할 일**

**(a) 문구 분기** — 지금은 모든 사유가 같은 문장입니다.

```js
// pages/login.js
const MSG = {
  no_code:  "로그인이 취소되었습니다.",
  token:    "카카오 서버와 연결하지 못했습니다. 잠시 후 다시 시도해 주세요.",
  profile:  "카카오 정보를 받아오지 못했습니다. 잠시 후 다시 시도해 주세요.",
  server:   "일시적인 문제가 있었습니다. 잠시 후 다시 시도해 주세요.",
};
// 그 외(bad_sig·expired 등)는 S36-2가 자동 재시도하므로 화면에 안 나옵니다
```

**"문제가 있었습니다"를 쓰지 마십시오.** 사용자는 자기가 뭘 잘못했는지 앱이 고장인지 모릅니다. **무엇이 안 됐는지와 지금 뭘 하면 되는지**를 말하십시오.

**(b) URL에서 `error` 지우기**

지금은 `/login?error=bad_state` 가 주소에 남습니다. 로그인에 성공한 뒤 뒤로 가면 **오류 화면이 다시 보입니다.**

```js
useEffect(() => {
  if (router.query.error) router.replace("/login", undefined, { shallow: true });
}, [router.query.error]);
```

문구를 state로 옮긴 뒤 주소를 정리하십시오.

**(c) 버튼 중복 클릭 방지**

`<a class="kakao">` 를 한 번 누르면 비활성화하고 "이동 중…" 으로 바꿉니다. start 중복 호출이 원인 후보 중 하나입니다.

### S36-4 · 원인을 남기십시오

**할 일**

지금은 `console.error` 만 있어 어느 단계에서 깨졌는지 사후에 알 수 없습니다. **구조화해서 남기십시오.**

```js
console.error("[kakao] fail", JSON.stringify({
  reason,                       // bad_sig | expired | token | profile | server
  hasCookie: !!cookieState,     // 쿠키가 왔는지  ← 이게 핵심
  host: req.headers.host,       // www 인지 app 인지 ← 이것도
  ua: (req.headers["user-agent"] || "").slice(0, 80),  // 인앱 브라우저 판별
  retry: !!req.query.retry,
}));
```

**개인정보를 넣지 마십시오** — 카카오 id·닉네임·이메일·토큰은 절대 로그에 남기지 않습니다.

이 세 줄(`hasCookie`·`host`·`ua`)이면 **며칠 뒤 Vercel 로그에서 진짜 원인을 확정**할 수 있습니다. 지금은 추정뿐입니다.

## 배치 FC — 검증

```
[기능]
□ npm run build (= next build --webpack) 성공
□ 정상 로그인이 한 번에 됨 (오류 화면 안 거침)
□ ★ 쿠키를 강제로 지우고 콜백해도 로그인 성공
    재현: 카카오 인증 화면에서 개발자도구로 oh_oauth 삭제 후 진행
□ ★ state를 한 글자 바꾸면 실패 (CSRF 방어 살아 있음)   ← 반드시 확인
□ 만료 검증: state의 타임스탬프를 11분 전으로 만들면 실패
□ retry=1 상태에서 또 실패하면 무한 루프 없이 /login 으로 1회만 이동
□ 로그인 취소(카카오에서 뒤로) → "로그인이 취소되었습니다"
□ 로그인 성공 후 뒤로가기 → 오류 문구가 다시 보이지 않음
□ next 가 보존됨: /pwa/assets 로 진입 → 로그인 → /pwa/assets 로 복귀

[환경]
□ www.one-hub.kr/login 으로 들어가도 정상 (app 으로 리다이렉트 후 로그인)
□ 카카오톡 인앱 브라우저에서 정상
□ 모바일 사파리 · 크롬에서 정상

[원칙]
□ 쿠키가 없을 때 '그냥 통과'시키지 않았다 — 서명으로 검증한다   ← 눈으로 확인
□ 로그에 카카오 id·닉네임·이메일·토큰이 없다
□ SECRET 이 하드코딩되지 않았다
□ git diff 에 CRLF 유령 변경 없음
```

**"state를 한 글자 바꾸면 실패"를 반드시 직접 확인하십시오.** 이 스프린트에서 가장 위험한 실수는 로그인을 되게 만들려다 CSRF 방어를 없애는 것입니다.

## 3. 별건 확인 요청

사용자가 보내온 로그인 화면 텍스트에서 링크 글자가 비어 보였습니다.

```
받은 것:  "로그인 시 및 에 동의하는 것으로 간주됩니다"
코드:     "로그인 시 [이용약관] 및 [개인정보 처리방침]에 동의하는 것으로 간주됩니다"
```

`pages/login.js` 의 마크업은 정상입니다(`<a href="/terms">이용약관</a>`). 복사 과정에서 빠진 것일 수도 있으나, **실제 화면에서도 링크 글자가 안 보인다면 `.note a` 의 색상이 배경과 같은 것**입니다. 확인하고, 안 보이면 색을 고치십시오 — 약관 링크가 안 보이는 건 표시 의무 문제이기도 합니다.

# 1부 · 대본 쓰기

## 1. 세 시리즈는 대본 구조가 다릅니다

같은 틀로 쓰면 안 됩니다. 무엇이 화면을 채우느냐가 다르기 때문입니다.

| 시리즈 | 구조 | 화면을 채우는 것 | 난이도 |
|---|---|---|---|
| **사용법 (C)** | 타임라인형 | 손가락 조작 | 쉬움 |
| **주간 리포트 (B)** | 블록형 (5블록 고정) | 녹화 화면 다섯 장 | 쉬움 |
| **스토리 (A)** | 서사형 | **거의 없음** | 어려움 |

**사용법**은 화면이 주인공이고 나레이션이 종입니다. 초 단위로 "무엇을 누르는지"를 적습니다.

**주간 리포트**는 `/pwa/weekly-report`가 초안을 만들어 줍니다. 사람이 쓰는 건 블록③ 하나뿐입니다.

**스토리**가 진짜 어렵습니다. 보여줄 화면이 없어서, 대본에 **화면 지시를 따로 설계**해야 합니다. 이 차이를 모르고 스토리부터 찍으면 촬영 당일 화면이 비어서 멈춥니다.

## 2. 분량 — 글자를 세지 않으면 항상 두 배가 됩니다

말하기 속도 **분당 330자**가 기준입니다(S32의 대본 자동초안도 같은 값을 씁니다).

| 영상 길이 | 나레이션 글자수 | 비고 |
|---|---|---|
| 4분 | **1,100자** | 사용법 기본 |
| 5분 | 1,400자 | |
| 7분 | 1,900자 | 스토리 기본 |
| 8분 | 2,200자 | 스토리 상한 |

표의 숫자는 **1,320자(4분×330)가 아니라 1,100자**입니다. 화면 전환·조작 대기·호흡으로 15~20%가 말 없이 지나가기 때문입니다. 이 여백을 빼지 않으면 대본대로 찍었는데 5분이 나옵니다.

**대본을 다 쓰면 글자수를 세십시오.** 눈대중은 항상 틀립니다.

넘치면 자르지 말고 **덜어내십시오.** 잘라낸 문장은 어색해지지만, 문단 하나를 통째로 빼면 티가 안 납니다.

## 3. 후킹 20초 — 영상의 절반입니다

첫 20초에서 시청자가 남을지 정합니다. 나머지 7분을 아무리 잘 만들어도 여기서 나가면 소용없습니다.

### 구조

```
① 구체적인 장면 또는 숫자     "삼성전자 마이너스 18%"
② 그게 내 얘기라는 신호        "3년 동안 팔지 못했습니다"
③ 이 영상에서 얻을 것          "왜 못 팔았는지, 진짜 문제가 뭐였는지"
④ 결론을 먼저                 "종목이 문제가 아니었습니다"
```

**④가 핵심입니다.** 결론을 숨기면 사람들은 기다려주지 않습니다. 결론을 먼저 말하면 "왜?"가 생겨서 남습니다.

### 금지

```
✘  "안녕하세요, 한곳지기입니다"          ← 정보 0. 0:20에 하십시오
✘  "오늘은 ~에 대해 알아보겠습니다"      ← 학교 수업
✘  "구독과 좋아요"                      ← 아무것도 안 준 상태에서 요구
✘  긴 배경 설명                         ← 본론이 늦으면 나갑니다
```

### 자기소개의 자리

```
0:00  후킹
0:20  "한곳지기입니다."       ← 딱 이 한 줄
0:22  본론
```

첫 편에서만 한 번 길게 말하십시오 — *"흩어진 걸 한곳에 모으자고 만든 앱이라, 저는 한곳지기라고 부릅니다."*

## 4. 목소리만 낼 때의 문장 규칙

얼굴이 없으면 **문장이 곧 얼굴**입니다.

### 한 문장 40자 이내

```
✘  3년 전에 지인이 반도체가 오른다고 해서 삼성전자와 하이닉스를 샀는데
   그때는 정말 확신이 있었고 주변에서도 다들 그렇게 말했기 때문에
   별로 의심하지 않았습니다.

✔  3년 전이었습니다.
   지인이 그러더라고요. "반도체 슈퍼사이클 온다."
   그때는 확신이 있었습니다.
```

말로 하면 긴 문장은 숨이 찹니다. **쓸 때 소리 내어 읽어보십시오.** 한 호흡에 안 되면 자르십시오.

### 접속사를 지우십시오

"그래서 / 하지만 / 그런데"가 문단마다 나오면 지루해집니다. 대부분 지워도 뜻이 통합니다.

### 숫자는 읽는 대로

```
✘  -18%           →  ✔  마이너스 18%
✘  2026.09.12     →  ✔  9월 12일
✘  1,682,288KB    →  ✔  1.6기가
```

화면 자막은 숫자로, **나레이션 대본은 읽는 대로** 적으십시오. 촬영 중에 변환하려면 반드시 버벅입니다.

### 호흡 표시

목소리만이라 호흡이 편집점이 됩니다. 대본에 표시해 두십시오.

```
> 3년 동안, 저는 이걸 팔지 못했습니다. 【쉼】
> 오늘은 왜 못 팔았는지 이야기해 보려고 합니다.
```

## 5. 대본 템플릿

### 사용법 (C) — 타임라인형

```markdown
# U○ · 제목
**목표 길이** ○분 · **재생목록** 사용법 · **발행** ○주차

**제목 3안**  (서로 다른 각도에서)
**썸네일** 큰 글씨 한 단어 + 폰 화면

### 0:00 – 0:20 · 후킹
> (나레이션)
**화면**: (무엇을 보여주는지)

### 0:20 – 0:50 · ○○
> (나레이션)
**화면**: (실제 조작)
**자막**: (버튼 이름)

...

**핵심 한 문장**: (이 편에서 하나만 남긴다면)
```

**규칙**: 구간마다 `**화면**`이 반드시 있어야 합니다. 없으면 그 구간은 찍을 수 없습니다.

### 스토리 (A) — 서사형

```markdown
## ○화 · 제목
**목표** ○분

**제목 3안** / **썸네일 문구**

**[0:00–0:20 후킹]**
`[화면] (정지 이미지 또는 자막)`
> (결론 먼저)

**[0:20–1:40 시작]**
`[화면] ...`
> ...

**[마무리]**
> (앱으로 자연스럽게 이어지는 한 줄)

**챕터** / **태그** / **고지 문구**
```

**규칙**: `[화면]` 지시가 빈 구간이 하나라도 있으면 대본이 미완성입니다. 스토리는 여기서 실패합니다.

### 주간 리포트 (B) — 블록형

사람이 쓰는 건 **블록③ 하나**입니다. 나머지 넷은 `/pwa/weekly-report`가 만듭니다.

```
① 이번 주 숫자        40초 · 220자   자동
② 이번 주 만든 것     100초 · 550자   자동 (개발용어 번역층 통과)
③ 배운 것·틀린 것     120초 · 660자   ★ 사람이 씁니다
④ 시장에서 있었던 일  100초 · 550자   자동
⑤ 다음 주에 할 것     40초 · 220자   자동 (하나만)
```

**블록③ 쓰는 법** — 앱이 후보 3~5개를 뽑아줍니다. 하나 고르고 세 문장으로 살을 붙이십시오.

```
무엇이 있었는지  →  "손절 규칙 R7이 이번 주 네 번 중 세 번 틀렸습니다."
왜 그랬는지     →  "하락 폭만 보고 거래량을 안 봤습니다."
그래서 뭘 바꿨나 →  "거래량 조건을 넣었습니다. 다음 주에 결과가 나옵니다."
```

**만든 게 없는 주에는 없다고 말하십시오.** "이번 주는 안정화만 했습니다"가 억지로 만든 항목보다 낫습니다.

## 6. 스토리 시리즈의 화면 — 여기가 진짜 문제입니다

목소리만 내기로 했으니 스토리 7분 동안 화면을 채울 것이 필요합니다. **다섯 가지면 충분합니다.**

| 화면 | 만드는 법 | 쓰는 곳 |
|---|---|---|
| **자막 카드** | 검은 배경 + 큰 문장 한 줄 | 후킹, 전환점 |
| **앱 화면 녹화** | 시연 계정, 마스킹 | 앱이 등장하는 대목 |
| **단순 그래프** | 앱의 스파크라인 또는 직접 그림 | 숫자를 말할 때 |
| **정지 이미지** | 무료 소스 (Unsplash 등) | 배경 서술 |
| **손글씨/메모** | 종이에 적고 촬영 | 감정이 실리는 대목 |

**얼굴 대신 손을 쓰십시오.** 종이에 숫자를 적는 손, 폰을 조작하는 손. 사람이 있다는 신호가 되면서 신원은 안 드러납니다.

**같은 화면이 15초를 넘기지 않게** 하십시오. 스토리 이탈의 가장 큰 원인입니다.

# 2부 · 만들기

## 7. 촬영

### 순서를 지키십시오

```
1) 화면만 녹화 — 소리 없이, 조작에만 집중
2) 녹화본을 보며 목소리만 따로 녹음
3) 편집에서 합치기
```

조작하면서 말하면 말이 굳습니다. 따로 녹음하면 **다시 할 수 있다는 것만으로** 톤이 달라집니다.

### 화면 녹화

| | 설정 |
|---|---|
| 아이폰 | 설정 → 제어 센터 → 화면 기록 추가 · 마이크 **끄기** |
| 안드로이드 | 빠른 설정 → 화면 녹화 · 소리 **없음** |
| 해상도 | 폰 기본 그대로 (1080p 이상) |
| 방해 요소 | 알림 끄기 · 방해금지 · 배터리 80% 이상 |

**녹화 전에 조작을 두 번 연습하십시오.** 실제 녹화에서 헤매면 그 구간을 통째로 다시 찍어야 합니다.

### 음성 녹음

| | |
|---|---|
| 마이크 | 유선 이어폰 마이크로 시작. 입에서 **20cm** |
| 앱 | 폰 기본 음성 메모로 충분 |
| 시간대 | 밤. 에어컨·냉장고·환풍기 끄기 |
| ★ 주의 | **아파트 안내방송** — 단지명이 나옵니다 |

**한 번에 다 녹음하지 마십시오.** 구간별로 나눠 녹음하면 한 군데 틀렸을 때 그 구간만 다시 하면 됩니다.

### 재녹음 기준

이 중 하나면 다시 하십시오. 편집으로 살리려 하지 마십시오.

```
□ 말하다 막혔다
□ 톤이 갑자기 높아졌다 (긴장)
□ "어..." "음..." 이 세 번 이상
□ 대본을 읽는 티가 난다
```

**대본을 읽지 마십시오.** 요점만 보고 말하십시오. 예외는 후킹 20초 — 그건 외우십시오.

## 8. 편집

### 도구

| 용도 | 무료 |
|---|---|
| 컷 편집·자막 | **CapCut** (폰·PC) — 자동 자막이 한국어를 잘 잡습니다 |
| 정밀 편집 | DaVinci Resolve (PC) |
| 자막 텍스트 | 클로바노트로 받아쓰기 후 수정 |

**CapCut으로 시작하십시오.** 3편까지는 이걸로 충분하고, 부족함을 느낀 뒤에 옮기면 됩니다.

### 순서

```
1) 화면 녹화본을 타임라인에
2) 음성 얹고 싱크 맞추기
3) 침묵 0.5초 이상 컷           ← 체감 속도가 확 달라집니다
4) 자동 자막 → 오타 수정
5) ★ 버튼 이름 자막 별도 추가
6) 마스킹 확인
7) 고지 문구 (마지막 5초)
```

### 자막 규칙

- **자동 자막은 반드시 수정**하십시오. "한곳지기"를 "한 곳 지기"로 씁니다
- **버튼 이름은 자동 자막과 별개로** 큰 글씨로 넣으십시오 — `＋ 버튼` `홈 화면에 추가`
- 한 줄 **20자 이내**, 두 줄까지
- 화면 아래 1/5 지점. 유튜브 UI에 가리지 않게

### 마스킹

```
□ 자산 금액        → 모자이크 또는 블러
□ 종목명           → 시연 계정이면 가상 종목으로
□ 단지명           → 반드시 가릴 것
□ 카카오 로그인 화면 → 전체 블러
```

**한 프레임씩 확인하십시오.** 스크럽하며 빠르게 넘기지 말고, 마스킹 구간은 0.5배속으로 보십시오.

### BGM

**없어도 됩니다.** 넣는다면 **-30dB 이하**로. 목소리가 유일한 인격인데 음악이 이기면 안 됩니다. 유튜브 오디오 보관함의 저작권 프리 곡만 쓰십시오.

- 도구: Canva 무료 · 미리캔버스

## 10. 업로드

```
□ 제목       3안 중 하나 (☞ 8절 아래 선택 기준)
□ 설명란     후킹 2~3줄 → 링크 → 챕터 → 고지 문구 → 태그
□ ★ 링크     one-hub.kr/estimate?from=youtube&v=<영상id>
□ 재생목록   서현동 이야기 / 혼자 만드는 자산 앱 / ONE·HUB 사용법
□ 시청자층   아동용 아님        ← 아동용이면 댓글이 막힙니다
□ 챕터       설명란에 0:00 부터 시작해야 인식됩니다
□ 종료화면   다음 영상 + 구독
□ 고정 댓글  "막히신 부분 있으면 댓글 주세요. 다음 편 소재가 됩니다."
□ lib/videos.js 에 유튜브 ID 한 줄 추가 → 배포   ← S34
□ 이야기 탭 회차에 한 줄
```

**`v=<영상id>`를 빠뜨리지 마십시오.** 이게 없으면 어느 영상이 사람을 데려왔는지 영영 모릅니다.

### 제목 3안 중 고르는 법

세 안은 **서로 다른 각도**여야 합니다 — 감정 / 숫자 / 질문.

고를 때 기준은 하나입니다. **검색창에 누가 칠 법한 말인가.**

```
✘  "혼자 만드는 자산 앱 12주차"          ← 아무도 이렇게 검색 안 합니다
✔  "손절 규칙이 세 번 틀렸습니다"         ← "손절"을 검색합니다
```

# 3부 · 한 주의 리듬

## 11. 주 1편을 굴리는 방법

```
토  아침 10분   /pwa/weekly-report 열기 · 블록③ 후보에서 하나 고르기
    낮 40분     촬영 (화면 → 음성)
    저녁 60분   편집
일  30분        썸네일 · 업로드 · 링크 반영
```

**대본을 새로 쓰는 시간이 없습니다.** 그게 정상입니다 — 스토리·사용법 대본은 이미 11편이 있고, 주간 리포트는 앱이 초안을 만듭니다. **쓰는 일이 아니라 고르는 일**이 되어야 주 1편이 굴러갑니다.

## 12. 대본을 새로 쓸 때 (2~3주에 한 번)

```
□ 어느 시리즈인지 정한다 → 해당 템플릿을 연다
□ 후킹 20초를 먼저 쓴다              ← 여기가 안 되면 소재가 약한 것
□ 결론을 후킹에 넣는다
□ 구간마다 [화면]을 채운다
□ 글자수를 센다 (목표 길이 × 275자)
□ 소리 내어 읽는다 — 숨이 차는 문장을 자른다
□ 고지 문구를 넣는다
□ 제목 3안 · 썸네일 문구 · 태그
```

**후킹이 안 써지면 그 소재는 버리십시오.** 20초를 못 만드는 소재로 7분을 만들 수 없습니다.

## 13. 자가 점검 — 발행 전 마지막

```
[안전]
□ 시연 계정으로 찍었는가
□ 금액·종목명·단지명이 한 프레임도 안 나오는가
□ 실명·회사명·부서·직급을 말하지 않았는가
□ 나이·직장을 흐린 표현으로 말했는가

[규제]
□ "지금 사세요/파세요"로 읽힐 문장이 없는가
□ "적정가"라는 말을 쓰지 않았는가
□ 고지 문구가 마지막 자막과 설명란에 둘 다 있는가
□ (스토리) 각색 고지가 설명란에 있는가

[품질]
□ 후킹 20초에 결론이 있는가
□ 인사로 시작하지 않았는가
□ 같은 화면이 15초를 넘기지 않는가
□ 버튼 이름이 자막으로도 나오는가
□ 길이가 목표 ±1분 안인가

[연결]
□ 설명란 링크에 ?from=youtube&v=<id> 가 붙었는가
□ lib/videos.js 에 ID를 넣고 배포했는가
□ 재생목록에 넣었는가
```

## 0. 오늘 무슨 일이 있었나 (사실관계 — 추측 아님)

**측정값**

| 시각(KST) | 밖에서 본 상태 (`/api/health`) | 텔레그램 알림 |
|---|---|---|
| 08:00 | — | 🟢 정상 (전날 09-08 기준) |
| 17:55 | — | 🔴 realestate(:5002), news(:5004) — **같은 알림 2번** |
| **20:04** | **engine·realestate·etf 셋 다 TimeoutError 6001ms** | **없음** |
| 21:00 | — | 🔴 news(:5004) |
| 21:14 | 셋 다 up, 22~29ms | — |

**여기서 나온 문제 5가지**

1. **20:04에 세 축이 전부 밖에서 안 닿았는데 알림이 없었다.** engine(:5001) 사망 알림은 오늘 한 번도 오지 않았다.
2. **알림 본문 시각이 UTC다.** 수신 17:55 KST ↔ 본문 "08:55", 수신 21:00 ↔ 본문 "12:00". 정확히 9시간 차이.
3. **자동 복구가 없다.** news는 17:55에 죽어 21:00에도 죽어 있었다 — 3시간 이상 방치.
4. **복구 알림이 없다.** realestate는 그사이 살아났는데 아무 말이 없었다.
5. **중복 발송.** 17:55에 같은 메시지 2번.

**1번의 원인은 코드에 있다.** `scripts/health.sh`:

```bash
curl -s -o /dev/null -w "%{http_code}" "localhost:$p/health"
systemctl is-active onehub onehub-b onehub-api onehub-realestate
```

**점검이 서버 안에서 자기 자신을 본다.** 텔레그램 메시지 형식("서비스: onehub=active…", "포트: 5001/5002/5003/5004 정상")이 이 스크립트와 일치하므로 감시 봇도 같은 방식이다.
서비스는 살아 있는데 **밖에서 못 닿는 상태**는 구조적으로 감지할 수 없다. 그런데 오늘 사용자가 겪은 것이 정확히 그 상태였다.

**그리고 앱이 빈 화면이 된 원인도 코드에 있다.** `pages/pwa/today.js`의 거의 모든 fetch:

```js
.catch(() => {});          // 침묵
.catch(() => setNews([])); // 빈 배열로 위장
```

장애를 삼켜서 카드가 그냥 안 그려진다. 사용자에게는 "앱이 고장났다"로 보인다.
같은 저장소 안에 **올바른 예시가 이미 있다** — `pages/pwa/assets.js:360`:

> `⚠ 증권사 연동 자산을 불러오지 못했습니다 — 이 총자산은 실제보다 적습니다.`

이 태도를 `today.js`에도 적용한다.

### S33-9 · `scripts/s33_server_hardening.sh` ★이 배치의 핵심 산출물

사용자가 Lightsail 브라우저 터미널에 붙여넣어 실행할 스크립트 하나를 만든다.

**요구사항 — 하나도 빠뜨리지 말 것**

1. **기본이 조사 모드다.** 인자 없이 실행하면 **아무것도 바꾸지 않고**, 각 서비스의 현재 메모리 사용량과 "이렇게 바꾸겠다"만 출력한다. `--apply` 를 줘야 실제로 적용한다.

2. **대상**: `onehub-realestate` `onehub-api` `onehub-etf` `onehub-news`
   **★ `onehub`, `onehub-b`(매매봇)는 절대 포함하지 않는다.** 제외 목록을 스크립트에 하드코딩하고, 왜 제외인지 주석으로 남긴다 — *주문 처리 중 강제 종료·자동 재기동은 주문 중복 위험이 있고, 이는 별도 판단이 필요한 영역이다.*

3. **실측**: 서비스별 `systemctl show <svc> -p MemoryCurrent --value` (바이트).

4. **상한 계산**: `MemoryMax = clamp(측정값 × 2.5, 400M, 700M)`, `MemoryHigh = MemoryMax × 0.85`.
   측정값이 0이거나 비어 있으면 **그 서비스는 건너뛰고 경고를 출력한다. 추측값을 넣지 말 것.**
   *상한을 평상시 사용량에 너무 가깝게 잡으면 정상 요청에도 죽고, 재시작을 반복하다 systemd가 포기해 서비스가 아예 내려간다. 실측이 이 항목의 전부다.*

5. **적용은 drop-in 방식만.**
   ```
   /etc/systemd/system/<svc>.service.d/limits.conf
   ```
   **원본 유닛 파일을 절대 수정하지 않는다.** 되돌리기는 이 파일 삭제 한 번이면 끝나야 한다.

   ```ini
   [Service]
   MemoryMax=<계산값>
   MemoryHigh=<계산값>
   Restart=always
   RestartSec=5
   ```

6. `systemctl daemon-reload` → 서비스별 `restart` → `systemctl show -p MemoryMax -p Restart` 로 **적용 확인을 출력**한다.

7. **멱등**: 두 번 실행해도 안전할 것. 기존 `limits.conf`가 있으면 **이전 값을 출력한 뒤** 덮어쓴다.

8. 마지막에 요약표를 출력한다.

   ```
   서비스                 측정      새 상한   Restart   결과
   onehub-realestate     312MB     780MB     always    적용
   onehub-api            118MB     400MB     always    적용
   onehub-etf             96MB     400MB     always    적용
   onehub-news             –          –         –      건너뜀(측정 실패)
   ```

**효과**: 부동산 서비스가 또 부풀어도 그것만 죽고 5초 뒤 되살아난다. 서버는 멀쩡하다. **오늘 같은 3시간 전면 정지가 5초짜리 딸꾹질이 된다.**

|---|---|---|
| 계단식으로 계속 오름 | 누수 | 안 놓아주는 객체를 코드에서 찾는다 |

### S33-8 · 감시 봇 수정 (SSH 복구 후)

> SSH가 막혀 있어 이 항목은 **마지막으로 미룬다.** 봇 파일이 서버에 있어 원격 편집이 필요하다.
> 스크립트로 대체하지 말 것 — 봇의 실체를 먼저 확인해야 한다(`crontab -l`, `systemctl list-units | grep -i "monitor\|alert\|ca-bot"`).

원본을 `.bak`으로 남긴 뒤 네 가지를 고친다.

| # | 고칠 것 | 근거 |
|---|---|---|
| 1 | **시각을 KST로** | 서버 시계가 UTC. 수신 17:55 ↔ 본문 "08:55" — 9시간 어긋남 |
| 2 | **복구 알림 추가** | realestate가 살아난 걸 아무도 알려주지 않았다 |
| 3 | **상태 전이일 때만 발송** | 09-09 17:55 같은 메시지 2번. 알림이 늘면 사람은 무시한다 |
| 4 | **로그 3줄 첨부** | `journalctl -u <svc> -n 3` — 폰에서 원인 판단이 된다 |

목표 형태:

```
🔴 ONE-HUB · 09-09 17:55 KST
죽은 축: realestate(:5002)
자동 재기동 시도 → 성공 (3초)
최근 로그:
  oom-kill: uvicorn
→ 메모리 상한 확인 필요
```

**3번을 반드시 넣을 것.** 이게 없으면 나머지가 소용없다.

## 배치 HD — 검증

**전부 통과해야 완료다.**

```
[프론트]
□ npm run build (= next build --webpack) 성공
□ /api/health 응답에 services 4개 (engine·realestate·etf·news)
□ /status 가 로그인 없이 열리고, 내부 IP·포트가 노출되지 않음

    → 빈 화면이 아니고, 배너 한 줄 + 마지막 값 또는 자리표시자가 보임   ← 이번 스프린트의 핵심
□ 도달 실패 시 "엔진 버전" 이라는 표현이 화면 어디에도 없음
□ 전역 배너와 EngineVersionBanner 가 동시에 뜨지 않음
□ git diff 에 CRLF 유령 변경 없음

[서버 스크립트 — 실행이 아니라 스크립트 자체를 검토한다]
□ 인자 없이 실행하면 아무것도 바꾸지 않는다 (조사 모드가 기본)
□ 대상 목록에 onehub / onehub-b 가 없다              ← 반드시 눈으로 확인
□ 원본 유닛 파일을 수정하는 코드가 없다 (drop-in 전용)
□ 측정 실패 시 추측값 대신 건너뛴다
□ 두 번 실행해도 안전하다 (멱등)
□ crontab 을 중복 등록하지 않는다
□ shellcheck 통과 (없으면 bash -n 문법 검사)

[문서]
□ docs/운영_감시.md 에 사람이 할 일 3가지가 체크리스트로 있다
□ docs/S33_결과.md 에 미해결 1건(11:04 UTC 전면 불통)이 명시되어 있다
```

**"빈 화면이 아니어야 한다"를 눈으로 확인하지 않고 넘어가지 말 것.** 이 스프린트를 하는 이유가 그것 하나다.

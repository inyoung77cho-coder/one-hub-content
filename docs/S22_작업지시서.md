## 0. 이 스프린트가 바꾸려는 것

지금 ONE·HUB는 **"얼마인가"를 잘 보여주는 앱**입니다. 오래 쓰게 하려면 **"그래서 무엇을 바꿀 것인가"를 묻는 앱**이 되어야 합니다.

전략의 축은 **주기**입니다. 주식은 일간, ETF는 월간·분기, 부동산은 분기·연간으로 움직입니다. 지금 앱에는 **매일 훅만 있고 주간·월간·분기 훅이 없습니다.** 하루 안 들어오면 그대로 이탈합니다. 이 스프린트는 그 안전망을 만듭니다.

### 페이지별 목적 — 앞으로 모든 판단의 기준

| 페이지 | 목적 (한 문장) | 주기 |
|---|---|---|
| 주식 | 돈을 벌어주는 곳이 아니라, **내 판단이 AI보다 나은지를 데이터로 알려주는 곳** | 일간 |
| ETF | 무엇을 살지 고르는 곳이 아니라, **배분 이탈과 절세 가능액을 알려주는 곳** | 월간·분기 |
| 부동산 | 시세 조회가 아니라, **상급지로 가는 문이 열리는지 닫히는지 알려주는 곳** | 분기·연간 |
| 종합자산 | 잔액 합계가 아니라, **지금 무엇이 가장 목표에서 멀고 다음 한 수는 무엇인지** 판정하는 곳 |  |

기능을 추가할지 말지 애매하면 **이 표로 판단하십시오.** 목적에 안 맞으면 안 넣습니다.

# 단계 1 — 신뢰의 바닥

## S22-1 · ETF 시세·평단 정합성

### 증거 (2026-09-01 실측, trader A)

```
A133690 (TIGER 미국나스닥100) · 퇴직연금
  저장값        222주 × 평단 204,918원 = 매수 4,549만원
  화면 평가      522만원  →  -88.5%  ·  손익 -4,027만원
  화면이 쓴 시세  약 23,500원/주
  단건 API 응답   /api/etf/quote?ticker=133690&market=kr → 178,785원

A448300 · 개인연금
  11,190,630주 × 1.5085원      ← 수량·단가 자릿수가 의심스러움
```

### 무엇이 문제인가 — 단정하지 말고 먼저 판정할 것

**두 가지가 겹쳐 있습니다. 순서대로 확인하십시오.**

1. **평단이 오염됐을 가능성** — TIGER 미국나스닥100의 실제 주가는 2만원대입니다. 평단 204,918원은 액면분할 전 가격이거나 총매수금액을 평단 칸에 넣은 값일 수 있습니다. 222주 × 2.4만원 ≈ 533만원인데 저장된 매수액은 4,549만원입니다.
2. **시세 소스 둘이 다른 값을 줍니다** — 화면(약 23,500원)과 단건 API(178,785원)가 8배 차이납니다. `resolveOne` 이 `133690.KS` / `133690.KQ` 중 다른 종목을 잡았을 수 있습니다. **어느 쪽이 맞는지 먼저 확정**하고, 틀린 쪽을 고치십시오.

> ⚠ **어느 값이 맞는지 확정하기 전에 숫자를 고치지 마십시오.** 사용자 입력 데이터를 앱이 임의로 바꾸면 안 됩니다(`lib/ledger.js` 의 기존 원칙 — "앱은 값을 고치지 않는다. 원본이 평단인지 총매입액인지는 입력한 사람만 안다").

### 작업

1. **판정 먼저.** `133690`, `448300`, `360750`, `381170`, `449190`, `472160` 각각에 대해 배치·단건 API 응답과 실제 시세를 대조해 표로 남기십시오(`docs/S22-1_결과.md`). 시세 소스가 틀렸다면 `pages/api/etf/quote.js` 의 `resolveOne` 후보 심볼 순서(`.KS`/`.KQ`)를 고칩니다.
2. **ETF에도 평단 온전성 검사를 넣습니다.** 주식(`lib/stockHoldings.js`)에는 이미 `saneAvg`(0 초과·정수·300만원 이하, `verified` 플래그로 사람이 확인하면 통과)가 있는데 **ETF에는 없습니다.** 같은 규칙을 `lib/etfHoldings.js` 에 옮겨 심고, 위반 시 `lib/ledger.js` 가 `AVG_PRICE_OUT_OF_RANGE` 경고를 내도록 합니다.
3. **판정 기준은 시세 대비 배수로.** 고정 상한(300만원)은 ETF에 안 맞습니다. **현재가 대비 10배 초과 또는 1/10 미만**이면 이상치로 봅니다(이미 `ManualHoldingsCard` 가 쓰는 규칙과 동일).
4. **화면은 묻습니다, 고치지 않습니다.** 이상치 종목은 ETF 페이지에서 "확인이 필요합니다 — 평단 수정 / 이 값이 맞습니다" 두 버튼으로. 주식의 `AVG_PRICE_OUT_OF_RANGE` 카드(`pages/pwa/assets.js`)와 **같은 UI를 재사용**하십시오(복제 금지).
5. **이상치는 파생 계산에서 뺍니다.** 확인 전까지 Portfolio Score·예상 양도세·손익통산 대상·총자산에서 제외하고, 제외했다는 사실을 그 숫자 옆에 표기합니다.

### 합격선

- `docs/S22-1_결과.md` 에 6종목 시세 대조표
- 이상치 종목이 "확인 필요"로 표시되고, 확인 전에는 양도세·Score에서 제외됨
- 확인(`verified`) 후에는 정상 합산
- `bash scripts/verify_s19.sh` FAIL=0 · `npm run build` 통과

## S22-2 · 판단 원장 통합

### 증거

```
/api/pwa/game-state?trader=A   ledger 120건 (take 2 / pass 118)
AI 탭 "판단 기록 보기"          16건 (전부 매수/매도 거부)
```

같은 "내 판단"을 두 곳이 다른 숫자로 말합니다. 이 상태로는 성적표를 팔 수 없습니다.

### 원인

- `lib/verdictLedger.js`(`onehub_ai_vs_me`) — 추천 카드의 샀어요/관망
- `lib/portfolioDuel.js`(`onehub_duel_decisions`) — 대결 카드의 수용/거부

두 원장이 **다른 사건**을 기록합니다. 통합의 의미는 "하나로 합치기"가 아니라 **하나의 화면에서 일관되게 세는 것**입니다.

### 작업

1. **개념을 먼저 정의하십시오.** 두 원장이 무엇을 기록하는지 `docs/S22-2_결과.md` 에 적고, **성적표가 세는 단위**를 하나로 정합니다. 권장: "AI 제안에 대한 내 응답" 하나로 보고, 출처(`source: 'recommend' | 'duel'`)만 구분해 남깁니다.
2. **집계 함수를 한 곳에.** `lib/verdictStats.js`(신규)에 `getVerdictStats(trader)` 를 만들어 두 원장을 읽어 **하나의 통계**를 냅니다. 화면은 이 함수만 씁니다.
3. **화면의 건수 표기를 통일.** "판단 기록 보기 (N건)" 의 N과 성적표의 모수가 같아야 합니다.
4. 원장 자체는 **합치지 마십시오.** 마이그레이션은 위험 대비 이득이 없습니다. 읽는 쪽만 통일합니다.

### 합격선

화면에 나오는 판단 건수가 어디서나 동일. `getVerdictStats` 외의 곳에서 판단을 세는 코드 0건.

# 단계 2 — 해자 만들기

## S22-3 · 총자산 곡선 적립

### 왜

자산관리 앱의 진짜 자산은 **누적된 시계열**입니다. 1년치 곡선이 있는 앱은 갈아타기 어렵고, 없는 앱은 언제든 지워집니다. 지금은 `lib/assetHistory.js` 로 스냅샷을 쌓기 시작한 단계입니다.

### 작업

1. **적립 지점을 늘립니다.** 지금은 자산 탭·오늘 탭 진입 시에만 쌓입니다. **하루 1건이 보장**되도록, 어느 화면으로 들어와도(오늘·자산·ETF·부동산·AI) 총자산이 유효하면 적립합니다. 같은 날은 1건으로 병합(기존 동작 유지).
2. **서버로 올립니다.** `SYNC_KEYS` 에 `onehub_asset_history` 를 추가해 `/api/user/state` 로 동기화합니다. 브라우저 저장소만으로는 기기 변경·캐시 삭제에 곡선이 통째로 날아갑니다. **이게 이 항목의 핵심입니다.**
3. **자산군별로 쌓습니다.** 총액만이 아니라 `{ total, stock, etf, realestate, cash }` 를 함께. 나중에 "무엇이 총자산을 움직였나"를 말하려면 필요합니다.
4. **화면은 최소로.** 종합자산에 스파크라인 하나면 충분합니다. 데이터가 쌓이기 전에 화면을 크게 만들 필요 없습니다.

### 합격선

- 어느 탭으로 들어와도 그날 스냅샷이 1건 적립됨
- 다른 기기에서 로그인해도 곡선이 따라옴
- 자산군별 값이 함께 저장됨

### 주의

`lib/ledger.js` 가 진실이고 히스토리는 그 사본입니다. 히스토리에서 총자산을 **재계산하지 마십시오**(N1 원칙).

## S22-4 · 목표 배분 온보딩

### 왜

지금 종합자산은 주식 20% · ETF 80%를 보여주지만 **"얼마여야 하는가"가 없습니다.** 목표가 없으니 이탈이 없고, 이탈이 없으니 조치가 없습니다. 도넛은 정보이지 판단이 아닙니다.

### 작업

1. **ETF 페이지에 이미 있는 프리셋을 전면으로.** 안정형·중립형·공격형이 `onehub_target_alloc` 으로 존재합니다. 이걸 **ETF 안쪽이 아니라 온보딩과 종합자산에서** 고르게 합니다.
2. **자산군 단위 목표를 추가합니다.** 지금 목표 배분은 ETF 내부(국내/해외)용입니다. **주식·ETF·부동산·현금 사이의 목표**가 따로 필요합니다. 새 키 `onehub_target_class`(`{stock, etf, realestate, cash}`, 합 100) — `SYNC_KEYS` 에 추가.
3. **실거주는 분모에서 뺍니다.** 목표 배분은 **운용자산 기준**입니다(실거주 부동산 제외 — 기존 설계 전제 유지).
4. **미설정 상태를 정직하게.** 목표를 안 정했으면 "목표 배분을 정하면 이탈을 알려드립니다" 한 줄과 설정 버튼. 임의의 기본값을 넣지 마십시오.
5. **온보딩에 1스텝 추가.** `pages/pwa/onboarding.js` 에 프리셋 3개 중 택1(건너뛰기 허용).

### 합격선

- 목표를 정하면 종합자산에 "ETF가 목표보다 +15%p 많습니다" 형태의 **차이**가 표시됨
- 안 정했으면 그 사실이 표시되고, 추측한 기본값이 없음

# 단계 3 — 주간 훅

## S22-5 · 내 판단 성적표

### 왜

증권사가 절대 안 만들어 주는 화면입니다(거래를 안 하게 만드는 정보라서). **"지난 3개월간 118번 관망하고 2번 샀으며, 관망한 종목의 평균은 +2.1%였습니다"** — 이건 ONE·HUB만 할 수 있습니다.

### 작업

1. **독립 화면으로.** 지금은 대결 카드 안에 접혀 있어 발견되지 않습니다. `pages/pwa/record.js`(신규) 또는 AI 탭의 4번째 섹션으로 승격.
2. **표시 항목** — 전부 `getVerdictStats`(S22-2)에서:
   - 승률 · 누적 수익 · AI 대비 성적
   - 관망 비율과 그 해석 (예: "10번 중 9번 관망하셨습니다")
   - **놓친 수익** — 관망했는데 오른 종목의 평균
   - 판단 성향 한 줄 (신중형 / 적극형 …)
3. **표본이 적으면 그렇게 말합니다.** `lib/sampleSize.js` 가 이미 있습니다. 30건 미만이면 "아직 판단하기 이릅니다"로.
4. **비교는 나 자신과.** 다른 사용자와 비교하지 마십시오(모수도 없고, 위화감만 생깁니다).

### 합격선

승률·누적수익·관망비율·놓친수익이 한 화면에. 건수가 S22-2 통계와 일치.

## S22-6 · 주간 리포트

### 왜

**주간 훅이 안전망입니다.** 매일 훅만 있는 앱은 하루 안 들어오면 이탈합니다. 그리고 알림이 8월 3일 이후 0건이라, 지금은 사용자를 다시 부르는 수단이 아예 없습니다.

### 작업

1. **월요일 아침 한 장.** 지난주 내 판단 N건, 채점된 결과, AI 대비, 총자산 주간 변화, 이번 주 볼 것 하나.
2. **웹푸시로 부릅니다.** `push_subscriptions`(trading.db)와 `/api/push-subscribe` 가 이미 있습니다. **새로 만들지 말고 재사용**하십시오.
3. **알림 채널을 분리합니다.** 현재 알림함에 운영자용 `job_monitor` 경보가 섞여 있습니다. 사용자용/운영자용을 나누고, 사용자에게는 사용자 것만 보냅니다.
4. **보낼 게 없으면 안 보냅니다.** 판단이 0건인 주에는 "지난주는 조용했습니다" 대신 **발송 안 함**. 빈 알림이 구독 해지를 부릅니다.

### 합격선

월요일 09:00 KST 발송. 알림함에 운영자 경보 미노출. 판단 0건 주에는 미발송.

## S22-7 · 종합자산 위계 전환

### 증거

```
  운용    10.67억  ← 실제 판단 대상인데 두 번째 줄
```

**가장 큰 숫자가 손댈 수 없는 숫자**입니다. 화면 위계가 사용자의 행동과 반대입니다.

### 작업 — 순서를 이렇게

1. **운용자산을 헤드라인으로.** 10.67억을 크게, 총자산 57.87억은 그 아래 한 줄. 실거주는 "못 파는 자산"으로 별도.
2. **목표 대비 이탈 한 줄.** 비중이 아니라 **차이**를 말합니다 (S22-4 필요).
3. **오늘의 한 수.** 세 자산군 신호 중 **가장 급한 것 하나만**. 주식 손절 근접 → 없으면 ETF 리밸런싱 → 없으면 부동산 분기 변화.
4. **총자산 곡선**(S22-3). 데이터가 쌓이면 이 화면의 주인공이 됩니다.
5. **"읽기 전용 지도예요" 문구 삭제.** 매일 열 이유를 스스로 부정하는 문장입니다.

### 주의

`pages/pwa/assets.js` 는 종합자산·주식이 한 파일입니다. **자산 지도 카드의 순서만 바꾸고** 보유/추천 탭 구조는 건드리지 마십시오.

## S22-8 · ETF 세금 달력 — **시기 민감**

### 왜

양도세·손익통산·연금 한도는 **연말에 값이 폭발**합니다. 상시 표시는 소음이고, **시점 알림은 상품**입니다. 11월 전에 붙어야 올해 절세 시즌을 잡습니다.

### 작업

1. **달력을 만듭니다.** `lib/taxCalendar.js`(신규) — 월별로 무엇이 중요한지: 6월 보유세 기준일, 11월 손익통산·연금 납입 마감 점검, 12월 확정, 1월 신고 준비.
2. **때가 되면 부릅니다.** 11월 1일에 웹푸시(S22-6 채널 재사용): "올해 250만원 공제 중 0원 사용 · 손실 4종목으로 절세 가능액 X원".
3. **평시에는 접어 둡니다.** ETF 페이지 5.9화면 중 세금 영역은 **접힌 상태가 기본**, 해당 달에만 펼침.
4. **계산은 이미 있습니다.** 예상 양도세·손익통산 대상·연금 세액공제 진행률이 전부 구현돼 있습니다. **새로 만들지 말고 시점에 맞춰 노출**하는 일입니다.

### 합격선

11월 진입 시 절세 알림 1건 발송. 평시 ETF 페이지에서 세금 영역이 접혀 있음.

## S22-9 · 부동산 내 집 중심 재구성

### 증거

사용자는 시범삼성을 **47.2억**으로 등록했는데, 화면은 **84㎡ 기준 대장 23억**으로 동네를 비교합니다. 내 평형(192㎡)은 "평형별 적정가"에 −1.6억으로 한 번 스칠 뿐입니다. "내 단지 포지션"이라는 제목인데 내용은 **동네 이야기**입니다.

### 작업

1. **첫 화면을 내 집으로.** 등록 평형 기준 현재가 · 매수가 대비 손익 · 대장 대비 위치 · 분기 변화.
2. **갈아타기 시뮬레이터.** "지금 팔고 대치동 84㎡로 가면 추가로 얼마가 필요한가" — **취득세·양도세·중개비까지 포함**해 한 줄. 이게 부동산의 유료 후보입니다.
3. **분기 리듬을 명시.** "다음 갱신 10월 1일"을 적어 두십시오. 매일 볼 화면이 아닙니다. 정직한 주기 표시가 신뢰를 만듭니다.
4. **커버리지를 넓히지 마십시오.** 분당·수지·광교·강남4구에서 **가장 깊은 도구**가 되는 편이 낫습니다. 전국으로 넓히면 데이터 품질이 무너집니다.
5. R² 낮은 곳을 정직하게 표시하는 현재 태도는 **유지**하십시오.

## S22-10 · 교차 인사이트

### 왜

### 작업

1. `lib/crossInsight.js` 가 이미 있습니다. **먼저 읽고**, 무엇이 구현돼 있고 어디서 쓰이는지 확인하십시오.
2. **규칙 기반 3~5개로 시작.** 자산군 집중, 섹터 중복(주식·ETF가 같은 섹터), 환노출 중복, 유동성(운용자산 대비 실거주 비중).
3. **하나만 보여줍니다.** 가장 강한 것 하나. 여러 개를 나열하면 아무것도 안 읽힙니다.
4. **근거를 함께.** "반도체 25%"처럼 숫자를 대고, 그 숫자를 클릭하면 해당 페이지로.

# 공통 규칙 · 함정

1. **줄바꿈** — 저장소 전체가 CRLF. `.gitattributes` 에는 `*.sh text eol=lf` 만 있습니다. `.js` 편집 시 줄바꿈을 바꾸지 마십시오(바꾸면 236개 파일이 통째로 변경된 것처럼 잡힙니다).
2. **빌드는 반드시 webpack** — `"build": "next build --webpack"` 유지.
3. **총자산 덧셈은 `lib/ledger.js` 안 한 곳뿐.** 새 저장 키는 꼭 필요할 때만, 만들면 `SYNC_KEYS` 에도 추가.
4. **UI 중복 정의 금지** — 같은 카드를 두 화면에 손으로 복제하지 말고 `components/shared/` 로 뽑아 import.
5. **동시 작업** — 다른 세션이 같은 저장소를 건드릴 수 있습니다. 시작 전 `git pull --rebase`.
6. **바꾸면 안 되는 설계 전제 2건**
   - AI 대결은 **실보유(KIS) 기준이 정상**. KIS 계좌가 없을 때만 1,000만원 가상 시드.
   - **실거주 부동산은 투자자산에서 제외가 정상.** 총자산에 별도 표기하고 운용자산 분모에서 뺍니다.
7. **앱이 사용자 값을 임의로 고치지 않습니다.** 이상하면 묻습니다(S22-1).

# S21-7 결과 — 배치 부분 실패 무시 해소

작업일 2026-09-01 · Claude Code

## 문제
`pages/api/etf/quote.js` 배치는 일부 티커를 못 가져와도 `ok:true` 로 응답하고 `s-maxage=300` 을 붙인다. 클라(`lib/stockLive.js`·`lib/etfLive.js`)는 `!d?.ok` 일 때만 개별 폴백하므로, **실패한 종목만 조용히 시세 없이** 넘어가고 5분간 그 상태로 캐시된다.

## 한 것
**서버 `pages/api/etf/quote.js`**
- 배치 응답에 `missing: [티커…]` 추가(못 가져온 입력 티커, 키 정규화는 `resolveOne` 과 동일).
- `missing.length > 0` 이면 `Cache-Control` 을 짧게(`s-maxage=30, stale-while-revalidate=60`) — 실패 상태를 5분간 굳히지 않음. 전건 성공이면 기존 `s-maxage=300`.

**클라 `lib/stockLive.js`·`lib/etfLive.js`**
- 배치 성공 시에도 결과에서 **빠진 종목만**(`quotes` 에 안 담긴 것) 개별 재조회. 서버 `missing` 유무와 무관하게 클라측 실측(누락)으로 판정 → 배치 엔드포인트 구버전에도 안전.
- 배치 자체 실패(`!d?.ok`)면 기존대로 전체 개별 폴백(회귀 방지).

## 검증
- `bash scripts/verify_s19.sh` → **FAIL=0**
- `npm run build`(webpack) → **Compiled successfully**
- 합격선(잘못된 티커 섞어도 나머지 정상 + 실패분 재조회로 채움/‘시세 없음’ 명시): 로그인 브라우저에서 확인(사용자). 개별 재조회도 실패하는 종목은 저장 평단 폴백(호출측 기존 로직) 유지.

### 끊긴 지점

정상 설계 흐름:
```
08:50 morning_analysis → 신호 생성
      ↓ (장 시작 전이라 is_trading_time()=False → 자동매수 분기 못 탐)
      pending → 사용자 예약 → status='queued', scheduled_at=09:00
09:00 queue_release.py (cron) → status='approve_requested'   ← ✅ 여기까지 정상
      ↓
      main.py _sync_pwa_approvals (30초 루프)
        if code in pending: → approved → _auto_execute_approved_pending() → 체결
        else:              → expired (★ 로그 출력 없음)
```

**7/15 실측:**
- `queue_release.log.1`: `예약 주문 릴리스 (2026-07-15 09:00 KST) / 1건 / - HMM(011200) BUY 79주` → **릴리스 성공**
- 그 후 7/15 09:00 ~ 7/16 08:30 **약 14.5시간 동안 아무 일도 일어나지 않음**
- 7/16 08:30:04 `expire_all_pending`(reset_daily_state, UTC 23:30)이 `approve_requested`를 **만료 처리**
  (스윕 제외 목록 `('done','rejected','expired','queued')`에 **`approve_requested`가 없음**)
- 같은 시간대 봇 로그: `[CACHE HIT] balance_A`(동일 1분 주기 잡)는 매분 기록 / **`[v8.3] PWA 승인 반영` 없음**

**주변 사실:**
- `_sync_pwa_approvals`는 살아 있음 — 7/9 10:33 `[v8.3] PWA 거절 반영: 000270` 외 4건 정상 처리
- 자율 모드 ON — 부팅 로그 `[v8.4] AI 자율 운영 모드 복원: ON` (7/7 13:55:33)
- 스케줄러 정상 — `while True: schedule.run_pending(); time.sleep(30)`, 등록은 전부 루프 앞
- 서비스 무재시작 — `NRestarts=0`, 7/7부터 9일 연속 가동
- DB 경로 일치 — `HOME=/home/ubuntu` → `DB_PATH=/home/ubuntu/trading.db` = queue_release의 `DB`

**즉 릴리스는 됐는데 소비가 안 됐습니다.** 정확한 결손 지점(폴러가 왜 그 행을 못 봤는지)은 Part 1의 심층 범위이며, 이번 Part 0에서는 **"엔진이 신호를 내고도 집행에 도달하지 못한다"**는 사실 확정까지 수행했습니다.

### 설계상 지적 1건

`_sync_pwa_approvals`의 `else` 분기(`code not in pending` → `expired`)에 **로그가 없습니다.** 승인이 조용히 폐기되므로 이런 사고가 **감지되지 않습니다.** Part 1에서 최소한 이 한 줄은 넣어야 합니다.

## Part 2에 대한 권고 — 실행 금지

지시서 0-2의 F1(v8.2)이 사실이 아니므로 S-2·S-4·H-B의 근거가 모두 사라집니다.
`.vscode-server/History`(20K·파일 2개)로 v9.x를 복원하려는 시도는:

1. **되찾을 것이 없고**(단서 자체가 20K),
2. **되찾을 필요도 없으며**(배포본이 이미 v10.0.0-ops로 더 앞섬),
3. 실행하면 **v10 → v9 롤백**이라는 실제 사고가 됩니다.

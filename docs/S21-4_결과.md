# S21-4 결과 — 종목 마스터 한글명 (백엔드)

작업일 2026-09-01 · Claude Code

## 원인
`/api/stocks-search` → 엔진 `:5001`(onehub-api = `auto_trade/engine_status_api.py`) `/api/stocks/search`. 이 핸들러가 `STOCK_POOL` 의 **영문 `name`** 을 반환. `STOCK_POOL` 에 `name_kr` 필드가 있으나 **182개 중 25개만** 채워져 있어(빈 157개) 그대로 쓸 수 없었음.

## 한 것 (서버 — one-hub-content 저장소 아님)
1. **한글명 오버레이 생성**: `FinanceDataReader.StockListing('KRX')`(KRX 상장종목 마스터)로 `STOCK_POOL` 182개 코드의 정식 한글명을 만들어 `auto_trade/stock_names_ko.json`(150개) 저장. 나머지 32개는 KRX 등록명이 영문(SK·LG·GS·HMM·S-Oil·SKC·HDC·HPSP 등 지주/브랜드)이거나 STOCK_POOL name 이 이미 한글(엔씨소프트·KODEX반도체)이라 폴백으로 충분.
2. **`engine_status_api.py` 수정**(백업 `engine_status_api.py.bak_s21_*`):
   - 모듈 로더 `_STOCK_KO` + `_ko_name(stock)` = **오버레이(KRX) → name_kr → 영문명 → 코드** 순.
   - `/api/stocks/search` 결과 `name` 을 `_ko_name(s)` 로. 검색 매칭은 영문명·한글명·코드 모두.
   - `/api/analyze/<code>` 의 종목명도 `_ko_name`.
3. `sudo systemctl restart onehub-api`. 엔진 `/api/version` 정상(트레이딩 무영향).

## 프론트
**추가 작업 없음** — S20-2 매핑이 `stocks-search` 의 한글 `name` 을 자동으로 집는다.

# S34 작업지시서 — 유튜브와 앱을 잇는 다섯 개의 선

> 작성 2026-09-12 · 근거: `docs/유튜브_기획서_두개의시리즈.md` · 로드맵 4절(PWA 연계 세 방향)
> 실행 시점: **첫 영상을 찍기 전.** 측정 장치가 없으면 첫 편이 일했는지 알 수 없다.
> 선행: S33 HC(서버 메모리 상한)를 먼저 닫을 것 — 사람이 들어오는 날 서버가 넘어가면 이 스프린트가 무의미하다.

---

## 0. 왜 지금인가

유튜브와 앱은 세 방향으로 이어져야 한다.

| 방향 | 상태 |
|---|---|
| ① 유튜브 → 앱 (유입) | **반쯤 됨** — 유튜브에서 온 건 알지만 **어느 영상인지 모른다** |
| ② 앱 → 유튜브 (소재 공급) | **완료** — S32가 자동화 |
| ③ 앱 안의 유튜브 (잔류) | **전혀 없음** — 막힌 사용자가 영상으로 갈 길이 하나도 없다 |

이 스프린트는 ①의 나머지 절반과 ③ 전체를 만든다.

**핵심은 ③이다.** 사용자가 앱에서 막히는 지점이 곧 영상이 필요한 지점이다. 지금은 영상을 만들어도 앱 안에서 아무도 못 본다.

## 1. 전제 조건

```
1) 빌드는 반드시  next build --webpack
   → package.json의 "build"를 절대 바꾸지 말 것.

2) 저장소 전체가 CRLF. 리눅스에서 줄바꿈을 LF로 바꾸지 말 것.

3) ★ 개인정보 원칙을 깨지 말 것.

     "개인정보 안 받음·IP 로그 안 남김"
   이 스프린트가 추가하는 것은 전부 **집계 카운터**다.
   개인을 따라다니는 식별자를 만들지 말 것. 쿠키 추적 금지.

4) 새 API를 만들면 middleware.js PROTECTED_API_PREFIXES를 확인할 것
   (fail-closed 화이트리스트 — 등록 안 하면 공개된다).

5) 배포는 git push origin main → Vercel.
```

## 배치 CA — 어느 영상이 일하는가

### S34-1 · `lib/videos.js` — 영상 등록부

**할 일**

영상 정보를 한 곳에서 관리한다. 유튜브 ID를 화면마다 하드코딩하면 편수가 늘 때 반드시 어긋난다.

```js
// lib/videos.js
export const VIDEOS = {
  u1: { yt: "", title: "3분 만에 시작하기",        series: "usage", published: null },
  u2: { yt: "", title: "증권 계좌 없이 쓰는 법",    series: "usage", published: null },
  // s5, s2, w01 ... 발행할 때마다 여기만 고친다
};
export function videoUrl(id, from = "app")   // → https://youtu.be/<yt>?... (yt 없으면 null)
export function isKnownVideo(id)             // 출처 파라미터 검증용 — 닫힌 집합
```

**규칙**

- `yt`가 비어 있으면(미발행) **링크를 그리지 않는다.** 빈 링크를 노출하지 말 것.
- `id`는 소문자+숫자 3자 이내(`u1`, `s5`, `w01`) — 출처 파라미터로 그대로 쓴다.
- 이 파일이 유일한 진실. 다른 파일에 유튜브 ID를 적지 말 것.

### S34-2 · 출처 파라미터 확장 — `?from=youtube&v=<id>`

**할 일**

`pages/estimate.js:25`가 이미 `from`을 정제한다(`[a-z0-9]` 16자). **같은 방식으로 `v`를 추가**한다.

```
one-hub.kr/estimate?from=youtube&v=u1
```

`pages/api/public/re/estimate.js:51` 부근이 지금 `tool_view`와 `tool_view_<src>` 둘을 올린다. 여기에 한 단계를 더한다.

```
tool_view                 전체
tool_view_youtube         유튜브 전체   (기존)
tool_view_youtube_u1      영상별        (신규)
```

**주의**

- `v`는 `isKnownVideo()`로 **검증**한다. 모르는 값이면 무시하고 `tool_view_youtube`만 올린다. 임의 문자열로 카운터가 무한히 늘어나면 안 된다.
- 카운터만 올린다. **누가 봤는지는 남기지 않는다.**

---

### S34-3 · 첫 접점 보존 — 방문에서 가입까지 출처를 잇는다

**할 일**

`/estimate`는 로그인 전이고, 가입은 그 뒤에 일어난다. 지금은 그 사이에서 출처가 끊긴다.

```
영상 → /estimate?from=youtube&v=u1 → (며칠 뒤) 가입
                                        ↑ 여기서 출처를 모른다
```

**방식**

1. `/estimate` 진입 시 출처를 `localStorage.onehub_first_src`에 저장
2. **이미 값이 있으면 덮어쓰지 않는다** — 첫 접점(first-touch)을 유지
3. 유효기간 **30일**. 지나면 버린다
4. `lib/funnel.js`의 `markFunnel("signup", ...)` 시점에 이 값을 함께 보낸다

**왜 first-touch인가**: 마지막 접점을 쓰면 "영상 보고 왔다가 며칠 뒤 직접 접속해 가입"한 사람이 유튜브 성과에서 사라진다. 영상은 **데려오는** 일을 하지 가입 버튼을 누르게 하는 일을 하지 않는다.

**주의**: 이 값은 **출처 문자열 하나**다(`youtube:u1`). 방문 이력이나 식별자를 쌓지 말 것.

### S34-4 · 정비소에 유튜브 줄 추가

**할 일**

AI 탭 → 정비소(`components/MaintenanceShop.js`)에 한 블록을 더한다. 가입 깔때기(S30-9) 바로 아래.

```
유튜브 경유
  도구 조회   128건        가입 14명    전환 10.9%
  ─────────────────────────────────────────────
  u1  3분 만에 시작하기      86건   →  11명   12.8%
  u2  증권 계좌 없이         42건   →   3명    7.1%
```

**읽는 법을 화면에 한 줄로 적을 것**: 전환율이 낮은 영상은 **영상이 나쁜 게 아니라 그 영상이 데려온 사람에게 앱이 안 맞는다는 뜻**일 수 있다. 두 해석을 구분하려면 다음 항목이 필요하다.

---

### S34-5 · 주차별 전환 기록

**할 일**

위 숫자를 **주차별로** 남긴다. 한 시점의 숫자만 보면 영상이 일하는지 알 수 없다 — 유튜브는 발행 후 몇 주에 걸쳐 유입이 쌓인다.

- 저장 위치: `:5002` (`user_state`와 같은 계열, 집계 테이블)
- 주차 경계는 **`lib/weeklyDigest.js`의 `weekBounds`를 재사용**한다. 새로 만들지 말 것 — 주간 리포트와 숫자가 어긋나면 안 된다
- 기록 항목: 주차 · 영상id · 조회 · 가입 · 첫판단

**첫 판단까지 기록하는 이유**: 가입은 껍데기다. 로드맵의 중단 기준 세 번째가 *"가입 대비 첫 판단이 20% 미만이면 영상 문제가 아니라 앱 문제"* 인데, 그걸 판정하려면 이 숫자가 있어야 한다.

## 배치 CB — 앱 안에서 영상으로 가는 길 (가장 약한 고리)

### S34-6 · 막힌 지점에 영상 링크

**할 일**

사용자가 멈추는 곳에 해당 사용법 영상을 건다. **네 자리만** 한다. 더 늘리면 광고처럼 보인다.

| 자리 | 영상 | 문구 |
|---|---|---|
| 오늘 화면 · 보유 0건 빈 상태 | `u2` | 종목을 직접 넣는 방법 (2분) |
| 온보딩 마지막 단계 | `u1` | 처음 쓰는 법 다시 보기 (4분) |
| 직접입력 화면(`AssetForms`) 상단 | `u2` | 손절선·목표가 정하는 법 |
| 설정 → 도움말 | 전체 | 사용법 영상 모아보기 |

**규칙**

- `VIDEOS[id].yt`가 비어 있으면 **아무것도 그리지 않는다.** 미발행 상태에서 빈 링크가 뜨면 안 된다
- 링크에 `?from=app&v=<id>` 를 붙인다 — 앱에서 나간 사람도 세야 어느 자리가 일하는지 안다
- 새 탭으로 연다(`rel="noopener"`). 앱을 떠나게 하지 말 것
- **팝업·모달 금지.** 카드 안의 한 줄로 충분하다

**S33 HA와 충돌하지 말 것**: 빈 상태 화면은 S33에서 "다음 걸음"을 이미 넣었다. **그 자리를 뺏지 말고 그 아래에 한 줄**로 붙인다.

### S34-7 · 이야기 탭 회차에 영상 임베드

**할 일**

`pages/pwa/story.js`가 `content/episodes/*.md`를 읽어 회차를 그린다(S29-7). 프론트매터에 `video` 한 줄을 더한다.

```markdown
---
title: 12주차 · 손절 규칙이 세 번 틀렸습니다
date: 2026-11-22
video: w12          # lib/videos.js 의 id
---
```

- `video`가 있고 `VIDEOS[video].yt`가 있으면 **썸네일 + 재생 링크**를 회차 상단에 그린다
- **iframe 자동재생 금지.** 썸네일과 링크로 충분하다. 앱이 무거워지고 데이터를 먹는다
- 없으면 지금처럼 텍스트만

**주의**: `content/episodes/`는 빌드타임(`getStaticProps`)이다. 회차를 새로 올리려면 커밋이 필요하다 — S32-9에서 확인된 제약이고 이번에도 그대로다. 화면에 그 사실을 적을 필요는 없다.

## 배치 CC — 주간 리포트에 연결

### S34-8 · 블록①에 유튜브 수치 편입

**할 일**

`lib/weeklyDigest.js`의 `buildDigest`가 만드는 **block1(이번 주 숫자)** 에 S34-5의 주차 기록을 더한다.

```
이번 주 숫자
  가입 6명 · 첫 판단 4명 · 7일 재방문 2명
  유튜브 경유 조회 41건 → 가입 3명        ← 신규
```

**규칙**

- 데이터가 없으면 그 줄을 빼고, 오류를 던지지 않는다(기존 원칙)
- `?record=1` 마스킹 대상이 아니다 — 건수와 퍼센트는 리포트의 본체다
- `buildWeeklyScript`의 블록① 글자수 상한(220자)을 넘기지 않게 문장을 짧게

**이게 순환을 닫는다.** 영상이 사람을 데려오고, 그 숫자가 다음 영상의 첫 블록이 된다.

## 배치 CD — 검증

```
[기능]
□ npm run build (= next build --webpack) 성공
□ /estimate?from=youtube&v=u1 진입 → tool_view / tool_view_youtube /
  tool_view_youtube_u1 세 카운터가 모두 +1
□ ?v=<등록되지 않은 값> → 무시되고 tool_view_youtube 만 +1 (카운터 증식 없음)
□ 첫 접점 보존: v=u1 로 들어온 뒤 다른 경로로 재방문해도
  localStorage 값이 u1 그대로 (덮어쓰지 않음)
□ 31일 지난 값은 버려짐
□ 가입 시 출처가 함께 전송되고 정비소에 반영됨
□ 정비소 유튜브 블록이 영상별로 나뉘어 보임
□ VIDEOS[id].yt 가 빈 상태에서 앱 어디에도 빈 링크가 없음   ← 반드시 확인
□ 영상 링크가 새 탭으로 열리고 rel="noopener" 가 붙음
□ 이야기 회차에 video 없으면 지금과 동일하게 렌더
□ 주간 리포트 블록①에 유튜브 줄이 뜨고, 데이터 없으면 줄이 사라짐
□ 블록① 글자수 220자 이내 유지

[원칙]
□ 개인을 따라다니는 식별자를 만들지 않았다      ← 눈으로 확인
□ IP를 저장하지 않는다 (기존 주석과 일치)
□ 유튜브 ID가 lib/videos.js 밖에 하드코딩되지 않았다
□ 빈 상태 화면에서 S33 HA의 "다음 걸음"을 밀어내지 않았다
□ git diff 에 CRLF 유령 변경 없음
```

**"빈 링크가 없음"을 대충 넘기지 말 것.** 이 스프린트는 **영상이 하나도 없는 상태에서** 배포된다. 미발행 영상의 링크가 노출되면 첫 사용자가 깨진 앱을 본다.

## 3. 이 스프린트가 끝나면

```
영상 발행  → lib/videos.js 에 yt ID 한 줄 추가 → 배포
              그 순간 앱 안 네 자리에 링크가 살아나고,
              설명란 링크가 영상별로 집계되기 시작한다.

다음 토요일 → /pwa/weekly-report 의 블록①에
              "유튜브 경유 조회 N건 → 가입 M명" 이 자동으로 들어온다.
```

**영상을 찍기 전에 이게 끝나 있어야 한다.** 나중에 붙이면 첫 몇 편의 성과를 영영 모른다.

## 배치 CA — 어느 영상이 일하는가

### S34-1 · lib/videos.js 영상 등록부
- **한 것**: `lib/videos.js` 신설 — `VIDEOS`(u1·u2·u3, yt 빈칸=미발행)·`isKnownVideo`(발행됨)·`isRegisteredVideo`(등록됨, 출처검증)·`videoUrl(id,from)`(yt 없으면 null)·`videoThumb`·`videoTitle`. ★유튜브 ID의 유일한 진실. id=소문자+숫자 3자.
- **파일**: `lib/videos.js`.
- **검증**: build 성공. yt 빈 상태에서 videoUrl→null(빈 링크 안 그림).

### S34-2 · 출처 파라미터 확장 ?from=youtube&v=<id>
- **한 것**: `estimate.js`가 `v`(3자)도 URL에서 읽어 조회 fetch·로그인 CTA에 전달. 프록시(`pages/api/public/re/estimate.js`)가 `v`를 **isRegisteredVideo로 검증**(모르는 값 무시) 후 `tool_view`·`tool_view_youtube`·`tool_view_youtube_<v>` **3단계** 카운터 +1. 백엔드 `_METRIC_RE`를 2단계 접미사 허용으로 확장.
- **파일**: `pages/estimate.js`, `pages/api/public/re/estimate.js`, `account_api.py`(:5002).
- **검증**: :5002 실측 — `tool_view_youtube_u1` bump OK, 잘못된 값 거부. (배포 후 프로덕션 3카운터 동시 +1은 CD에서.)

### S34-3 · 첫 접점(first-touch) 보존
- **한 것**: `/estimate` 진입 시 `onehub_first_src`(www origin) 저장 + **★교차출처(www→app) 우회**: 로그인 CTA에 `src·v` 실어 보내고 `login.js`가 **앱 origin** `onehub_first_src`={`youtube:u1`}로 저장. **이미 신선한 값이 있으면 덮어쓰지 않음(first-touch)·30일 만료.** `funnel.js markFunnel("signup")` 최초 시 이 값을 서버 집계로 전송(youtube만).
- **왜 first-touch**: 영상 보고 며칠 뒤 직접 가입한 사람을 유튜브 성과에 남기기 위함(영상은 데려오는 일).
- **파일**: `pages/estimate.js`, `pages/login.js`, `lib/funnel.js`, `pages/api/pwa/video-conv.js`(신규).
- **검증**: build 성공. 덮어쓰기 방지·30일 만료 로직 코드 확인. (실동작은 로그인 게이트라 CD/사용자.)

### S34-4 · 정비소에 유튜브 줄
- **한 것**: `MaintenanceShop.js`에 "유튜브 경유" 카드 — 도구조회→가입→전환율(전체) + 영상별(by_source의 `youtube_<id>` 파싱, videoTitle). "읽는 법" 한 줄(전환율 낮음=영상 나쁨 아니라 앱이 그 사람에게 안 맞을 수 있음, 첫 판단 함께 보라).
- **파일**: `components/MaintenanceShop.js`.
- **검증**: build 성공. 데이터 없으면 카드 자체 안 뜸.

### S34-5 · 주차별 전환 기록
- **한 것**: :5002 `weekly_video_stats(week,video,metric,cnt)` 테이블 + `POST/GET /api/v2/weekly-video`. metric=views(estimate 프록시)·signups·verdicts(video-conv 프록시). **주차 경계는 `lib/weeklyDigest.weekBounds` 재사용**(주간 리포트와 동일). 첫 판단(verdicts)까지 기록 → 로드맵 중단기준(가입 대비 첫판단 20%) 판정용.
- **파일**: `account_api.py`, `pages/api/public/re/estimate.js`, `pages/api/pwa/video-conv.js`, `lib/funnel.js`.
- **검증**: :5002 실측 — weekly-video bump/read OK, 잘못된 week/metric 거부.

**CA 배치: 완료. 백엔드(:5002) 배포·재시작 완료, 프론트 Vercel 배포 커밋 아래.**

## 배치 CB — 앱 안에서 영상으로 가는 길

### S34-6 · 막힌 지점에 영상 링크(네 자리)
- **한 것**: `components/VideoLink.js` 신설 — ★yt 없으면 `null`(빈 링크 금지)·새 탭·`rel=noopener`·`?from=app&v=<id>`·팝업/모달 없음. 네 자리 배선:
  1. 오늘 화면 보유 0건 빈 상태 → `u2`(S33 '빠른 입력' **아래** 한 줄, 다음 걸음 안 밀어냄)
  2. 온보딩 완료 단계 → `u1`
  3. 직접입력 `AssetForms` 상단 → `u3`(★WO 표는 u2로 적혔으나 문구가 "손절선·목표가"라 u3가 맞음 — 판단하여 u3)
  4. 설정 → 도움말 → 발행된 usage 영상 목록(미발행이면 목록 자체 안 뜸)
- **파일**: `components/VideoLink.js`, `pages/pwa/today.js`, `pages/pwa/onboarding.js`, `components/shared/AssetForms.js`, `pages/pwa/settings.js`.
- **검증**: node — 미발행 상태에서 videoUrl=null·발행된 영상 0 → **빈 링크 없음 PASS**. 발행 시(yt 채우면) 링크 생성 PASS.

### S34-7 · 이야기 회차에 영상 임베드

- **파일**: `pages/pwa/story.js`, `components/EpisodeCard.js`.
- **검증**: build 성공. video 없으면 기존과 동일 렌더(코드 경로).

# S30 작업지시서 — 문턱 낮추기 + 계기판

> 작성 2026-09-05 · 선행: S29 후속(`28c0ca8`) 완료
> 근거: 아티팩트 **"세 사람의 한 달"** · 사업자 결정 = **방향 A + D**, **경계 없이 전부 동일**
> 주말 1회 분량. **10항목 4묶음.**
> 페르소나를 여섯(KIS 연동 3 · 미연동 3)으로 늘려 재검증한 결과 **두 항목이 추가**됐습니다 — ETF 판단 누락, 관망 채점의 불공정.

## 0. 이 스프린트가 고치는 것

세 페르소나를 코드 경로에 태워 본 결과, 셋 중 둘이 2주 안에 떠납니다. 원인은 기능 부족이 아니라 **한 줄**이었습니다.

```
today.js:271  const positions = parsePositions(dash);
today.js:91   dash?.balance?.positions      ← /api/pwa-dashboard = KIS 계좌 잔고만

today.js 전체에 onehub_stock_holdings · getStockHoldings · ManualHoldingsCard 참조 0건
today.js:652  "증권사 연동 보유 종목이 없어요 — 조치할 주식이 없습니다."
```

**종합자산은 직접 입력을 인정합니다.** `assets.js:248` 은 `KIS N종목 + 직접입력 M종목` 이라 정확히 쓰고, 단일 원장(`lib/ledger.js`)도 둘을 합칩니다. **오늘 화면만 인정하지 않습니다.** 그런데 그 오늘 화면이 판단 원장의 **유일한 입구**입니다(S23 T-1).

그리고 온보딩은 **"3가지만 넣으면 내 자산으로 판단합니다"** 라고 약속합니다. 직접 입력을 권해 놓고 다음 날부터 무시합니다.

### 파급 — 사슬 전체가 이 한 줄에 걸려 있습니다

```
오늘 판단 0건 → 판단 원장 0건 → 심판석 빈 화면 → 월요일 카드 미발동
             → 주간 리포트 미발송 → 활동 토큰 0
```

S22~S29 여덟 스프린트로 쌓은 것의 대부분이 **KIS 연동자에게만** 열려 있습니다. 증권 계좌 연동은 신규 사용자에게 심리적 문턱이 가장 높은 행동입니다.

### 사업자 결정

- **방향** — A(문턱 낮추기) + D(계기판). C(유입)는 A가 확인된 뒤에.
- **경계선** — **없음.** 직접 입력이든 KIS든 **같은 기능**. 유료화 경계는 사용자가 몇 명 생긴 뒤에 정합니다. 다만 **나중에 잠글 수 있도록 판정 지점만 한 곳**에 만들어 둡니다.

## 0-2. 단순 교체로는 안 됩니다 — 반드시 읽으십시오

`actionStocks` 에 직접 입력 보유를 그냥 밀어 넣으면 **여전히 0건**입니다. 판정 함수가 요구하는 필드가 없기 때문입니다.

```js
// components/shared/KisHoldingsCard.js:32
export function deriveUrgency(p, cfg = HOLD_URG_CFG) {
  const cur = n(p.current_price) ?? 0, tgt = n(p.target) ?? 0, stp = n(p.stop_loss) ?? 0;
  const day = n(p.change_1d);
  if (stp > 0 && cur > 0 && cur <= stp * (1 + near))  return rank 0;  // 손절 임박
  if (tgt > 0 && cur > 0 && cur >= tgt * (1 - near))  return rank 1;  // 익절 검토
  if (day != null && Math.abs(day) >= cfg.spikePct)   return rank 2;  // 점검 필요
  return rank 3;                                                       // 유지
}
```

직접 입력 보유의 실제 스키마(`lib/stockHoldings.js:3`)는 이렇습니다.

```
{ id, name, code, shares, avgPrice, ccy, broker, market, account, buyDate, ts, trader, priceBasis }
```

**`current_price`·`target`·`stop_loss`·`change_1d` 가 전부 없습니다.**

### 그래서 세 단계로 나눕니다

| 단계 | 얻는 것 | 필요한 것 |
|---|---|---|
| **S30-1** 소스 통합 | 종목이 목록에 나타남 | 형태 변환만 |
| **S30-2** 시세·등락 연결 | **rank 2(당일 급변)가 즉시 작동** | `fetchStockQuotes` + 전일 종가 |
| **S30-3** 손절·목표 설정 | rank 0·1 작동 | 사용자 입력 |

**S30-2만 끝나도 급변 종목은 오늘 화면에 뜹니다.** 세 조건 중 하나는 시세만으로 판정되기 때문입니다. 순서를 지키십시오.

# ZA — 오늘 화면이 직접 입력을 보게

## S30-1 · 보유 소스 통합

### 할 일

1. **공용 함수로 합치십시오.** `lib/allHoldings.js`(신규) — `getAllStockPositions(trader)` 가 **KIS + 직접 입력**을 하나의 배열로 반환합니다.
   - **`today.js` 안에서 합치지 마십시오.** 종합자산·AI 페이지도 같은 것이 필요하고, 세 곳에서 각자 합치면 S22~S26에서 없앤 중복이 되살아납니다.
   - `lib/ledger.js` 가 이미 둘을 합쳐 금액을 냅니다. **거기서 쓰는 경로를 확인하고 같은 소스를 쓰십시오.** 새 저장소를 만들지 마십시오.
2. **필드 이름을 KIS 쪽에 맞추십시오.** 화면과 `deriveUrgency` 가 이미 KIS 형태를 기대합니다.
   ```
   직접입력            → 통합 형태
   name                → name
   code                → code
   shares              → qty
   avgPrice            → avg_price
   (없음)              → current_price   ← S30-2
   (없음)              → change_1d       ← S30-2
   (없음)              → target          ← S30-3
   (없음)              → stop_loss       ← S30-3
   ```
   **`source: "kis" | "manual"`** 를 반드시 넣으십시오. 화면이 구분해 표시해야 하고, 나중에 유료 경계를 그을 때 이 필드 하나로 갈립니다.
3. **오늘 화면이 이 함수를 쓰게** 하십시오 — `today.js:271` 의 `parsePositions(dash)` 를 교체.
4. **직접 입력 종목임을 표시하십시오.** 배지 하나면 됩니다(`직접입력` 또는 증권사 이름). 사용자가 "내가 넣은 게 여기 있구나"를 알아야 합니다.

### 함정

- **매도 버튼.** `KisHoldingsCard` 의 매도는 KIS 주문 API를 부릅니다. 직접 입력 종목에 그 버튼이 뜨면 안 됩니다. `source === "manual"` 이면 **판단 기록만** 되게 하고 주문 버튼은 숨기십시오.
- 같은 종목을 KIS와 직접 입력 양쪽에 갖고 있을 수 있습니다. **합치지 말고 따로 보여주십시오** — 계좌가 다릅니다. 다만 판단 기록은 종목코드 기준 하루 1건이므로(`getTodayDecision`) 중복 기록되지 않습니다.

### 합격선

- 직접 입력만 있는 계정에서 오늘 화면 보유 목록에 그 종목들이 보인다.
- `직접입력` 배지가 붙는다.
- 직접 입력 종목에 매도 버튼이 없다.
- 종합자산의 종목 수와 오늘 화면의 종목 수가 같다.

## S30-2 · 시세와 등락률 연결 ★여기서 켜집니다

### 먼저 확인

1. `lib/stockLive.js` 의 `fetchStockQuotes(holdings)` 는 `{ quotes, fxRate }` 를 반환하고, 각 quote는 **`{ price, currency, krw, date }`** 입니다. **`change_1d` 가 없습니다.**
2. **전일 종가를 어디서 얻을지 확인하십시오.** 후보 순서대로:
   - `/api/etf/quote` 응답에 전일 종가나 등락률 필드가 있는지(stooq CSV가 `sd2t2ohlcv` 라 시가·고가·저가가 있습니다)
   - **S27이 만든 `:5003` 일별 이력**(`/api/etf/history`) — FinanceDataReader 기반이고 **KRX도 정상 확인됨**. 여기서 직전 영업일 종가를 가져올 수 있습니다.
   - 어느 쪽을 택했는지와 그 이유를 결과 문서에 적으십시오.

### 할 일

1. **통합 목록에 `current_price` 를 채우십시오.** `ManualHoldingsCard` 가 이미 `fetchStockQuotes` 를 부르고 있으니 **같은 경로를 쓰고 새로 만들지 마십시오.**
2. **`change_1d` 를 채우십시오** — 위에서 정한 소스로. `(현재가 / 전일종가 - 1) * 100`.
3. **시세를 못 가져온 종목은 조용히 빼지 말고** 목록에 남기되 `시세 확인 중` 으로 표시하십시오(S24 원칙). 그 종목은 `deriveUrgency` 에서 rank 3이 됩니다.
4. **요청을 늘리지 마십시오.** 오늘 화면은 이미 마운트 요청을 줄여 왔습니다(S23 T-8, S29-3). `cachedJson` 을 쓰고, 종합자산이 같은 시세를 이미 받았다면 **캐시를 공유**하게 하십시오.

### 이것만으로 켜지는 것

`deriveUrgency` 의 세 조건 중 **rank 2(당일 급변 ≥ `spikePct`)는 `change_1d` 만으로 판정됩니다.** 손절선·목표가가 없어도 급변 종목은 즉시 오늘 화면에 올라오고, **거기에 판단 3버튼이 붙습니다.** 사슬이 여기서 켜집니다.

### 합격선

- 직접 입력 종목에 현재가와 등락률이 보인다.
- 등락률이 임계 이상인 종목이 `점검 필요` 로 오늘 조치 목록에 뜬다.
- **그 종목에서 [보유]를 누르면 `/pwa/record` 판단 건수가 1 증가한다.** ← 이 스프린트의 핵심 합격선
- 오늘 화면 마운트 요청 수가 늘지 않았다.

## S30-3 · 손절선·목표가를 사용자가 정하게

### 왜

`rank 0`(손절 임박)·`rank 1`(익절 검토)은 `stop_loss`·`target` 이 있어야 판정됩니다. KIS 종목은 매매 엔진이 정하지만, 직접 입력 종목은 아무도 정한 적이 없습니다.

### 할 일

1. **직접 입력 종목 상세에 두 칸을 더하십시오** — 손절선 · 목표가. **선택 입력이고 비워도 됩니다.**
2. **제안하되 강요하지 마십시오.** 값이 비어 있으면 한 줄로:
   ```
   손절선을 정해두면 가까워졌을 때 오늘 화면에서 알려드립니다
   [평단 −8%로 설정]  [직접 입력]  [안 할래요]
   ```
   - **자동으로 채우지 마십시오.** "앱이 사용자 값을 임의로 고치지 않는다"는 이 프로젝트의 전제입니다. 버튼을 눌러야 들어갑니다.
   - `안 할래요` 를 누르면 그 종목에 다시 묻지 마십시오(`stop_hint_dismissed`).
3. **저장은 `onehub_stock_holdings` 항목에** 필드를 더하십시오(`stopLoss`·`target`). 새 키를 만들지 마십시오. `SYNC_KEYS` 에 이미 등록돼 있어 기기 간 동기화가 따라옵니다.
4. **기본값 상수는 한 곳에** — `-8%`·`+15%` 같은 숫자를 여기저기 흩지 마십시오.

### 합격선

- 손절선을 정한 종목이 그 값에 가까워지면 오늘 화면에 `손절 임박` 으로 뜬다.
- 비워둔 종목도 목록에서 사라지지 않는다.
- 앱이 값을 자동으로 채우지 않는다.
- `안 할래요` 를 누른 종목은 다시 권하지 않는다.

# ZB — 6인 재검증에서 나온 둘

## S30-4 · ETF도 판단 대상에

### 왜 — 제 지시의 오류를 바로잡는 것입니다

S23에서 판단 버튼을 만들 때 **"1차는 주식만 — 부동산·ETF 항목은 종목코드가 없어 원장 스키마와 맞지 않습니다"** 라고 지시했습니다. **부동산에는 맞지만 ETF에는 틀렸습니다.**

```
onehub_etf_holdings   [{ id, ticker, shares, avgPrice, account, … }]   ← ticker 있음
today.js:482          recordDecisionWithPrice({ code: item.code, … })  ← code만 있으면 됩니다
```

ETF만 보유한 사용자(연금·해외 ETF 중심)는 S30-1~3을 다 해도 **여전히 판단 0건**입니다. 한 달 내내 자산관리 기능이 한 번도 작동하지 않습니다.

### 할 일

1. **`getAllStockPositions`(S30-1)를 확장하거나 형제 함수로** ETF 보유도 같은 통합 형태로 내보내십시오. `source: "etf"` 로 구분합니다.
   - `ticker` → `code`, `shares` → `qty`, `avgPrice` → `avg_price`.
   - 시세는 **S25-8·S27이 만든 경로**를 쓰십시오. ETF는 이미 일별 이력(`:5003`)과 현재가가 있습니다. 새로 만들지 마십시오.
2. **오늘 화면 판단 카드에 ETF 항목을 포함**하되 **배지로 구분**하십시오(`ETF`).
3. **판정 규칙을 ETF에 맞추십시오.** 개별주와 성격이 다릅니다.
   - 손절선·목표가는 ETF에 잘 안 맞습니다. **당일 급변(rank 2)** 과 **배분 이탈**을 주 신호로 쓰십시오.
   - 배분 이탈은 이미 `onehub_target_class`(S22-4)와 `recommendEtfs` 가 계산합니다. **재사용하고 새 규칙을 만들지 마십시오.**
4. **판단 문구를 자산군에 맞게** — 주식은 `[매도][보유][관망]`, ETF는 `[비중 줄임][유지][관망]` 이 자연스럽습니다. 원장 저장은 동일하게 `take`/`pass`.
5. **부동산은 이번에도 제외**입니다. 종목코드가 없고 하루 단위 판단 대상이 아닙니다. 이건 원래 판단이 맞았습니다.

### 합격선

- ETF만 보유한 계정에서 오늘 화면에 ETF 항목이 뜨고 판단이 기록된다.
- `/pwa/record` 판단 건수에 반영된다.
- 주식과 ETF가 배지로 구분된다.
- 부동산은 판단 대상에 없다.

## S30-5 · 관망을 공정하게 채점

### 문제

AI 제안을 거절만 하는 사용자는 성적표가 **매주 자기를 패자로 그립니다.**

```
verdictStats.js
  myRet = avg(details.map(d => d.decision === "take" ? d.ret : 0))   ← 관망 = 0%
  aiRet = avg(details.map(d => d.ret))                               ← AI = 전부 매매
```

상승장에서 관망 일변도면 **나 0% vs AI +3%** 로 항상 집니다. 계산은 맞지만 **이야기가 반쪽**입니다. 관망이 손실을 피한 경우를 세지 않기 때문입니다.

`getVerdictScorecard` 는 이미 **`missedCount`·`missedAvg`(관망했는데 오른 것 = 놓친 수익)** 를 계산합니다. **그 반대쪽이 없습니다.**

### 할 일

1. **`avoidedCount`·`avoidedAvg` 를 추가**하십시오 — 관망했는데 **내린** 종목. `missed` 와 정확히 대칭입니다. `getVerdictScorecard` 한 곳에만 더하십시오.
2. **성적표에 둘을 나란히** 놓으십시오.
   ```
   관망 12건 중
   놓친 수익   5건 · 평균 +3.2%
   피한 손실   7건 · 평균 −4.1%
   ```
3. **승패 문구를 다시 쓰십시오.** 관망 비율이 높은 사용자에게 `AI가 나았습니다` 만 반복하지 말고 근거를 함께.
   - `AI가 나았습니다 · 다만 관망 7건이 평균 −4.1% 손실을 피했습니다`
   - 이건 위로가 아니라 **사실을 다 말하는 것**입니다. 지금은 절반만 말하고 있습니다.
4. **`winRate` 정의는 건드리지 마십시오.** 이미 `pass && ret<0` 을 정답으로 세고 있어 관망을 공정하게 봅니다. 문제는 **`myRet` 표시와 승패 문구**입니다.
5. **관망 비율이 70% 이상이면**(`tendency === "신중형"`) 화면 상단에 성향을 밝히십시오 — `당신은 신중형입니다 · 관망 중심 투자자의 성적은 수익률보다 회피율로 보는 편이 맞습니다`.

### 합격선

- 성적표에 놓친 수익과 피한 손실이 함께 나온다.
- 관망만 한 계정에서 승패 문구가 근거와 함께 나온다.
- 기존 승률·건수 값이 변하지 않는다(회귀 없음).

# ZC — 첫 주에 떠나지 않게

## S30-6 · 온보딩 마지막에 첫 판단

### 왜

이 대리는 온보딩을 성실히 마쳤는데 **판단을 한 건도 기록하지 않은 채** 앱을 나갔습니다. 첫 판단이 없으면 심판석·주간 리포트가 영원히 비어 있고, 그 사용자는 이 앱의 유일한 차별점을 **한 번도 보지 못한 채** 떠납니다.

### 할 일

1. **STEP 5(완료) 화면에 판단 한 건**을 넣으십시오. `onboarding.js:331` 부근입니다.
   ```
   마지막으로 하나만 —
   방금 넣은 삼성전자, 지금 어떻게 보시나요?
   [계속 보유]  [줄일까 고민]  [관망]
   ```
   - 입력한 종목 중 **하나만** 고르십시오(가장 비중이 큰 것).
   - 누르면 `recordDecisionWithPrice({ source: "onboarding" })`. 기존 공용 함수를 쓰고 새로 만들지 마십시오.
   - **건너뛰기를 반드시 두십시오.** 강요하면 온보딩 완료율이 떨어집니다.
2. **기록 직후 무엇이 생겼는지 보여주십시오.**
   ```
   ✓ 첫 판단이 기록됐습니다
   3거래일 뒤 결과가 채점돼 성적표에 쌓입니다 · 월요일마다 요약을 보내드려요
   ```
   이 한 문장이 **앱을 쓰는 이유**를 설명합니다. 지금은 아무도 설명해 주지 않습니다.
3. **보유 종목이 없는 사용자**(부동산만 입력)에게는 이 단계를 건너뛰십시오. 없는 걸 만들지 마십시오.

### 합격선

- 온보딩을 마치면 판단 1건이 기록돼 있다.
- 건너뛸 수 있다.
- 보유 종목이 없으면 이 단계가 나오지 않는다.
- `source: "onboarding"` 으로 구분된다.

## S30-7 · 빈 화면에 다음 한 걸음

### 왜

이 대리는 2주차 월요일에 심판석을 열었고 **비어 있었습니다.** 그리고 아이콘을 지웠습니다. 빈 화면은 이탈 지점입니다.

### 할 일

빈 화면마다 **왜 비었는지와 무엇을 하면 채워지는지**를 쓰십시오. S24에서 정한 교정 원칙("없으면 왜 없는지를 쓴다")의 적용입니다.

| 화면 | 지금 | 바꿀 것 |
|---|---|---|
| 심판석 (판단 0건) | 빈 화면 | `아직 판단 기록이 없습니다 · 오늘 화면에서 보유 종목에 [보유]나 [관망]을 한 번 누르면 3거래일 뒤 채점이 시작됩니다 → 오늘 가기` |
| 성적표 (채점 0건) | 빈 화면 | `판단 3건 기록됨 · 첫 채점까지 2거래일 남았습니다` ← 진행 중임을 보이기 |
| 오늘 조치 0건 + 보유 0건 | `증권사 연동 보유 종목이 없어요` | `보유 종목을 넣으면 매일 조치할 것을 알려드립니다 → 빠른 입력` |
| 주간 리포트 미수신 | 아무 말 없음 | 설정 알림 항목에 `판단 기록이 쌓이면 월요일 아침에 보내드립니다` |

**금지** — 없는 숫자를 예시로 채워 실제인 척하지 마십시오. 예시를 쓰려면 `예시` 라고 분명히 표시하십시오(S24-8에서 정한 규칙).

### 합격선

- 판단 0건 계정에서 심판석에 다음 걸음과 이동 버튼이 있다.
- "증권사 연동" 문구가 직접 입력 사용자에게 더 이상 뜨지 않는다.
- 예시 수치가 실제 수치로 오인되지 않는다.

### 할 일

1. **`lib/funnel.js`(신규)** — 이정표에 **처음 도달한 시각만** 한 번씩 기록합니다. 이벤트 스트림을 만들지 마십시오. 다섯 개면 충분합니다.
   ```
   signup          첫 로그인
   onboard_done    온보딩 완료
   first_holding   보유 1건 입력(직접 또는 KIS 연동)
   first_verdict   판단 1건 기록          ← 가장 중요한 관문
   d7_return       가입 7일 뒤 재방문
   ```

### 발견 ① — 콘텐츠가 하단 탭에 가려집니다 (실제 버그)

`BottomNav` 는 `min-height: 56px` + 안전영역이고, FAB은 `bottom: 안전영역 + 68px` 에 높이 52px이라 **FAB 상단이 안전영역 + 120px** 입니다. 따라서 필요한 최소 여백은:

```
FAB 있는 페이지   ≈ 130px
FAB 없는 페이지   ≈  72px
```

그런데 실제 값은 **20px에서 140px까지 7배로 흩어져 있고**, 다음 페이지들은 **부족합니다.**

```
index.js        20 / 28px   ← FAB까지 있는데 130px 필요. 가장 심각
realestate.js   20px
ai-advisor.js   24px
system-health   24px
glossary.js     40px
onboarding.js   40px
today.js        22px        ← 일부 컨테이너
```

마지막 카드가 하단 탭 뒤로 들어가 **읽을 수도 누를 수도 없습니다.** 통일감 이전에 버그입니다.

### 발견 ② — 헤더가 두 종류입니다

`components/AppHeader.js`(로고 · 트레이더 배지 · 🔍 · 피드백 · ⚙️)를 여덟 페이지가 쓰는데, **today·assets 는 자기 헤더**(`sticky-hdr` + `td-hd`/`as-hd`)를 따로 갖고 있습니다. 구성은 거의 같은데 구현이 둘입니다. 여백·아이콘 크기·상단 안전영역 처리가 미세하게 다릅니다.

### 발견 ③ — 헤더가 사라지는 페이지가 있습니다

`english` · `record` · `vocab` · `clip` 은 `position: sticky` 가 없어 스크롤하면 헤더가 위로 밀려 사라집니다. 다른 페이지는 남아 있습니다. **같은 앱 안에서 헤더가 어떤 데선 따라오고 어떤 데선 안 따라옵니다.**

### 발견 ④ — 빠른입력 버튼이 나타났다 사라집니다

FAB(＋)이 `assets` 와 `index` 두 페이지에만 있습니다. 오늘 화면에서 자산을 입력하고 싶으면 FAB이 없습니다. **있다가 없어지는 버튼은 없는 버튼보다 나쁩니다.**

### 발견 ⑤ — 스와이프는 잘 됐습니다

탭이 있는 여섯 페이지에 모두 `useSwipeTabs` 가 붙었습니다(S25-5). 구현체 하나를 공유하므로 촉감도 같습니다. **이 부분은 건드리지 마십시오.** 남은 것은 탭의 *생김새* 18종을 하나로 만드는 일입니다(S26-5).

## 0-3. 듣는 경제 분류 실측 — 원하시는 테마가 이미 데이터에 있습니다

### 지금 구조

```js
MODES (대메뉴)   en=경제영어 · gen=일반영어 · zh=중국어
SUBTABS (하위)   en/zh : news · video · idiom   (형식)
                 gen   : live · review          ← 개수도 성격도 다름
TRACK (카드 배지) economy=경제 · display=디스플레이 · general=생활영어/생활중국어
```

### 혼선의 정체 — 축이 셋인데 두 축이 뒤섞여 있습니다

**① 대메뉴가 언어와 테마를 섞습니다.** `en`(경제영어)과 `gen`(일반영어)은 **둘 다 영어인데 테마로 갈렸고**, `zh`(중국어)는 **언어**입니다. 같은 줄에 "일반영어"와 "중국어"가 나란히 있는 게 논리적으로 어긋납니다. 사용자가 "중국어 경제"를 보려면 어디로 가야 하는지 화면이 답하지 못합니다.

**② 하위 메뉴가 대메뉴마다 다릅니다.** en·zh는 3개(뉴스·영상·이디엄), gen은 2개(라이브·주말복습)입니다. 대메뉴를 옮기면 **하위 메뉴의 개수와 성격이 통째로 바뀌어** 위치 감각이 깨집니다.

**③ 정작 테마는 탐색에 안 쓰입니다.** `lesson.track` 에 **`economy` · `display` · `general` — 사용자가 요청한 바로 그 분류**가 이미 들어 있는데, 카드 구석의 작은 배지로만 표시됩니다.

### 좋은 소식 — 배관이 이미 깔려 있습니다

`pages/api/english/[fn].js` 의 화이트리스트를 보십시오.

```js
today:   (q) => `/english/today${qs(q, ["medium", "track", "language"])}`,
lessons: (q) => `/english/lessons${qs(q, ["medium", "track", "language", "limit", "before"])}`,
```

**`track` 이 이미 허용 목록에 있습니다.** 프론트가 안 보내고 있을 뿐입니다. `/api/english/lessons?track=economy&language=en` 이 지금도 라우팅됩니다.

→ **:5005가 실제로 `track` 을 걸러 주는지만 확인하면**(curl 한 번) 축 전환은 프론트 작업으로 끝납니다. 안 걸러 주면 전체를 받아 클라에서 `lesson.track` 으로 묶으면 됩니다 — 어느 쪽이든 가능합니다.

### 제안하는 구조 — 축을 셋으로 분리

```
축 1 · 언어   영어 · 중국어              ← 세그먼트(상단)
축 2 · 테마   경제 · 디스플레이 · 회화    ← 세그먼트(그 아래) · 스와이프 대상
축 3 · 형식   전체 · 뉴스 · 영상 · 이디엄  ← 칩(선택) · 스와이프 아님
```

- **언어가 2개**가 되어 "중국어 경제"·"영어 디스플레이" 같은 조합이 자연스럽게 열립니다.
- **테마 3개가 두 언어에서 같습니다.** 하위 메뉴가 대메뉴마다 달라지는 문제가 사라집니다.
- **`gen`(일반영어)은 대메뉴에서 없어집니다.** 그 안에 있던 둘은 이렇게 갑니다.
  - `live`(생활영어 유튜브) → **테마 "회화" + 형식 "영상"**
  - `review`(주말복습) → 테마와 무관한 별개 기능이므로 **상단 링크**(내 단어장 옆)
- 라벨 `general` 은 **"회화"** 로. 두 언어에서 같은 글자 수라 세그먼트 폭이 흔들리지 않습니다(기존 "생활영어"/"생활중국어"는 부제로 남겨도 됩니다).

## S26-1 · 토큰 세우기

### 할 일

1. **활자 8단 신설** — `styles/globals.css` 에 추가합니다. **단위는 `rem`** 으로 통일하십시오. S24-4에서 핀치 줌을 막았기 때문에 OS 글자 크기 설정을 존중하는 것이 더 중요해졌습니다. `px` 로 고정하면 접근성이 한 번 더 나빠집니다.
   ```
   --fs-1: 0.6875rem   /* 11px  라벨·배지 */
   --fs-2: 0.75rem     /* 12px  캡션·보조 */
   --fs-3: 0.8125rem   /* 13px  작은 본문 */
   --fs-4: 0.875rem    /* 14px  본문 */
   --fs-5: 1rem        /* 16px  강조 본문 */
   --fs-6: 1.1875rem   /* 19px  카드 제목 */
   --fs-7: 1.4375rem   /* 23px  섹션 제목 */
   --fs-8: 1.875rem    /* 30px  숫자 헤드라인 */

   ```
   --sp-1: 4px   --sp-2: 8px   --sp-3: 12px
   --sp-4: 16px  --sp-5: 20px  --sp-6: 24px
   ```
   기존 `--sp-1`·`--sp-5` 값이 다르면 **기존 값을 바꾸지 말고** 스케일을 그 값에 맞춰 조정하십시오. 이미 쓰이고 있습니다.
3. **모서리는 새로 만들지 않습니다.** `--radius-sm` `--radius-md` `--radius-card` `--radius-pill` 네 개만 쓰기로 정하고, `--radius-lg`·`--radius-hero` 는 기존 사용처를 유지하되 새로 쓰지 않습니다. 각 토큰의 현재 값을 결과 문서에 적으십시오.

## S26-2 · 색 토큰 정본화

### 문제

색 토큰 사용률은 97%인데 통일이 안 됩니다. **이름이 세 세대 겹쳐 있기 때문입니다.**

```
배경 8개  --bg · --bg-base · --bg-card · --card-bg · --color-bg · --color-card · --color-surface · --bg-surface
글자 10개 --color-ink · --color-ink-2 · --color-ink-3 · --color-text · --text-primary ·
          --text-secondary · --text-tertiary · --text-dim · --color-muted · --label-color
```

실제 역할은 각각 3개 정도입니다. 개발자가 `--text-secondary` 를 고르느냐 `--color-ink-2` 를 고르느냐에 따라 **페이지마다 다른 회색**이 나옵니다.

### 할 일

1. **정본을 `--color-*` 계열로 정합니다** — 가장 많이 쓰이고 다크 모드가 이미 이 계열로 성립합니다.
2. **나머지는 지우지 말고 별칭으로** — `--text-secondary: var(--color-ink-2);` 형태로 정본을 가리키게 합니다. **지우면 회귀가 납니다.** 22개 파일에 흩어져 있습니다.
3. **값이 다른 경우 결과 문서에 적으십시오.** 예를 들어 `--text-secondary` 와 `--color-ink-2` 의 현재 값이 다르면, 별칭으로 묶는 순간 **일부 화면의 회색이 바뀝니다.** 그건 의도된 통일이지만, 어느 화면이 바뀌는지 알고 있어야 합니다.
4. **하드코딩 79종 중 `#fff`(83회)만 처리하십시오.** 나머지 78종은 차트·배지 등 의미가 있는 색일 수 있으니 이번 스프린트에서 건드리지 마십시오. `#fff` 는 다크 모드에서 흰 글자가 흰 배경에 얹힐 위험이 있으니 토큰으로 바꿉니다.

### 합격선

- 배경 8개·글자 10개 이름이 전부 남아 있고, 정본 3개를 가리킨다.
- 다크 모드에서 읽기 어려운 곳이 새로 생기지 않았다.
- 값이 바뀌는 화면 목록이 결과 문서에 있다.

## S26-4 · 공용 카드

### 할 일

`components/shared/Card.js` — **껍데기만** 담당합니다.

```
<Card tone="default|accent|warn" pad="sm|md" as="section">
```

- 담당: 배경 · 테두리 · 모서리(`--radius-card`) · 그림자(`--shadow-card`) · 안쪽 여백(`--sp-3`/`--sp-4`) · 아래 간격

**styled-jsx 는 컴포넌트 스코프입니다.** `Card.js` 안에서 쓴 스타일은 `children` 으로 넘어온 요소에 **적용되지 않습니다.** 그래서:

- `Card` 는 **바깥 껍데기만** 갖고, 내부 콘텐츠(제목·행·버튼)의 스타일은 **각 페이지가 계속 자기 styled-jsx 로** 갖습니다.
- 카드 제목처럼 반복되는 것은 `Card.Title` 같은 하위 컴포넌트로 따로 빼거나, 그냥 각 페이지에 두되 **`--fs-6` 토큰을 쓰게** 하십시오.
- 억지로 `:global()` 을 쓰지 마십시오. 전역 오염이 나면 되돌리기 어렵습니다.

### 합격선

- `Card.js` 가 있고 세 tone이 다크 모드에서 모두 성립한다.
- 아직 어느 페이지도 바꾸지 않았다(부품만 만듭니다).

## S26-7 · 하단 여백과 FAB 규칙 ★버그 수정

### 문제 (실측)

```
BottomNav   min-height 56px + 안전영역
FAB         bottom: 안전영역 + 68px, height 52px  →  상단 = 안전영역 + 120px

필요 최소    FAB 있음 ≈ 130px  ·  FAB 없음 ≈ 72px
실제 값      20 ~ 140px (7배 차이)

부족한 페이지
  index.js        20 / 28px   ← FAB까지 있는데 130px 필요. 가장 심각
  realestate.js   20px
  ai-advisor.js   24px
  system-health   24px
  glossary.js     40px
  onboarding.js   40px
  today.js        22px (일부 컨테이너)
```

**마지막 카드가 하단 탭 뒤로 들어가 읽을 수도 누를 수도 없습니다.**

### 할 일

1. **토큰으로 규칙을 고정** — `globals.css` 에 `--nav-height` 가 이미 있습니다. 그 위에:
   ```
   --nav-clearance:     calc(env(safe-area-inset-bottom, 0px) + 84px)   /* FAB 없는 페이지 */
   --nav-clearance-fab: calc(env(safe-area-inset-bottom, 0px) + 140px)  /* FAB 있는 페이지 */
   ```
   기존 84·140이 이미 여러 페이지에서 쓰이고 있으니 그 값을 정본으로 삼는 것이 안전합니다.
2. **전 페이지 적용** — 하단 탭이 있는 모든 PWA 페이지의 최하단 여백을 두 토큰 중 하나로 바꾸십시오.
3. **FAB을 어디에 둘지 정하십시오.** 지금은 `assets`·`index` 두 곳뿐이라 나타났다 사라집니다. 둘 중 하나:
   - **(권장) 하단 탭이 있는 전 페이지에 표시.** 자산 입력은 어디서든 필요합니다. 그러면 여백도 `--nav-clearance-fab` 하나로 통일됩니다.
   - 또는 지금처럼 두 곳만 두되, **그 두 곳이라는 규칙을 결과 문서에 명시**하고 나머지에는 절대 안 나오게 하십시오.
4. **온보딩은 예외입니다** — 하단 탭이 없는 화면이면 여백 규칙을 적용하지 마십시오. 먼저 하단 탭 유무를 확인하십시오.

### 합격선

- 모든 페이지에서 **마지막 카드 아래에 하단 탭과 겹치지 않는 여백**이 있다.
- 여백 값이 페이지 파일에 리터럴로 남아 있지 않다(토큰만).
- FAB 노출 규칙이 하나로 정해졌고 결과 문서에 적혀 있다.
- 계측기의 "하단 여백 미달 페이지" 가 **0**이다.

## S26-11 · 듣는 경제 분류 축 전환 (WE에 포함)

### 왜 여기인가

WE에서 듣는 경제의 탭을 `SegTabs` 로 어차피 새로 만듭니다. **같은 페이지를 두 번 열지 않도록** 축 전환을 여기서 함께 합니다. 다만 이건 표현이 아니라 **정보 구조 변경**이므로, 커밋을 나누고 결과 문서에 따로 적으십시오.

### 먼저 확인 (한 번이면 됩니다)

```
curl "http://54.180.54.132:5005/english/lessons?track=economy&language=en&limit=5"
curl "http://54.180.54.132:5005/english/lessons?track=display&language=zh&limit=5"
```

- **걸러 주면** → 프론트가 `track` 을 보내는 것으로 끝.
- **안 걸러 주면** → 전체를 받아 클라에서 `lesson.track` 으로 묶습니다. 레슨 수가 적으므로(limit 12) 부담이 없습니다.
- 어느 쪽인지 **결과 문서에 적으십시오.**

### 할 일

1. **축 셋으로 분리**
   ```
   언어  영어 · 중국어              SegTabs(2칸) · 상단
   테마  경제 · 디스플레이 · 회화    SegTabs(3칸) · 스와이프 대상
   형식  전체 · 뉴스 · 영상 · 이디엄  칩 · 스와이프 아님
   ```
   - 스와이프는 **테마 축에만** 겁니다. 2단 스와이프(언어+테마)는 손가락이 헷갈립니다.
2. **`gen` 대메뉴 해체**
   - `live`(생활영어 유튜브) → 테마 **회화** · 형식 **영상** 으로 편입.
   - `review`(주말복습) → 상단 링크로 이동(`⭐ 내 단어장` 옆에 `📝 주말복습`). API는 `?language=` 만 받으므로 테마와 무관한 별개 기능이 맞습니다.
   - **기능을 없애지 마십시오.** 위치만 옮깁니다.
3. **라벨** — `TRACK_KO` 의 `general` 을 **"회화"** 로. `TRACK_KO_ZH` 도 동일하게 "회화". 두 언어에서 글자 수가 같아 세그먼트 폭이 흔들리지 않습니다. 기존 "생활영어"/"생활중국어"는 필요하면 부제로만.
4. **상태 저장** — 마지막으로 본 언어·테마를 기억하십시오(`onehub_listen_last`). 매번 첫 탭으로 돌아가면 회화만 듣는 사람이 매일 두 번씩 눌러야 합니다. 기기별이 자연스러우니 `SYNC_KEYS` 대상은 아닙니다.
5. **URL 반영** — `/pwa/english?lang=en&track=economy`. S24-5에서 정한 대로 스와이프는 `replace`, 탭 클릭도 `replace`.

### 함정

- **빈 조합이 생깁니다.** "중국어 × 디스플레이"에 레슨이 0건일 수 있습니다. 그때 **탭을 숨기지 말고** `아직 준비된 학습이 없어요 · 다른 테마를 보시겠어요?` 로 쓰십시오. 탭이 조합마다 나타났다 사라지면 더 혼란스럽습니다(S24에서 정한 "없으면 왜 없는지를 쓴다").
- 기존 `SUBTABS` 상수를 지우기 전에 **참조하는 곳을 전부 찾으십시오.** 990줄 안에 흩어져 있습니다.
- `medium` 파라미터는 계속 씁니다 — 형식 칩이 그걸로 걸러냅니다. **API 계약은 안 바뀝니다.**

### 합격선

- 스와이프로 테마가 바뀌고 언어는 안 바뀐다.

   [intro]   목표어 · 오늘 이 테마에 무엇이 있는지 한두 문장
   [레슨 1]  기존 /api/english/audio/{id}          ← 그대로
   [bridge]  목표어 한 줄 · 다음으로 넘어가는 말
   [레슨 2]  …
   [outro]   목표어 마무리 + 한국어 한 줄 요약(설정으로 끄기)
   ```
   브리지만 새로 합성하고 **본문은 기존 오디오를 그대로 이어붙입니다.**

2. **테마마다 성격을 다르게** — "각 페이지의 성격에 맞고"의 실행입니다.
   | 테마 | 나레이션 성격 |
   |---|---|
   | 경제 | 브리핑 톤. 숫자·기업명을 또박또박 |
   | 디스플레이 | 오늘 나온 **산업 용어 2~3개**를 끝에 다시 짚어 줌 |
   | 회화 | **어떤 상황에서 쓰는 표현인지** 상황을 먼저 설명 |
   프롬프트를 테마별로 나누되 **한 파일에 상수로** 모으십시오(`lib/clipNarration.js`).

3. **난이도 조절** — 목표어만으로는 어려울 수 있습니다.
   - 설정에 토글: `목표어만` / **`목표어 + 한국어 요약`(기본)**
   - 브리지 문장은 **짧고 쉬운 어휘**로 생성하도록 프롬프트에 명시. 원문 기사 수준으로 쓰면 브리지가 본문보다 어려워집니다.

4. **비용 — 이게 이 항목에서 가장 중요합니다.**
   - 나레이션은 **사용자마다가 아니라 테마마다 하루 한 번** 생성합니다. 레슨은 모든 사용자에게 같으니 결과도 같습니다.
   - **서버(:5005)에서 생성해 캐시**하십시오. 클라가 `tutor-chat` 을 직접 부르게 하지 마십시오.
   - 기존 **서킷브레이커를 반드시 통과**시키십시오. 우회 경로를 만들지 마십시오.
   - 생성 실패 시 **브리지 없이 레슨만 이어붙여 재생**합니다. 클립 자체가 실패하면 안 됩니다.

5. **하루 한 클립(S25-10)과의 관계** — `lib/dailyClip.js` 의 ⑥ 외국어 트랙을 **이 테마 클립으로 교체**하십시오. 한국어 나레이션 트랙(①~⑤)은 그대로 두고, 외국어 구간만 목표어 나레이션이 됩니다. 두 개의 재생목록을 만들지 마십시오.

6. **진입로** — 듣는 경제의 각 테마 화면 하단에 한 줄:
   `🎧 경제 전체 듣기 · 4편 · 약 7분 · 영어 해설`

### 함정

- **자동 재생 금지** — iOS는 사용자 제스처 없이 재생이 안 됩니다.
- **미리 다 만들지 마십시오** — S24-10에서 정한 "다음 한 편만 preload" 규칙 그대로.
- LLM이 만든 문장을 **레슨 원문인 것처럼 표시하지 마십시오.** `AI 해설` 이라고 밝히십시오.
- 총 길이 **10분 초과 시 잘라내십시오.**

### 합격선

- 경제·디스플레이·회화 각각에 목표어 해설이 붙은 통합 클립이 있다.
- 브리지가 목표어이고, 본문은 기존 레슨 오디오 그대로다.
- 나레이션 생성이 하루 한 번·테마당 한 번이다(로그로 확인).
- 생성이 실패해도 레슨만으로 재생된다.
- 하루 한 클립의 외국어 구간이 이 클립으로 바뀌었고, 재생목록이 하나다.
- 설정에서 한국어 요약을 끌 수 있다.

# 공통 규칙

## 절대 어기면 안 되는 것

1. **CRLF** — 저장소 전체가 CRLF. 파일을 통째로 다시 쓰지 말고 부분 편집.
2. **`next build --webpack`** — Turbopack 프로덕션 빌드는 하이드레이션을 깨뜨립니다.
3. **WA~WF는 기능 변경 0건.** 로직·API·상태를 만지지 마십시오. 예외는 S26-11(정보 구조)과 WG(기능 추가)뿐이고, 그 둘은 커밋을 따로 나눕니다.
4. **토큰을 지우지 마십시오.** 별칭으로 남깁니다 — 22개 파일에 흩어져 있습니다.
5. **`:global()` 남용 금지** — styled-jsx 전역 오염은 되돌리기 어렵습니다.
6. **백업 파일(`*.bak*`)을 고치지 마십시오.** 집계에서도 뺍니다.

## 바꾸지 말아야 할 설계 전제

- 하단 탭 사이 이동은 **클릭만**. 스와이프로 만들지 마십시오.
- 대결은 KIS 실보유 금액 기준. 실거주 부동산은 투자자산 제외.
- URL 경로는 바꾸지 않습니다.

## 각 묶음 완료 절차

```
1. bash scripts/verify_s19.sh          → FAIL=0 + 계측 5숫자 기록
2. npm run build                        → 통과 확인
3. git add -A && git commit             → "S26 WA: ..." 형식
4. git pull --rebase origin main && git push origin main
5. docs/S26-WA_결과.md 작성             → 계측 숫자 변화 포함
6. 여기서 멈추고 보고                    ← 다음 묶음 자동 진행 금지
```

## 결과 문서 규칙

- 계측기 다섯 숫자를 **묶음 시작 시점과 끝 시점** 둘 다 적으십시오.
- 색 별칭으로 **값이 바뀐 화면 목록**을 적으십시오(S26-2).
- 확인 못 한 것은 `⚠️ 사용자 확인 필요` 로 남기고 통과 처리하지 마십시오.
- **"이미 존재"를 통과 사유로 쓰려면 렌더 경로까지 확인**하십시오(S22-3의 죽은 스파크라인 사례).

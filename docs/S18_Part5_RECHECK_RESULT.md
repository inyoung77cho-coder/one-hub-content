## G12 판정: 코드 결함은 **확정**, 데이터 오염은 **기각**

### 코드는 실제로 달력일이었다 (G12 확정)

```python
# block_accuracy_checker.py:32 (수정 전)
check_cutoff = (datetime.now() - timedelta(days=3)).strftime("%Y-%m-%d")
```

지시서 W5-0의 지적이 맞았습니다. **`timedelta(days=3)` = 달력 3일**이고 거래일이 아닙니다.

### 그런데 데이터는 왜 안 틀렸나

지시서 W5-5 판정표는 *"gap_days가 전부 3.0 → 달력일로 계산됨 → 연휴 낀 건은 오염"*이라 했고,
실측 gap은 **전부 정확히 3.0**이었습니다. 여기까지는 지시서대로입니다.

**하지만 차단일 요일 분포가 구원했습니다:**

```
차단일 요일:  일 6건 · 월 18건 · 화 14건   ← 수·목·금 0건
```

| 차단 요일 | T+3 달력일 | T+3 거래일 | 일치? |
|---|---|---|---|
| 일요일 | 수요일 | 수요일 | ✅ 우연 |
| 월요일 | 목요일 | 목요일 | ✅ 우연 |
| 화요일 | 금요일 | 금요일 | ✅ 우연 |
| **금요일** | **월요일** | **수요일** | ❌ **2거래일 차이** |

`block_accuracy` 데이터는 **2026-06-14 ~ 06-16 사흘치뿐**이고 전부 주 초반이라
**주말이 T+3 구간에 끼지 않았습니다.** 그래서 달력일 = 거래일이 됐습니다.

> **운이 좋았던 것이지 코드가 맞았던 게 아닙니다.**
> **금요일 차단이 한 건이라도 생기는 순간 즉시 틀립니다.** 수요일 차단도 마찬가지입니다.

**따라서 55.3%는 오염되지 않았습니다.** 재채점해도 값이 그대로입니다.

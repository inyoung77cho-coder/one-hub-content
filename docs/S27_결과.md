## 3) user_state 실계정 e2e 검증 + 동기화 실패 화면 노출 — ✅ 완료

### ★ 진단: "dormant" 의 진짜 원인 = 생산자·소비자가 다른 DB/테이블
- **생산자**(라이브 동기화): `:5002 re_spot_endpoints.py` 가 `/api/v2/user-state` 를 **중복 정의**(account_api 보다 먼저 등록되어 그림자)하고, **apartment.db 의 `user_sync`** 테이블에 저장.
- **소비자**(크론 `weekly_verdict_report.py`·`tax_calendar_push.py`): **accounts.db 의 `user_state`** 를 읽음 — 이 테이블은 account_api 의 (그림자로 죽은) 라우트용이라 **0행**.
- 결과: **동기화는 정상 작동**(실계정 A 41KB·B 32KB·카카오유저 25KB payload 존재) 인데, 소비자만 빈 테이블을 봐서 주간 리포트·세금 푸시가 **한 명도 발송 안 됨**(dormant). 메모리의 "accounts.db 0행" 은 잘못된 테이블을 본 것.

### 수정(안전 = 소비자를 라이브 저장소로 정렬)
- 두 크론을 `apartment.db.user_sync(trader_id, payload)` 를 읽도록 변경(백업·py_compile·배포). 라이브 동기화 경로는 건드리지 않음(실계정 데이터 보존).
- **검증(--dry)**: `weekly` → 대상 4명·발송 1명(A: 판단 102건·총자산 −0.18억), `tax` → 대상 4명·발송 3명(A·B·카카오 절세 안내). **이전 0명 → 실발송 대상 생김.**

### 동기화 실패 화면 노출(프론트, 커밋 6e64887)
- `syncManager.pushLocal` 이 `catch{}` 로 실패를 삼키고 `r.ok` 도 안 보던 것 수정 — HTTP 오류·`{ok:false}` 까지 실패로 잡아 `getPushError()`/`SYNC_PUSH_EVENT` 공개.
- `components/SyncStatus.js`: 실패 시에만 "입력이 아직 동기화되지 않았어요 — 이 기기에만 저장·리포트 미반영" 배너. 오늘·자산 화면에 마운트. 정상이면 렌더 안 함.

### ⚠️ 후속(권장, 이번엔 건드리지 않음)
- **중복 라우트 정리**: `/api/v2/user-state` 가 re_spot_endpoints(라이브)·account_api(죽음) 둘에 있음 → 등록 순서만 바뀌어도 깨지는 지뢰. 설계 의도는 accounts.db 분리였으나 실사용은 apartment.db.user_sync. 데이터 이관 후 단일화 필요(실계정 3명 영향이라 신중히).
- `apartment.db.user_sync` 에 잔여 테스트행 `TESTPROBE`(18B, 판단 0건이라 무해) 1건 — 내가 만든 것 아니라 남겨둠.

# S22-2 결과 — 판단 원장 통합

작업일 2026-09-02 · Claude Code

## 개념 정의 (먼저)

두 원장은 **서로 다른 사건**을 기록한다. 합치지 않는다(마이그레이션은 위험 대비 이득 없음). 읽는 쪽만 통일한다.

| source | 원장(localStorage) | 기록 사건 | take(실행) | pass(관망/거부) |
|---|---|---|---|---|
| `recommend` | `lib/verdictLedger.js` (`onehub_ai_vs_me`) | 추천 카드에 대한 응답 | 샀어요 | 관망 |
| `duel` | `lib/portfolioDuel.js` (`onehub_duel_decisions`) | 대결 카드의 매수/매도 제안 수용/거부 | 수용(accepted) | 거부(rejected) |

**성적표가 세는 단위 = "AI 제안에 대한 내 응답" 1건.** `source` 로만 구분한다. 그래서 `내 판단 총계 = recommend.total + duel.total`.

실측 불일치의 정체:
- `/api/pwa/game-state?trader=A` 의 120건 = **recommend 원장만** (서버로 동기화된 `onehub_ai_vs_me`).
- 대결 카드 "판단 기록 보기 16건" = **duel 원장만**.
- 둘은 다른 부분집합인데 같은 "판단"이라는 이름을 써서 어긋나 보였다.

## 작업

1. **집계 함수를 한 곳에** — `lib/verdictStats.js`(신규) `getVerdictStats(trader)`:
   - `recommend`: `verdictLedger.getLedger` + `computeShowdown`(3거래일 채점).
   - `duel`: `portfolioDuel.getDecisions` + `getDecisionAnalysis`(단기→중기 채점).
   - 반환 `{ total, take, pass, scored, passRate, bySource:{recommend, duel} }`.
   - **화면의 '판단 건수'는 이 함수에서만 나온다.**
2. **화면 건수 통일** — `components/PortfolioDuelCard.js`:
   - 성적표 상단에 **"내 판단 {vs.total}건 · 추천 M · 대결 K"**(getVerdictStats) 한 줄 추가 — game-state(recommend)와 대결 원장을 한 자리에서 화해.
   - 기존 대결 전용 수치는 **"대결 판단"** 으로 명시(수용/거부·채점·성적은 대결 원장 기준임을 분명히). 토글도 "대결 판단 기록 보기".
3. **원장은 합치지 않음** — 저장 스키마·마이그레이션 무변경. 읽는 쪽만 통일.

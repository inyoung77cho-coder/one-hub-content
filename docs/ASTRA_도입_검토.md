# Astra 도입 검토 — 무엇이 맞고 무엇이 틀렸나

> 작성 2026-09-25 · 대상: ChatGPT가 제안한 「ONE-HUB × GPT-6 Astra × Claude Code 운영체계」
> 결론 먼저: **Astra는 실재하고 쓸 만합니다. 다만 제안된 도입 방식은 ONE-HUB 현실과 어긋납니다.**

---

## 0. 사실 확인 — ChatGPT의 정정이 오히려 틀렸습니다

ChatGPT가 마지막에 *"GPT-6 Astra를 공식 제품으로 확정할 근거가 없다"* 며 스스로 철회했는데, **그 철회가 잘못입니다.**

```
GPT-6 Astra   2026-09-03~04 공개
포함 요금제    Plus · Pro · Business · Enterprise  (Free 제외)
사용처        Codex, 그리고 Chat·Work·Codex를 합친 새 데스크톱 앱
사용량        기존 구독 한도 안에서 소모, 추가 크레딧 구매 가능
```

ChatGPT의 지식 기준일이 출시보다 앞서 있어서 자기가 맞게 말해놓고 되물린 것으로 보입니다. **설치와 결제를 미룰 이유는 없습니다.**

## 1. 그런데 제안된 계획에 구조적 문제가 셋 있습니다

### ① "AS-IS 분석부터"가 이미 되어 있습니다

제안서는 *"먼저 전체 Repository를 분석해 AS-IS Architecture를 만들라"* 로 시작합니다. 그런데 저장소에는 이미 이런 것들이 있습니다.

| 이미 있는 것 | 내용 |
|---|---|
| `CLAUDE.md` | 아키텍처 · 인프라 좌표 · 데이터 저장 규칙 · 인증 · 금지사항 |
| `docs/` **112개 문서** | 작업지시서 15개 + 결과 문서 + 감사 문서 |
| `docs/S**_결과.md` | S22~S36 각 항목의 한 것 / 안 한 것 / 검증 결과 |
| `lib/generated/weeklyManifest.json` | 결과 문서 68건 · 작업지시서 13건 색인 |

**Astra에게 처음부터 분석시키면 이미 있는 것을 다시 만들고, 둘이 어긋납니다.** 그리고 어긋난 문서 두 벌은 없느니만 못합니다.

### ② 저장소에 백엔드가 없습니다 ★가장 중요

`one-hub-content`는 **프론트엔드(Next.js·Vercel)만** 있습니다. 실제 엔진은 전부 Lightsail에 있고 **git을 쓰지 않습니다.**

```
저장소에 있음        PWA · pages/api 프록시 · 카카오 인증 · lib/*
저장소에 없음  ★     auto_trade(매매봇)      :5001 engine_status_api
                     :5002 realestate FastAPI :5003 ETF
                     :5005 english            ca-bot
                     trading.db · apartment.db · accounts.db
```

`CLAUDE.md`에도 적혀 있습니다 — *"백엔드(Lightsail)는 파일 scp → systemctl restart (git 아님)"*.

그러니 **GitHub 읽기 연결만으로는 시스템의 절반만 봅니다.** 제안서가 요구한 "Stock Engine 구조 / Real Estate Engine 구조 / Database 및 Data Model" 은 저장소에서 확인이 **불가능**합니다. Astra는 그 항목들을 전부 `UNKNOWN`으로 돌려줄 것이고, 그건 이미 우리가 아는 사실입니다.

### ③ 제안된 문서 8개는 이중화를 만듭니다

`ONEHUB_MASTER_SPEC.md` `ARCHITECTURE.md` `DATA_MODEL.md` `AI_DECISION_RULES.md` `ASTRA.md` `ADR.md` … 대부분 `CLAUDE.md`와 `docs/`에 이미 흩어져 있습니다.

**새로 만들지 마십시오.** 대신 `ASTRA.md` **한 개만** 만들되, 내용을 새로 쓰지 말고 **기존 문서를 가리키게** 하십시오.

## 2. 비용 — 솔직하게

제안서는 월 $100 → $200 → 도구 교체를 검토합니다. 그 전에 짚어야 할 게 있습니다.

**지금 병목은 코드 생산 속도가 아닙니다.**

```
S22 ~ S36      스프린트 15개 완료
docs/          문서 112개
영상            0편
가입자          0명
```

앱은 충분히 만들어졌습니다. **쓰는 사람이 없을 뿐입니다.** 개발 AI를 하나 더 붙여도 이 병목은 안 풀립니다.

월 $200를 쓰기 전에 **U1 한 편을 찍고 지인 5명에게 보내는 것**이 먼저입니다. 그게 안 된 상태에서 개발 도구를 늘리면, 더 빨리 만들어지는 것을 여전히 아무도 안 씁니다.

## 3. 그럼에도 Astra가 값어치 하는 한 지점 — 독립 검수

같은 모델이 쓰고 같은 모델이 검토하면 **같은 맹점을 공유합니다.** 이 프로젝트에서 실제로 그랬습니다.

| 제가 낸 결함 | 어떻게 드러났나 |
|---|---|
| S23 지시서에 *"ETF는 종목코드가 없다"* 고 잘못 써서 **ETF 사용자를 통째로 판단 대상에서 제외** | 페르소나 시뮬레이션에서 뒤늦게 발견 → S30-4에서 수정 |
| S24에서 **배지와 lazy load를 같은 배치**에 넣어 첫 진입 시 배지가 항상 0 | 제가 설계 결함으로 뒤늦게 인정 |
| S32에서 **런타임에 docs를 읽으라**고 지시 (Vercel에서 불안정) | Claude Code가 빌드타임 매니페스트로 바꿔 잡음 |
| S36 원인을 **네 가지 후보**로만 좁히고 확정 못 함 | 계측을 넣어 나중에 확인하기로 |

**제가 스스로 못 잡은 것들입니다.** 독립 검수는 실제로 값이 있습니다.

다만 **그 값이 월 $100인지는 검증해야 합니다.** Plus($20)로 두세 건 시켜보고 판단하십시오.

## 4. 첫 작업은 "전체 분석"이 아니라 좁은 검수 한 건

제안서의 첫 지시문은 항목이 스무 개가 넘습니다. **그런 지시는 길고 그럴듯한 보고서를 만들지만 검증이 안 됩니다.**

대신 **이미 답을 아는 문제**를 시켜서 Astra의 실력을 재십시오.

### Astra 첫 작업지시서 (그대로 복사)

```
너는 ONE-HUB의 독립 코드 검수자다. 코드를 수정하지 마라.

먼저 저장소의 CLAUDE.md 를 읽어라. 아키텍처·인프라·금지사항이 거기 있다.
그다음 docs/S35_작업지시서.md 와 docs/S35_결과.md 를 읽어라.

★ 중요한 전제
이 저장소는 프론트엔드(Next.js/Vercel)만 있다.
백엔드 엔진(:5001 :5002 :5003 :5005, auto_trade, SQLite DB들)은
Lightsail에 있고 git을 쓰지 않는다. 저장소에서 확인할 수 없는 것은
추측하지 말고 UNKNOWN 으로 표시해라.

검수 대상
S35 는 "모바일에서 글자가 화면 밖으로 나가는 문제"를 고친 스프린트다.
작업지시서가 요구한 것과 결과 문서가 주장하는 것을 1:1로 대조하고,
실제 코드가 그 주장을 뒷받침하는지 확인해라.

특히 다음을 확인해라.
1. pages/pwa/today.js 의 반올림 수정이 실제로 들어갔는가
2. white-space:nowrap 을 쓰는 곳에 min-width:0 과 overflow 처리가
   같이 들어갔는가. 빠진 곳이 남아 있는가
3. 공용 클래스(u-shrink / u-1line / u-wrap)가 만들어지고 실제로
   쓰이는가, 아니면 선언만 되어 있는가
4. 개발 모드 감지기가 프로덕션 번들에 들어갈 위험이 없는가
5. 전역 overflow-x 가드가 실제 수정 없이 증상만 덮고 있지는 않은가
6. 결과 문서가 "했다"고 적었는데 코드에 근거가 없는 항목이 있는가

결과 형식
- CONFIRMED / INFERRED / UNKNOWN 을 항목마다 표시
- Critical / Major / Minor 로 구분
- 마지막에 PASS · CHANGES_REQUIRED · INSUFFICIENT_EVIDENCE 중 하나

코드를 수정하지 말고, DB나 거래 기능을 건드리지 말고,
새 프레임워크를 제안하지 마라.
```

### 왜 S35인가

제가 **프로덕션에서 직접 측정한 스프린트**입니다. 10개 화면을 360px에서 재서 16곳을 찾았고, 그 숫자가 지시서에 들어 있습니다. **Astra가 뭘 찾아내고 뭘 놓치는지 제가 대조할 수 있습니다.**

전체 아키텍처 분석은 그럴듯해 보여도 맞는지 틀린지 판정할 방법이 없습니다.

## 5. 비교 기준 — 미리 정해두십시오

두세 건 시켜본 뒤 이 표로 판단하십시오. **나중에 정하면 "좋은 것 같다"로 끝납니다.**

| 항목 | 무엇을 보나 |
|---|---|
| **새 결함을 찾았나** | 제가 못 본 것을 하나라도 찾았으면 값이 있습니다 |
| **거짓 지적 비율** | 코드에 없는 문제를 지어냈으면 감점. 이게 가장 위험합니다 |
| **UNKNOWN 을 제대로 쓰나** | 백엔드를 못 보면서 본 척하면 신뢰할 수 없습니다 |
| **기존 규칙을 지키나** | `next build --webpack`, CRLF, 매매봇 제외를 알고 있나 |
| **범위를 지키나** | 시키지 않은 대규모 리팩터링을 제안하면 감점 |

**세 건 중 두 건에서 새 결함을 찾으면 유료 전환을 검토하십시오.** 아니면 Plus로 충분합니다.

## 6. `ASTRA.md` — 새로 쓰지 말고 가리키게

저장소 루트에 이것만 두십시오. **내용을 복제하면 두 문서가 어긋납니다.**

```markdown
# ASTRA.md — ChatGPT/Astra 작업 규칙

## 먼저 읽을 것
1. CLAUDE.md          아키텍처·인프라·금지사항 (이것이 정본)
2. docs/S**_작업지시서.md   해당 스프린트의 요구사항
3. docs/S**_결과.md        그 결과 주장

## 이 저장소의 범위 ★
프론트엔드(Next.js/Vercel)만 있다.
백엔드 엔진(:5001 :5002 :5003 :5005, auto_trade)과 SQLite DB는
Lightsail에 있고 git을 쓰지 않는다.
저장소에서 확인 불가능한 것은 UNKNOWN 으로 표시한다.

## 역할
Astra = 검수와 설계. 코드를 직접 수정하지 않는다.
Claude Code = 구현.
최종 승인 = 사용자.

## 절대 금지
- CLAUDE.md 의 금지사항을 어기는 제안
  (특히 package.json 의 build 스크립트 변경 — Turbopack 프로덕션 빌드는 PWA를 깨뜨린다)
- 매매봇(onehub, onehub-b) 관련 자동화 제안
- 확인하지 않은 구조를 사실처럼 서술
- 대규모 리팩터링·프레임워크 교체 제안
```

## 1. UptimeRobot 모니터 설정 (10분)

`pages/api/health/index.js`는 **처음부터 이 방식을 전제로** 쓰였다(주석: "UptimeRobot 등 외부 모니터가 이 URL 하나로 웹앱+백엔드 생존을 확인한다"). 그런데 **연결이 안 되어 있었다** — 그래서 2026-09-09 사고 때 밖에서 세 축이 안 닿는 걸 아무도 못 봤다. 아래를 실제로 연결한다.

```
UptimeRobot 모니터 설정
  URL      https://app.one-hub.kr/api/health
  Type     Keyword
  Keyword  "ok":true      ← 이 문자열이 없으면 다운 판정
  Interval 5분
  알림     텔레그램
```

- **왜 Keyword인가**: `/api/health`는 핵심(주식 엔진) 다운 시 HTTP 503, 그 외 축 다운 시 200 + `"ok":false`(degraded)를 준다. HTTP 코드만 보면 degraded(200)를 놓친다. **`"ok":true` 문자열 유무**로 잡아야 어떤 축이 죽어도 알림이 온다.
- 응답에는 이제 **services 4개**(engine·realestate·etf·news)가 들어간다(S33-4). news가 죽어도 `ok:false`가 되어 잡힌다.
- 텔레그램 알림 연동은 UptimeRobot의 My Settings → Alert Contacts → Telegram.

### 확인
```
curl -s https://app.one-hub.kr/api/health
→ services 4개, 정상이면 "ok":true
```
사람이 읽는 화면은 **https://app.one-hub.kr/status** (로그인 없이 열림).

- HC(서버): **원인 = OOM 확정**(2026-09-09 17:55 KST, realestate uvicorn 1.68GB / RAM 1910MB). **스왑 2GB 이미 존재**라 스왑 추가는 불필요. 적용 방법은 아래 **5절 하드닝 스크립트** 참조.

## 5. 서버 하드닝 스크립트 (SSH 22 막혔을 때 · 사람이 서버에서 실행)

원격 SSH 가 막혀 있으면 원격 적용 대신 **스크립트를 서버에 올려 사람이 실행**한다. 조사 → 승인 → 적용 순서를 스크립트가 강제한다.

```
파일: scripts/s33_server_hardening.sh  (저장소에 있음)

# 1) 서버로 올린다 (SSH 되면 scp, 막혔으면 Lightsail 브라우저 콘솔에 붙여넣기)
scp scripts/s33_server_hardening.sh ubuntu@54.180.54.132:/home/ubuntu/
chmod +x /home/ubuntu/s33_server_hardening.sh

# 2) 조사만 (읽기 전용 — 아무것도 안 바꿈). 결과를 눈으로 확인.
./s33_server_hardening.sh

# 3) 확인 후 적용 (S33-8 감시봇 + S33-9 systemd + S33-10 조건부 스왑)
./s33_server_hardening.sh --apply

# 4) 검증 (etf 강제 종료 → 10초 내 자동 복구)
./s33_server_hardening.sh --test
```

- **멱등**: 재실행해도 안전(이미 반영됐으면 건너뜀). 파일 수정 전 `.bak` 자동 백업.
- ★**매매봇 `onehub`·`onehub-b` 는 절대 건드리지 않는다**(주문 중복 위험).
- 무암호 sudo 가 필요하다(없으면 `sudo -v` 후 실행).
- `--apply` 가 하는 것:
  - S33-8: `G7_healthcheck.sh` 를 KST·복구알림🟢·상태 전이일 때만 발송·원인 로그 첨부 버전으로 교체(원본 백업).
  - S33-9: `onehub-api·onehub-realestate·onehub-news` = `Restart=always`+`RestartSec=5`, `onehub-etf·ca-bot` = `RestartSec=5` (drop-in, 원본 유닛 미변경), `daemon-reload`.
  - S33-10: 스왑 있으면 건너뜀 / OOM 흔적 있고 스왑 없을 때만 2G 생성(`/etc/fstab` 백업 후).

## 0. AI 페이지 진단

### 지금 무엇인가 (코드 실측)

`/pwa?tab=report` 가 "AI" 페이지입니다. `RotatingPageTitle` 의 **"분석변경"** 버튼으로 세 화면이 순환합니다.

| 섹션 | 내용 |
|---|---|
| `vs` — AI vs 나 대결 | `PortfolioDuelCard` |
| `verify` — AI 자기검증 | 오늘 매수/차단 건수, 어제 대비 판단 변화 목록 |
| `archive` — AI 리포트 | 오늘 요약 KPI, **AI 성적표·이번 주**(승률·차단적중률·손익비·MDD), 리포트 링크 목록 |

### 문제 넷

**① 성적표가 두 개인데 이름이 거의 같습니다.**
- `🏆 AI 성적표 · 이번 주` — index.js 아카이브 섹션. **AI의** 성적입니다.
- `🧾 내 판단 성적표` — `/pwa/record`(S22-5). **나의** 성적입니다. 그런데 이 페이지에서는 **링크 목록의 한 줄**(index.js:2828)로 밀려 있습니다.

페이지 이름이 "AI vs 나 대결"인데 정작 **나의 성적은 링크 한 줄**이고, AI의 성적은 카드 한 장을 차지합니다. 주어가 뒤바뀌어 있습니다.

**② 한 파일이 두 페이지 행세를 합니다.**
```
index.js:3310  <BottomNav active={tab === 'report' ? 'ai' : 'assets'} />
```
`index.js` 하나에 **여섯 탭**(dashboard · recommend · analyze · portfolio · report · profile)이 들어 있고, `tab` 값에 따라 하단 탭 강조가 **AI ↔ 자산** 사이를 오갑니다. AI 화면에서 추천 종목을 누르면 같은 페이지 안에서 tab이 바뀌면서 하단 강조가 '자산'으로 넘어갑니다. **사용자는 자기가 어디 있는지 알 수 없습니다.**

**③ 회전 버튼이 여기만 남았습니다.**
오늘 페이지는 S23 T-3에서 세그먼트 탭으로 바꿨는데 AI는 `buttonLabel="분석변경"` 그대로입니다. 세 화면이 여전히 숨어 있고, S24-5의 스와이프도 **`today.js` 에만** 붙었습니다(확인 완료: `useSwipeTabs` 사용처는 today.js 한 곳).

**④ 목적이 없습니다.**
전략 문서의 페이지 목적표에 AI 페이지가 없습니다. 지금의 암묵적 목적은 **"AI가 오늘 무엇을 했는지 보여주기"** 인데, 사용자가 처음 정의한 대로 그건 *"운영자 위주의 분석"* 입니다. 사용자 입장의 목적이 아닙니다.

### 목적 재설정

> **AI 페이지 = 심판석.**
> 나와 AI의 판단을 **같은 자로 재서**, 다음 판단을 누구 기준으로 내릴지 알려주는 곳.
> **주기는 주간.**

이 설정이 두 가지를 동시에 해결합니다.

**빈 주기를 정확히 채웁니다.**

| 페이지 | 목적 | 주기 |
|---|---|---|
| 오늘 | 매일의 판단 관문 | 일간 |
| 주식 | 내 판단이 AI보다 나은지 | 일간 |
| ETF | 배분 이탈과 절세 | 월간·분기 |
| 부동산 | 상급지로 가는 문 | 분기·연간 |
| 종합자산 | 관제탑 | 상시 |
| **AI** | **심판석 — 다음엔 누구 말을 들을 것인가** | **주간** ← 비어 있던 자리 |
| 듣는 경제 | 경제와 외국어를 손 안 쓰고 | 일간(듣기) |

**사업화의 축과 맞습니다.** S22-5(성적표) · S22-6(월요일 주간 리포트) · S24-2(지난주 기간 창)가 전부 여기로 착지합니다. 주간 리포트 푸시의 도착지가 지금은 `/pwa/record` 인데, **AI 페이지가 그 자리를 가져가야** 페이지에 주기가 생깁니다.

# VA — AI 페이지를 심판석으로

## S25-1 · 정체성 분리

### 할 일

1. **하단 탭 강조를 고정** — `BottomNav active={tab === 'report' ? 'ai' : 'assets'}` 는 사용자를 잃게 만듭니다.
   - `tab` 이 `report` 면 `ai`, **그 외 전부 `assets`** 인 현재 규칙 대신, **어디서 왔는지**가 아니라 **지금 무엇을 보는지**로 정하십시오.
   - 가장 단순한 해법: AI 섹션에서 종목 분석·추천으로 넘어갈 때 **같은 파일 안에서 `tab` 을 바꾸지 말고 `/pwa/assets` 또는 해당 페이지로 실제 이동**시키십시오. 파일 분리는 이 스프린트 범위 밖이지만, **이동 경로는 지금 바로잡을 수 있습니다.**
   - 그게 어려운 경로가 있으면 결과 문서에 그 경로를 적고 남겨두십시오. 억지로 고치다 회귀를 내지 마십시오.
2. **회전 버튼 → 3칸 세그먼트 탭** — `today.js` 가 S23 T-3에서 만든 것과 **같은 모양**으로. `RotatingPageTitle` 컴포넌트는 다른 페이지도 쓰므로 **고치지 말고** AI 페이지에서만 교체하십시오.
   - 라벨: `나 vs AI` · `AI 자기검증` · `기록`
   - `?sec=` 딥링크는 **그대로 유지**(기존 진입 경로가 있습니다). `trustSec` ↔ `router.query.sec` 동기화는 이미 `controlledIndex` 로 되어 있으니 그 관계를 세그먼트로 옮기기만 하면 됩니다.
3. **스와이프 추가** — `useSwipeTabs`(S24-5) 를 그대로 씁니다. 새로 만들지 마십시오. 함정은 S24-5 지시서와 동일(좌측 가장자리 24px 제외, 가로 스크롤 영역 제외, `replace` 사용).

### 합격선

- AI 화면 어디에서도 하단 탭 강조가 예고 없이 '자산'으로 넘어가지 않는다.
- 세 화면이 세그먼트로 한눈에 보이고 좌우 스와이프로 넘어간다.
- `?sec=verify` 딥링크가 종전대로 동작한다.

## S25-2 · 두 성적표를 하나의 심판석으로

### 문제

같은 페이지에 **AI의 성적**과 **나의 성적**이 따로 있고, 이름이 거의 같고, 나의 것이 링크 한 줄로 밀려 있습니다.

### 할 일

1. **첫 화면(`vs` 섹션) 최상단을 판정 카드로.** 아래 값을 **한 표**에 나란히 놓으십시오.

   | | 나 | AI |
   |---|---|---|
   | 판단 건수 | 12건 | 12건 |
   | 승률 | 58% | 50% |
   | 평균 수익 | +1.8% | +0.9% |
   | 관망 비율 | 33% | 0% |

   - 숫자는 **`getVerdictScorecard`(S22-5) 하나에서만** 가져오십시오. `myRet`·`aiRet`·`winRate`·`passRate` 가 이미 있습니다. **새 집계를 만들면 세 번째 성적표가 생깁니다.**
   - 기간은 **지난주**(S24-2가 만든 기간 창)를 기본으로 하고, `주간 / 누적` 토글을 두십시오. 어느 기간인지 항상 라벨에 씁니다.
2. **판정 한 줄** — 표 아래에 결론을 씁니다.
   - `지난주는 당신이 나았습니다 · 관망 4건이 손실을 피했습니다`
   - `지난주는 AI가 나았습니다 · 당신이 관망한 3종목이 평균 +4.1% 올랐습니다`
   - **소표본 정직성** — `samplePolicy`(S22-5)의 `declareWinner` 가 false면 승패를 단정하지 말고 `아직 판단하기 이릅니다 · 채점 8건 / 30건` 으로만 쓰십시오.
3. **AI 성적표 카드는 두 번째 섹션으로 이동**하고 이름을 **`AI 엔진 성적 · 참고`** 로 바꾸십시오. 차단적중률·손익비·MDD는 운영 지표라 첫 화면의 주인공이 아닙니다.
4. **`/pwa/record` 와의 관계를 정하십시오.** 둘 중 하나:
   - (권장) `/pwa/record` 의 내용을 AI 페이지 `vs` 섹션으로 **흡수**하고, `/pwa/record` 는 리다이렉트로 남깁니다. 성적표가 두 곳에 있을 이유가 없습니다.
   - 또는 `/pwa/record` 를 유지하되 AI 페이지에서 **"자세히"** 로만 연결하고, **같은 숫자**임을 보장합니다.
   - 어느 쪽이든 **주간 리포트 푸시(S22-6)의 `action_url` 을 새 도착지로 맞추십시오.**

### 합격선

- `vs` 섹션 첫 화면에 나와 AI의 같은 지표가 나란히 있다.
- 화면의 모든 성적 숫자가 `getVerdictScorecard` 한 곳에서 나온다.
- 채점 30건 미만에서 승패를 단정하지 않는다.
- 주간 리포트 푸시를 누르면 이 화면으로 온다.

# VB — 조작감 일관화

## S25-4 · 자산 페이지 스와이프 ★함정 있음

### 먼저 — 지금 구조를 확인하십시오 (중요)

```
assets.js:66   const [view, setView] = useState(0); // 0=주식 1=ETF 2=부동산
assets.js:492  // [사용자 지시] ETF·부동산은 이제 탭 선택 즉시 해당 페이지로 이동
```

**자산 페이지의 "탭"은 페이지 내 필터가 아니라 페이지 이동 트리거입니다.** 여기에 스와이프를 그대로 붙이면 **좌우로 밀 때마다 다른 페이지로 튀게 되고**, 이는 사용자가 정한 원칙 — *"페이지끼리는 클릭으로만 이동"* — 을 정면으로 위반합니다.

### 할 일

**스와이프의 대상을 바꾸십시오.** 페이지 이동이 아니라 **자산군 요약 카드**를 넘기게 합니다.

1. 자산 페이지 상단에 **자산군 요약 카드 3장**(주식 · ETF · 부동산)을 두고, 좌우 스와이프로 그 카드만 전환합니다.
   - 각 카드: 평가액 · 전일 대비 · 목표 배분 대비 이탈(`onehub_target_class`, S22-4) · 30일 스파크라인.
   - 카드 안의 **`상세 보기 →` 버튼을 눌렀을 때만** 해당 페이지로 이동합니다.
2. 스와이프는 **요약 카드 안에서만** 동작하게 범위를 제한하십시오. 페이지 전체에 걸면 아래 목록을 훑다가 페이지가 바뀝니다.
3. `useSwipeTabs` 재사용. 새로 만들지 마십시오.

### 합격선

- 자산 페이지에서 좌우로 밀면 **주식 ↔ ETF ↔ 부동산 요약 카드**가 바뀐다.
- 스와이프만으로는 **절대 다른 페이지로 이동하지 않는다.**
- 상세 페이지 진입은 클릭으로만 된다.
- 요약 카드 밖(목록 영역)에서 밀면 아무 일도 일어나지 않는다.

## S25-5 · 나머지 페이지 스와이프

### 대상 — 페이지 **내부**에 좌우 탭이 있는 곳만

| 페이지 | 탭 | 비고 |
|---|---|---|
| AI (`?tab=report`) | 나 vs AI · 자기검증 · 기록 | S25-1에서 처리 |
| 듣는 경제 (`english.js`) | 경제영어 · 일반영어 · 중국어 | S25-6에서 처리 |
| 주식 (`?tab=portfolio/recommend`) | 보유 · 추천 | 여기서 처리 |
| ETF (`etf.js`) | 보유 · 추천 등 탭이 있으면 | 확인 후 처리 |
| 부동산 (`realestate.js`) | 탭이 있으면 | 확인 후 처리 |

### 절대 하지 말 것

**하단 탭(오늘 · 자산 · 이야기 · 듣는경제 · AI) 사이 이동은 스와이프로 만들지 마십시오.** 사용자가 명시한 규칙입니다.

### 할 일

- 각 페이지에서 `useSwipeTabs` 를 **같은 방식으로** 붙입니다. 페이지마다 다르게 구현하면 조작감이 어긋납니다.
- 탭이 2개뿐인 곳(보유·추천)도 붙입니다 — 일관성이 조작감의 전부입니다.
- 스와이프 가능 영역에 **가로 스크롤 컨테이너가 있으면 그 안은 제외**(S24-5 함정 2번).

### 합격선

- 다섯 페이지에서 좌우 스와이프가 **똑같이** 동작한다.
- 하단 탭 사이는 스와이프로 이동되지 않는다.
- 표·칩 행을 가로로 스크롤해도 탭이 넘어가지 않는다.

# VC — 현장경제 재편

## S25-6 · 페이지 이름과 구조

### 이름

지금 이름 **"현장경제"** 는 이 페이지가 무엇을 하는 곳인지 말해주지 않습니다. 사용자가 정의한 목적은 *"실시간 주요 뉴스나 정보를 습득하고 **외국어로 직접적으로 이해**하여 경제 지식과 외국어 활용을 **동시에** 증가"* 입니다. 이름이 그 둘을 다 담아야 합니다.

| 후보 | 장점 | 단점 |
|---|---|---|
| **듣는 경제** ← 권장 | 4글자(하단 탭에 맞음) · 무엇을 하는지 즉시 · 듣기가 본체임을 선언 | '읽기'도 있는데 듣기만 강조 |
| 경제 리스닝 | 학습 성격이 분명 | 5글자 · 외래어 |
| 외신 경제 | 원문 뉴스 성격 | 학습 측면이 안 드러남 |
| 글로벌 데스크 | 감각적 | 무슨 페이지인지 모름 |

**"듣는 경제"** 를 권합니다. 부제는 `경제영어 · 일반영어 · 중국어`.

**이름을 바꿀 곳**: `components/BottomNav.js` 라벨, 페이지 `<h1>`, `<title>`, 각종 링크 문구, 공지·리포트에 이름이 박혀 있으면 그것까지. **URL(`/pwa/english`)은 바꾸지 마십시오** — 외부 링크·북마크가 깨집니다.

### 구조

현재 이미 대메뉴가 `en`(경제영어) · `zh`(중국어) · `gen`(일반영어)이고 하위 트랙이 `news` · `video` · `idiom` 입니다. **분류는 이미 맞습니다.** 할 일은 셋입니다.

1. **순서를 사용자 요구대로** — `경제영어 · 일반영어 · 중국어`. 지금 `gen` 이 뒤에 있으면 앞으로 옮기십시오.
2. **3칸 세그먼트 + 스와이프** — 다른 페이지와 같은 모양, `useSwipeTabs` 재사용.
3. **하위 트랙(news·video·idiom)은 스와이프 대상이 아닙니다** — 2단 스와이프는 손가락이 헷갈립니다. 하위는 칩으로 두십시오.

### 합격선

- 하단 탭과 페이지 제목이 새 이름으로 바뀌었고 URL은 그대로다.
- 세 언어가 세그먼트로 보이고 좌우 스와이프로 넘어간다.
- 하위 트랙은 스와이프로 바뀌지 않는다.

## S25-7 · 내 단어장 + 리마인드

### 사용자 요구

> 예전에 공부했거나 중요한 단어나 표현은 언제든지 리마인드 되도록 별도 메모장 지원

### 현재 상태 (확인 완료)

`english.js` 의 레슨은 이미 이런 구조입니다.
```
lesson.expressions[] : { expr, meaning_ko }
lesson.words[]       : { word, ... }
```
그리고 각 항목 옆에 **`SpeakButton({text, lang})` 이 이미 붙어 있습니다.** 저장할 대상과 재생 수단이 다 있습니다.

### 할 일

1. **저장은 별 하나** — 각 표현·단어 옆에 `☆` 를 답니다. 누르면 `★`. 그게 전부입니다. 메모 입력을 강요하지 마십시오(입력이 필요하면 아무도 안 씁니다).
2. **`lib/vocabNote.js`(신규)** — 키 `onehub_vocab_A`/`_B`, **`SYNC_KEYS` 등록**(폰에서 담고 PC에서 복습해야 합니다).
   ```
   { id, lang, text, meaning, source, savedAt, reviewedAt[], box }
   ```
   - `id` 는 `lang + text` 해시로. 같은 표현을 두 번 담아도 한 건입니다.
3. **내 단어장 화면** — 듣는 경제 페이지 안의 네 번째 세그먼트가 아니라 **상단 링크**로 두십시오(`⭐ 내 단어장 42`). 언어 세그먼트는 셋으로 유지합니다.
   - 언어별 필터, 최근순/오래된순, 전체 듣기(`AudioPlaylist` 재사용 — S24-10에서 만든 것).
4. **리마인드는 가볍게** — 간격 반복을 정식으로 구현하지 마십시오. **4단계면 충분합니다.**
   ```
   box 1 → 1일 뒤 · box 2 → 3일 뒤 · box 3 → 7일 뒤 · box 4 → 30일 뒤
   기억남 → box +1 · 가물 → box 1 로
   ```
   - 판정 버튼은 **두 개**(`기억남` / `가물`). 5단계 평가는 아무도 안 누릅니다.
5. **오늘 페이지에 연결** — `todayCadence`(S23 T-6)에 훅 하나 추가: `오늘 복습할 표현 5개`. **복습할 것이 없는 날엔 훅을 반환하지 않습니다.**
   - 이게 S24에서 지적한 **"조용한 날엔 앱이 할 말이 없다"** 를 메우는 좋은 재료입니다. 주식 조치가 없는 날에도 복습할 단어는 있습니다.

### 함정

- **알림으로 재촉하지 마십시오.** 복습은 오늘 화면에 조용히 뜨는 것으로 충분합니다. 푸시까지 붙이면 학습 앱의 잔소리가 됩니다.
- 저장 개수 배지를 크게 띄우지 마십시오(S24-12 토큰과 같은 원칙).

### 합격선

- 표현·단어를 별 하나로 담고 다른 기기에서 보인다.
- 단어장에서 전체 듣기가 된다.
- 복습 대상이 있는 날에만 오늘 화면에 훅이 뜬다.
- 복습 판정 버튼이 두 개다.

# VD — ETF 심화 ★오판 위험이 가장 큼

## S25-8 · ETF 추세와 테마

### 사용자 요구

> ETF 추세(일별 변동) 분석, 테마별 정보 분석 및 향후 트렌드 분석

### 먼저 — 지켜야 할 선

**"향후 트렌드 분석"을 예측으로 만들지 마십시오.** 이 앱의 가장 큰 자산은 정직성이고, 예측은 그것과 정면으로 충돌합니다. 그리고 투자자문 규제 문제도 있습니다.

요구를 이렇게 **재정의**하십시오.

> 예측을 파는 게 아니라 **관찰을 파는 것**입니다.
> "앞으로 오를 것이다"가 아니라 **"최근 N주 이 흐름이 이어지면 내 배분은 목표에서 이만큼 더 벌어진다"** 입니다.

전자는 맞히면 우연이고 틀리면 신뢰를 잃습니다. 후자는 **산수**라 항상 맞습니다.

### 현재 상태 (확인 완료)

- 일별 시세 이력이 **없습니다.** `pages/api/etf/quote.js` 는 stooq CSV(`sd2t2ohlcv`)로 **현재가 한 점**만 받습니다.
- `lib/etfClassify.json` 은 `{"SMH":{"r":"해외","a":"미국"}}` 형태로 **지역·권역만** 있습니다. **테마(반도체·AI·배당·채권) 분류는 존재하지 않습니다.** ETF 페이지의 "테마 도넛"은 사실상 지역 분포입니다.

### 할 일

1. **일별 이력 확보** — stooq 는 일별 CSV 엔드포인트를 제공합니다(`/q/d/l/?s=<sym>&i=d`). 이걸 쓰되:
   - **보유 종목만.** 전 종목을 긁지 마십시오.
   - 서버에서 하루 1회 받아 캐시하십시오. 클라가 매번 부르면 안 됩니다.
   - 실패하면 **추세를 계산하지 말고 "이력 수집 중"** 으로 두십시오. 없는 데이터로 추세를 그리지 마십시오.
2. **추세 표시** — 보유 ETF마다 **30일 스파크라인 + 4주 변화율**. `components/shared/Sparkline.js`(S23 T-4) 재사용.
3. **테마 분류** — **보유 종목에 한해서만** 테마를 붙이십시오. 수백 개를 분류할 수 없고, 틀린 분류는 없느니만 못합니다.
   - `lib/etfClassify.json` 에 `t`(theme) 필드를 더하고, 사용자가 실제로 보유한 티커부터 채웁니다.
   - 분류가 없는 종목은 `미분류` 로 **정직하게** 표시하고 도넛에서 별도 조각으로 두십시오. 임의로 끼워 넣지 마십시오.
4. **테마별 4주 변화** — 테마 단위로 묶어 `반도체 +6.2% · 배당 −1.1% · 채권 +0.3%` 형태. 분류된 종목이 2개 미만인 테마는 표시하지 않습니다.

### 합격선

- 보유 ETF마다 30일 곡선과 4주 변화율이 보인다.
- 이력이 없는 종목은 "수집 중"으로 표시되고 가짜 선이 그려지지 않는다.
- 미분류 종목이 임의 테마에 들어가지 않는다.
- **화면 어디에도 "오를 것이다" 류의 예측 문장이 없다.**

## S25-9 · 비중 조정 제안

### 사용자 요구

> 향후 트렌드 분석 후 비중 조정 방안까지 제시

### 할 일

1. **기존 것을 쓰십시오.** 목표 배분(`onehub_target_class`, S22-4)과 추천 엔진(`lib/etfRecommend.js`)이 이미 있습니다. **새 추천 로직을 만들지 마십시오.**
2. **제안의 형식** — 세 줄이면 충분합니다.
   ```
   지금        해외 68% · 국내 24% · 채권 8%
   목표        해외 55% · 국내 35% · 채권 10%
   조정        해외 −13%p(약 1,380만원) → 국내 +11%p · 채권 +2%p
   ```
   - **금액까지 계산해 주십시오.** %p만 주면 사용자가 다시 계산해야 합니다.
   - 어느 종목을 팔지는 **말하지 마십시오.** 그건 투자권유입니다. 자산군 단위까지가 안전선입니다.
3. **추세를 근거로 연결** — S25-8의 4주 변화가 이탈의 원인인지 밝히십시오.
   `해외 비중이 4주간 +6%p 늘었습니다 — 새로 사서가 아니라 미국 ETF가 올라서입니다.`
   이게 이 기능의 진짜 값어치입니다. **가만히 있어도 배분이 움직인다**는 걸 알려주는 것.
4. **행동 강요 금지** — `지금 리밸런싱하세요` 가 아니라 `목표에서 13%p 벌어졌습니다` 입니다. 판단은 사용자가 합니다.
5. **면책** — `규칙 기반 참고 정보 · 투자자문이나 특정 종목 권유가 아닙니다`. 기존 ETF 페이지 문구와 같은 것을 쓰십시오.

### 합격선

- 목표가 설정된 사용자에게 %p와 금액이 함께 나온다.
- 목표 미설정이면 **추측하지 않고** 설정 유도만 한다.
- 개별 종목 매매를 지시하는 문장이 없다.
- 이탈의 원인(가격 변동 vs 매매)이 구분돼 표시된다.

# VE — 하루 한 클립

## S25-10 · 통합 브리핑

### 사용자 요구

> 각 페이지의 내용을 통합해서 한 CLIP으로 마지막으로 한번에 들을 수 있도록

### 현재 상태 (확인 완료)

`components/shared/AudioPlaylist.js` 가 S24-10에서 만들어졌고 시그니처는 `{ items, storageKey, title, onComplete }` 입니다. MediaSession·이어듣기·다음 편 preload 가 이미 들어 있습니다. **재생기는 다 있습니다.** 할 일은 **대본을 모으는 것**입니다.

### 할 일

1. **`lib/dailyClip.js`(신규)** — 하루치 재생목록을 만드는 순수 함수. 순서는 **짧은 것부터 긴 것**으로, 도중에 끊겨도 중요한 걸 먼저 듣게:
   ```
   ① 오늘 요약      운용자산 · 전일 대비 · 오늘 조치 (S24-9 briefingScript 재사용)
   ② 내 판단        지난주 성적 · 오늘 기록한 판단 (월요일엔 심판 결과)
   ③ 자산 변화      목표 배분 이탈 · ETF 4주 추세 (S25-9)

   ⑤ 오늘의 뉴스    한국어 요약
   ⑥ 외국어         오늘의 듣기 (S24-10 재생목록 그대로 이어붙임)
   ```
2. **대본은 화면과 같은 소스에서** — 각 항목의 문장은 이미 화면이 쓰는 값에서 만드십시오. **읽어주는 내용과 보이는 내용이 다르면 최악입니다.** 눈으로 검증할 수 없으니까요.
3. **비어 있는 항목은 건너뜁니다.** 부동산 주간이 없으면 그 트랙이 없습니다. `오늘은 5개 트랙 · 약 9분` 처럼 실제 개수를 표시하십시오.
4. **배치 위치** — 오늘 페이지 요약 카드 안에 한 줄:
   `🎧 오늘 브리핑 전체 듣기 · 6트랙 · 약 9분`
   듣는 경제 페이지 하단에도 같은 진입로를 두십시오(거기서 외국어만 듣던 사람이 전체로 넘어오게).
5. **트랙 목록을 보여주십시오.** 재생 중에 무엇을 듣고 있고 다음이 무엇인지 보이지 않으면 8분을 못 견딥니다. 각 트랙을 눌러 건너뛸 수 있게 하십시오.

### 함정

- **한꺼번에 합성하지 마십시오.** 6트랙을 동시에 TTS 돌리면 `:5005` 가 멈춥니다. S24-10에서 정한 **다음 한 편만 preload** 규칙을 그대로 지키십시오.
- **자동 재생 금지** — iOS는 사용자 제스처 없이 재생이 안 됩니다.
- 대본 해시 캐시(S24-9)를 재사용하십시오. 같은 내용을 두 번 합성하지 않게.
- 총 길이가 **10분을 넘으면 잘라내십시오.** 다 듣지 못할 분량은 안 듣느니만 못합니다.

### 합격선

- 버튼 하나로 하루치가 순서대로 재생된다.
- 재생 중 트랙 목록이 보이고 건너뛸 수 있다.

- 비어 있는 트랙이 목록에 없다.

- 각 합격선에 **"사용자가 어느 화면에서 언제 이걸 보는가"** 를 한 줄 덧붙이십시오.
- 확인 못 한 것은 `⚠️ 사용자 확인 필요` 로 남기고 통과 처리하지 마십시오.

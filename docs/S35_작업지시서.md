> 작성 2026-09-13 · 계기: "모바일에서 글자가 앱 화면 밖으로 종종 나간다. 완성도가 떨어져 보인다"

### 왜 137%를 측정했나

시스템 글자 크기를 키우면(아이폰 손쉬운 사용 · 안드로이드 글꼴 크기) rem 기반 크기가 전부 커집니다. **데스크탑 에뮬레이터로는 재현이 안 되고 실제 폰에서만 납니다.** 100%·125%에서 멀쩡하다가 137%부터 무너집니다.

**"종종 나간다"의 정체가 이것일 가능성이 큽니다.** 같은 화면인데 어떤 때는 괜찮고 어떤 때는 깨지는 게 아니라, **데이터가 길어질 때**와 **글자가 클 때** 깨집니다.

### 뿌리 원인

`white-space: nowrap` 이 저장소에 **107곳** 있습니다. 대부분 짧은 라벨이라 안전하지만, 아래 세 조건이 겹치면 반드시 새어 나옵니다.

```
① 부모 flex/grid 칸에 min-width: 0 이 없다   → 칸이 안 줄어든다
② 자신에게 overflow: hidden 이 없다          → 내용이 상자 밖으로 흐른다
③ 내용 길이가 가변이다                        → 종목명·금액·설명문
```

## 배치 EA — 지금 나는 넘침

### S35-1 · 반올림 누락 ★한 줄, 가장 급함

`pages/pwa/today.js:370`

```js
// 지금 — 반올림 없음
if (p.change_1d != null) return `당일 ${Number(p.change_1d) >= 0 ? "+" : ""}${Number(p.change_1d)}% 급변`;

// 고침
if (p.change_1d != null) {
  const d = Number(p.change_1d);
  return `당일 ${d >= 0 ? "+" : ""}${d.toFixed(1)}% 급변`;
}
```

**바로 위 두 줄(`손절선까지`·`목표가까지`)은 `toFixed(1)` 이 제대로 있습니다.** 세 줄 중 한 줄만 빠졌습니다. 그래서 S35-5(포맷 일원화)가 필요합니다.

**같은 실수 전수 확인**: `pages`·`components`·`lib` 에서 반올림 없이 숫자를 문자열에 넣는 곳.
```
검색: ${Number(...)}%   ${p.xxx}%   ${n(...)}%
제외: toFixed / Math.round / 서버가 내려준 정수 / CSS width 값
```

### S35-3 · 나머지 여섯 곳

```
.tds-reason    (today)       규칙 A + B
```

### 세 가지 규칙

```css
/* A · 칸이 줄어들 수 있게 — flex/grid 자식 전부에 */
.칸 { min-width: 0; }

/* B · nowrap 을 유지해야 하는 것(금액·퍼센트·짧은 배지) */
.글자 { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; max-width: 100%; }

/* C · 잘리면 뜻이 사라지는 것(종목명·규칙명·설명문) */
.글자 { white-space: normal; overflow-wrap: anywhere; word-break: keep-all; }
```

**B와 C를 고르는 기준**

| 내용 | 규칙 | 이유 |
|---|---|---|
| 종목명 · 단지명 · 규칙명 · 설명문 | **C (줄바꿈)** | 잘리면 뭔지 모릅니다 |
| 금액 · 퍼센트 | **B + 상자 확대** | `57.8…` 로 잘리면 안 되고 줄바꿈도 안 됩니다 |
| 짧은 배지 (`펀드`·`↑`) | **A (상자를 늘림)** | 한 글자가 잘리는 건 상자 설계가 틀린 것 |

**금액·퍼센트가 안 잘리게 하려면** 한 줄에 여러 값이 들어가는 행을 좁은 폭에서 세로로 쌓으십시오.

```css
@media (max-width: 380px) { .행 { flex-direction: column; align-items: flex-start; gap: 4px; } }
```

### S35-6 · 개발 중 자동 감지 ★재발 방지의 핵심

**할 일**

개발 모드에서만 동작하는 감지기를 `_app.js` 에 넣습니다.

```js
// process.env.NODE_ENV === "development" 일 때만
// 라우트 변경 + 1초 뒤 1회 검사 → 넘친 요소를 콘솔에 경고 + 빨간 테두리
```

- **프로덕션 번들에 들어가지 않게** 할 것 (`if (process.env.NODE_ENV !== "development") return;`)
- 넘친 요소에 `outline: 2px solid red` 를 그려 눈에 보이게
- 콘솔에 선택자·내용·넘친 px 출력

**그리고 브라우저 콘솔용 단독 스크립트**도 `scripts/overflow-check.js` 로 남기십시오. 프로덕션에서 확인할 때 붙여넣어 씁니다.

```js
(() => {
  const W = document.documentElement.clientWidth, over = [], clip = [];
  document.querySelectorAll('body *').forEach(el => {
    const r = el.getBoundingClientRect();
    if (r.width <= 0 || r.height <= 0) return;
    if (r.right - W > 1) {
      const p = el.parentElement, pr = p && p.getBoundingClientRect();
      if (!(pr && pr.right - W > 1)) over.push([el, Math.round(r.right - W) + 'px']);
    }
    if (el.scrollWidth - el.clientWidth > 1 && !el.children.length && el.textContent.trim())
      clip.push([el, el.clientWidth + '→' + el.scrollWidth]);
  });
  console.log('페이지폭', document.documentElement.scrollWidth, '/ 화면폭', W);
  console.table(over.map(([e, o]) => ({ 넘침: o, 클래스: e.className, 내용: e.textContent.trim().slice(0, 30) })));
  console.table(clip.map(([e, o]) => ({ 잘림: o, 클래스: e.className, 내용: e.textContent.trim().slice(0, 30) })));
})();
```

**큰 글씨 흉내**: `document.documentElement.style.fontSize='22px'` (되돌리기 `=''`)

### S35-7 · 전역 안전망 — ★마지막에, 보험으로만

```css
/* styles/globals.css */
html, body, #__next { max-width: 100%; overflow-x: clip; }
```

**이건 증상을 감추는 코드입니다.** 넘친 글자가 안 보이게 될 뿐 여전히 잘립니다.

**EA·EB를 다 끝낸 뒤에 넣으십시오.** 이것부터 넣고 끝내면 다음 넘침을 아무도 못 보게 되고, 같은 문제가 조용히 쌓입니다.

`overflow-x: hidden` 이 아니라 **`clip`** 입니다. `hidden` 은 스크롤 컨테이너를 만들어 `position: sticky` 헤더·하단탭을 깨뜨립니다.

## 3. 이 스프린트가 끝나면

```
새 화면을 만들 때
  → 글자 담는 칸에 u-shrink / u-1line / u-wrap 중 하나를 붙인다
  → 숫자는 lib/fmt.js 를 거친다
  → 개발 중에 넘치면 빨간 테두리가 바로 보인다
```

**16곳을 고치는 게 목적이 아닙니다.** 17번째가 안 생기게 만드는 것이 목적입니다.

## Part B — 서버 사전생성 캐시 (2026-09-01 추가·배포)

### 원가 확인
`:5002 /api/briefing`(=Vercel `/api/pwa/re/briefing` 프록시의 upstream)은 매 요청 `_load_pivot` 에서 `SELECT * FROM raw_transactions`(**632,900행**)를 pandas 로 로드 후 단지별 갭·84㎡ 회귀를 계산 → **5~12초**. 요청 시점 계산이 원인.

### 한 것 (서버 — one-hub-content 저장소 아님)
- `real_estate/api/main.py`(백업 `main.py.bak_partb_*`):
  - `briefing_cache(region PK, payload, row_count, updated)` 테이블 신설.
  - 기존 계산부를 `_compute_briefing(region)` 로 분리, `@app.get("/api/briefing")` 는 **캐시 우선**: `raw_transactions` 행수가 캐시 저장 시 행수와 같으면 즉시 반환(`cached:true`), 다르거나 없으면 **1회만 계산·저장(self-healing)** 후 반환. `refresh=1` 이면 강제 재계산.
  - 응답에 `cached`/`cache_updated` 만 추가(기존 키·형태 불변 → 프론트 무영향).
- `real_estate/scripts/briefing_batch.py`(신규): 실행 중인 `:5002` 에 전 지역 `?refresh=1` 을 호출해 캐시를 미리 데우는 워머(계산 로직 중복 없음).
- 크론: `0 21 * * 0`(일 21:00 UTC) — 주간수집(20:00)·one_score(20:30)·region_leaders(20:45) 직후. 데이터가 바뀌는 주간 주기에 맞춤.

# S36 결과 — 카카오 로그인 첫 시도 실패

> 실행 2026-09-13 · 지시서 `docs/S36_작업지시서.md` · 빌드 `next build --webpack` ✓ (Compiled successfully, exit 0)

## 요약

state 를 난수 쿠키 의존에서 **HMAC 서명 토큰**으로 바꿔, 콜백 시점에 쿠키가 유실돼도(인앱 브라우저·start 중복호출·도메인 불일치·Max-Age 만료) 로그인이 되도록 했다. **CSRF 방어는 약화시키지 않았다** — 쿠키를 없앤 게 아니라 서명으로 대체했고, 쿠키는 보조(심층) 방어로 남겼다. 서명 위조는 불가능(단위 테스트로 확인). 실패해도 1회 조용히 재시도하고, 사유별 문구·구조화 로그를 넣었다. 별건(약관 링크 안 보임)도 고쳤다.

## 배치 FA — 쿠키에 의존하지 않게

### S36-1 · 서명된 state ★핵심 — 한 것

- **파일(신규)** `lib/kakaoState.js` — `makeState(next)` / `verifyState(state)`.
  - `payload = {n:next, t:Date.now(), r:randomBytes(8)}` → `body = base64url(JSON)` → `sig = HMAC-SHA256(body).base64url.slice(0,22)` → `state = "body.sig"`.
  - 검증: 길이 선검사 후 `crypto.timingSafeEqual` 로 서명 대조 → `bad_sig`. 타임스탬프 10분 초과 → `expired`. `next` 는 내부 경로만 허용(`/` 시작·`//` 아님)으로 정규화.
  - `SECRET` = `process.env.KAKAO_STATE_SECRET || process.env.AUTH_SECRET` (세션 서명 키 재사용). **하드코딩 없음.** 별도 env 를 안 넣어도 기존 `AUTH_SECRET`(프로덕션 이미 설정됨)로 즉시 동작.
- **파일** `pages/api/auth/kakao/start.js` — `makeState(next)` 로 state 생성. 쿠키 `oh_oauth` 에는 서명 대상 `body` 만 담아 **보조 방어로 유지**(Path/HttpOnly/Secure/SameSite=Lax/Max-Age=600 그대로).
- **파일** `pages/api/auth/kakao/callback.js` —
  - `verifyState(state)` 로 검증. 쿠키 없이도 여기서 위조 여부·목적지(next)가 판별된다.
  - **쿠키 보조 대조**: `if (cookieState && cookieState !== v.body) return fail("state_mismatch", …)`. **쿠키가 없으면 통과(서명이 이미 검증) / 있는데 다르면 이상.** '쿠키 없으면 그냥 통과'가 아님.

**검증 결과** (`node` 단위 테스트 11/11 PASS — scratchpad `test_state.mjs`):
- ✅ 정상 roundtrip + next 복원
- ✅ **서명 1글자 변조 → 실패(bad_sig)** ← CSRF 방어 살아 있음 (지시서 최우선 항목)
- ✅ body 1글자 변조 → 실패
- ✅ 빈/형식오류 state → 실패
- ✅ 11분 경과 → expired
- ✅ 오픈 리다이렉트(`//evil`·절대 URL) → `/pwa` 로 정규화

### S36-2 · 자동 1회 재시도 — 한 것

- `callback.js` 의 `fail(reason, recoverable, nextForRetry, extra)`:
  - `recoverable && !isRetry` 이면 `/api/auth/kakao/start?next=<원래목적지>&retry=1` 로 되돌림 → 사용자는 오류 문구 대신 카카오 화면을 한 번 더 보고 로그인.
  - **★무한 루프 방지**: `req.query.retry` 가 이미 있으면(`isRetry`) 절대 재시도 안 하고 `/login?error=…` 로.
- **복구 가능(재시도)**: `bad_sig`, `expired`, `state_mismatch`. **재시도 안 함**: `no_code`(취소)·`token`·`profile`·`server`.

**검증 결과**: 코드 경로 확인 — `retry=1` 이 붙으면 두 번째 실패는 `/login` 으로 1회만 이동(루프 없음). expired 는 next 를 보존해 재시도에 실어 보냄.

## 배치 FB — 실패해도 품위 있게

### S36-3 · 문구 분기 + URL 정리 + 버튼 가드 — 한 것 (`pages/login.js`)

- **(a) 사유별 문구** `MSG` 맵: `no_code`=로그인이 취소되었습니다 / `token`·`profile`·`server` 각각 별도 문구. 그 외(bad_sig·expired 등 재시도 실패 잔여)는 기본 문구. **"문제가 있었습니다" 제거.**
- **(b) URL 정리**: 오류 문구를 `errMsg` state 로 옮긴 뒤 `router.replace("/login?next=…", {shallow:true})` 로 주소의 `error` 를 지움. **next 는 보존.** → 성공 후 뒤로가기 시 오류 재노출 없음.
- **(c) 버튼 중복 클릭 방지**: 카카오 버튼 첫 클릭에 `going=true` → 문구 "이동 중…", `pointer-events:none`, 두 번째 클릭 `preventDefault`.

**검증 결과** (dev 서버 실측):
- ✅ `/login?error=token&next=%2Fpwa%2Fassets` → 문구 "카카오 서버와 연결하지 못했습니다…" 표시, URL 이 `/login?next=%2Fpwa%2Fassets` 로 정리(error 제거·next 보존), 카카오 링크도 `next=/pwa/assets` 유지.
- ✅ 빌드 통과.

### S36-4 · 구조화 로그 — 한 것 (`callback.js`)

- `console.error("[kakao] fail", JSON.stringify({reason, hasCookie, host, ua(80자), retry, …}))`.
- **PII 없음**: 카카오 id·닉네임·이메일·토큰·프로필 본문을 로그에 넣지 않음. token/profile/server 는 진단용으로 **카카오 에러코드·HTTP 상태·예외 메시지(80자)** 만 추가.

**검증 결과**: 로그 객체 필드 확인 — 개인식별 정보 없음. 며칠 뒤 Vercel 로그에서 `hasCookie:false` 가 어떤 `ua`/`host` 에서 나오는지로 네 후보 중 진짜 원인 확정 가능.

## 3. 별건 — 약관 링크가 안 보이던 문제 (해결)

**원인 확정**(dev 실측):
- `.note a` 색이 `#6366f1`(연한 인디고) → 흰 카드 대비 약 3.9:1 로 작은 0.72rem 글자엔 부족(WCAG AA 4.5:1 미달). 모바일 화면·눈부심에선 "안 보임"으로 읽힘.
- 게다가 `styles/globals.css:285` 의 전역 `a { user-select:none }`(앱 느낌용) 때문에 **링크 글자가 복사되지 않음** → 대표님이 보낸 텍스트에서 "이용약관"·"개인정보 처리방침"이 빠져 "로그인 시 및 에 동의"로 보였던 것.

**조치**(`pages/login.js` styled-jsx):
- `.note a` → `color:#4338ca`(대비 ≈ 8.6:1, AA/AAA) + `font-weight:600` + `user-select:text`(약관은 표시 의무 → 읽기·복사 허용).
- `.note` 본문 → `#94a3b8`(≈2.6:1) → `#64748b`(≈4.9:1, AA), `font-size` 0.7→0.72rem.

**검증 결과**(dev 실측): 링크 computed color `rgb(67,56,202)`(#4338ca)·`font-weight 600`·`user-select text`, 본문 `rgb(100,116,139)`. 스크린샷으로 "이용약관·개인정보 처리방침"이 굵고 진하게 보임을 확인.

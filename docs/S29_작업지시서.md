## 0-3. 헤더 세 버튼 실측

`components/AppHeader.js` 는 오른쪽에 **네 요소**를 답니다 — `TraderBadge` · 🔍 · 의견 · ⚙️. 전부 34px 원형입니다.

### 🔍 — 아이콘과 동작이 어긋납니다

```js
aria-label="AI 종목 검색"   onClick → router.push("/pwa?tab=analyze")
```

돋보기는 보편적으로 **"앱 안에서 찾기"** 를 뜻하는데, 실제로는 **주식 종목 분석 화면으로 이동**합니다. 그리고 이 헤더는 전 페이지 공용이라 **부동산 화면에서 돋보기를 눌러도 주식 분석**이 뜹니다. 맥락과 무관합니다.

더 큰 문제는, 사용자가 실제로 찾고 싶은 것들을 찾을 방법이 앱에 **없다**는 것입니다 — 내 보유 종목, 단지 이름, ETF 티커, 저장한 단어, 지난 판단, 지난 리포트.

### 💬 의견 — 잘 만들어졌는데 자리가 아깝습니다

`components/FeedbackButton.js`(119줄)는 바텀시트로 열리고 `/api/feedback` 으로 보내며, **어느 화면에서 보냈는지(`screenName(router.pathname)`)를 자동 첨부**합니다. 설계가 좋습니다.

다만 피드백은 **한 달에 한 번 있을까 말까 한 행동**인데 매 화면 최상단 고정 자리를 차지합니다. 그리고 버튼 색이 `#4f46e5` 하드코딩이라 S26이 세운 토큰 체계 밖입니다.

### ⚙️ 설정 — 627줄에 일반/운영자가 섞여 있습니다

섹션: 나의 정보(카카오톡 ID·One-hub ID·이용 등급) · 알림(Web Push) · 테마 · **화면 확대 허용**(S24-4 ✔) · 계정(계좌 전환·로그아웃) · 온보딩·자산 편집 · 도움말(용어사전·온보딩 다시) · 버전 · 연동(텔레그램) · **운영자 탭**.

운영자 탭이 일반 사용자에게 보이면 사업화 시 문제입니다. S28이 만들 `isOperator` 판정과 연결해야 합니다. 그리고 "지금 보는 계좌"(A/B 전환)가 설정에 있는데 `TraderBadge` 가 헤더에도 있어 **진입점이 둘**입니다.

### 배치 자체의 문제

상단 우측은 **한 손 조작에서 엄지가 가장 안 닿는 곳**입니다. S24-4에서 앱 느낌을 만들어 놨는데, 자주 쓰는 것이 그 자리에 있으면 안 됩니다. 빈도 순서는 **설정 > 검색 > 계좌 전환 > 피드백** 입니다.

## S29-2 · 코드 분할

1. **`recharts` 를 동적 로드로** — `components/PortfolioDuelCard.js` 안의 차트 부분만 `next/dynamic({ ssr: false })` 로 감싸십시오. 대결 카드를 실제로 여는 사람만 내려받게 됩니다.
   - 로딩 중에는 **높이가 같은 자리표시자**를 두십시오. 안 그러면 차트가 뜰 때 화면이 튑니다.
2. **`index.js` 여섯 탭을 분할** — 파일을 쪼개는 건 이번 범위가 아닙니다(4,309줄 리팩터는 회귀 위험이 큽니다). 대신 **탭 본문을 동적 컴포넌트로** 빼십시오.
   - 우선순위: `analyze`(가장 무겁고 가장 덜 쓰임) → `profile` → `recommend`.
   - `report`(AI)와 `portfolio`는 **건드리지 마십시오** — 진입 빈도가 높습니다.
3. **`heat-history.js` 도 같은 처리** — recharts를 씁니다. 공개 페이지라 SEO에 영향이 없도록 `ssr: false` 로.

**함정** — `next/dynamic` 이 이 저장소에 **선례가 없습니다**(백업 파일 하나뿐). 첫 적용 후 반드시 `npm run build` 와 실제 화면을 확인하십시오. styled-jsx 와 함께 쓸 때 스타일이 늦게 붙어 깜빡일 수 있습니다.

**합격선** — First Load JS 가 `index.js`·`heat-history.js` 에서 줄었다. 대결 카드 차트가 정상 렌더된다. 차트 로딩 중 화면이 튀지 않는다.

## S29-3 · 요청 지연 로드와 중복 제거

1. **`index.js` 의 19개 요청을 탭별로 나누십시오.** `today.js` 가 S23 T-8에서 쓴 **`...LoadedRef` 패턴 그대로**입니다. 새 패턴을 만들지 마십시오.
   - 마운트에는 **현재 탭에 필요한 것만**. 나머지는 그 탭이 활성화될 때 1회.
   - `?tab=` 로 직접 진입하는 경우를 처리하십시오(S24-5에서 겪은 함정).
2. **`cachedJson` 을 `etf.js`·`realestate.js`·`english.js` 에도** 적용하십시오. 같은 URL을 두 번 부르는 곳부터.
3. **서비스워커 런타임 캐시** — `public/sw.js` 가 정적 3개만 캐시합니다. GET API 응답에 **stale-while-revalidate** 를 넣으면 재방문이 즉시 뜹니다.
   - **대상은 읽기 전용 GET만.** 판단 기록·매도 같은 쓰기 경로는 절대 캐시하지 마십시오.
   - 캐시 이름에 이미 `CACHE_VERSION` 이 있으니 그 규칙을 따르십시오.

**합격선** — `index.js` 마운트 요청이 19 → 10 이하. 새로고침 후 오늘 화면이 눈에 띄게 빨라진다. 쓰기 요청이 캐시되지 않는다.

## S29-5 · 검색을 맥락 검색으로

### 문제

돋보기가 어느 페이지에서든 **주식 분석 화면**으로 갑니다. 부동산 화면에서도 그렇습니다.

### 할 일

1. **한 곳에서 다 찾게 하십시오.** 돋보기를 누르면 **검색 시트**가 열리고, 한 입력창에서 아래를 함께 찾습니다.
   | 종류 | 소스 | 이동 |
   |---|---|---|
   | 내 보유 종목 | 대시보드 positions | 주식 상세 |
   | 종목 코드·이름(신규) | 기존 종목 마스터 | AI 분석 |
   | 내 단지·관심 단지 | 부동산 | 부동산 상세 |
   | 보유 ETF·티커 | etfHoldings | ETF |
   | 저장한 단어 | `onehub_vocab`(S25-7) | 단어장 |
   | 지난 판단 | 판단 원장 | 심판석 |
2. **현재 페이지 것을 위에** 올리십시오. 부동산 화면에서 열면 단지가 먼저, 주식 화면에서 열면 종목이 먼저.
3. **최근 검색 5개**를 기억하십시오(로컬, 동기화 불필요).
4. **새 API를 만들지 마십시오.** 전부 이미 화면이 갖고 있는 데이터입니다. 검색은 클라이언트에서 걸러내면 됩니다.
5. **빈 입력 상태**에서 최근 검색과 함께 "무엇을 찾을 수 있는지" 예시를 보여주십시오.

**합격선** — 부동산 화면에서 돋보기를 눌러 단지를 찾을 수 있다. 종목·단지·ETF·단어가 한 입력창에서 나온다. 새 API가 없다.

3. **유튜브로 내보내지 마십시오.** 앱 안에서 재생합니다. "유튜브에서 보기"는 작은 보조 링크로만. 한 번 넘어가면 추천 영상에 사용자를 빼앗깁니다.
4. **회차가 없는 주에는** "이번 주는 쉬어갑니다 · 지난 회차 보기"로. 빈 카드를 만들지 마십시오(S24 원칙).
5. **`content/story` 7화 연재를 앱 안에서 링크** — 이야기 페이지 하단에 "ONE·HUB는 왜 만들어졌나 · 7화 연재"로. **이미 만들어 둔 자산이 놀고 있습니다.**

**합격선** — 마크다운 한 개를 커밋하면 이야기 최상단에 회차가 뜬다. 앱 안에서 재생된다. 7화 연재 진입로가 생겼다.

## S29-8 · 대본 초안 생성기 ★이 스프린트의 핵심

### 왜

유튜브 채널이 멈추는 이유는 아이디어가 아니라 **지속성**입니다. 본업이 있는 1인이 매주 리서치·대본·편집을 감당하기 어렵습니다. **그런데 이 앱은 이미 매일 소재를 만들고 있습니다.**

### 할 일

**`lib/episodeDraft.js`(신규)** — 운영자 화면(이야기 페이지 안, `isOperator` 뒤)에 토요일 아침 이렇게 뜨게 하십시오.

```
📺 이번 주 회차 소재 3개
① AI가 막은 삼성SDI·LG화학·SK하이닉스 — 이후 평균 −4.2%
② 내 판단 7건 승률 57% vs AI 50% — 관망 4건이 손실을 피함
③ 분당 정자동 신고가 24.1억 — 내 단지 대비 +8%

대본 초안 · 예상 6분   [복사]  [숫자 다시 뽑기]
```

### 소재는 기존 것에서만

| 소재 | 소스 | 강도 |
|---|---|---|
| **차단 종목 후일담** | `/api/pwa/accuracy` by_reason + 이후 가격 | **가장 강함 — 이 앱만 가능** |
| 나 vs AI 주간 | `getVerdictScorecard`(S22-5) | 강함 |
| 부동산 신고가 | `re-spot`(S28-10) | 중간 |
| 절세 달력 | `taxCalendar`(S22-8) | 시기 한정 |
| 엔진 개선 | `engine_changes`(S28-1) | 월 단위 |
| ETF 4주 추세 | S25-8 · S27 일별 이력 | 중간 |

**새 수집기를 만들지 마십시오.** 없는 소재는 그냥 빠집니다.

### 반드시 지킬 것

- **숫자마다 출처를 함께** 뽑으십시오. 영상에서 잘못 말하면 되돌릴 수 없습니다.
- **초안은 초안입니다.** 그대로 읽으라고 만드는 게 아니라 리서치를 없애는 것입니다.
- 소재가 2개 미만이면 **그렇다고 말하십시오.** 억지로 세 개를 채우지 마십시오.
- LLM으로 문장을 다듬는다면 **S27이 만든 `:5005` 서킷브레이커를 경유**하십시오. 새 경로를 만들지 마십시오.

**합격선** — 토요일에 운영자 화면에서 소재 3개와 숫자·출처가 나온다. 숫자가 각 소스의 화면 값과 일치한다. 소재가 부족하면 정직하게 말한다.

# 봇 비용 서킷 브레이커 + 모델 티어링 (2층)

`claude_usage.py` 의 **2층 안전장치**입니다. 1층(계측)은
[docs/API_COST_최적화.md](API_COST_최적화.md) 를, 이 문서는 그 위에 얹은
**비용 서킷 브레이커**와 **모델 티어링**을 다룹니다.

- **1층(계측)** = 모든 Claude 호출을 `call_and_log()` 로 기록 → "어디서 얼마 쓰는지"
- **2층(이 문서)** = 예산 초과 시 호출 차단/다운그레이드하는 **서킷 브레이커** +
  작업 중요도별 저가 모델 라우팅인 **티어링**

> 배경: `7/18`부터 Anthropic API 사용한도 도달로 프로덕션 AI 스크리닝/회고가 조용히
> 실패한 사건이 있었습니다. 이 2층은 그런 상황을 **비용 관점에서 사전에 감지·제어**하기
> 위한 안전장치입니다.

---

## ★ 핵심 원칙 3가지

1. **전부 기본 OFF.**
   아무 환경변수도 설정하지 않으면 2층은 아무 일도 하지 않습니다.
   `guarded_create()` 는 `call_and_log()` 와 100% 동일하게 동작하고(계측만),
   서킷 브레이커는 **절대 트립되지 않으며**, `pick_model()` 은 넘겨준 모델을 그대로 반환합니다.

2. **폴백 안전 (fail-open).**
   내부 오류(사용량 DB 손상, 디스크 풀 등)가 나면 **프로덕션을 절대 멈추지 않는**
   방향으로 처리합니다 → 오류 시 지출을 `0`으로 보고 **차단하지 않습니다**.
   회계 DB가 죽었다고 매매 봇을 멈춰서는 안 되기 때문입니다.

3. **무손상 통합.**
   기존 5개 호출부가 쓰는 1층 API(`call_and_log`, `MODEL_SCREENER`, `MODEL_REPORT` …)는
   **그대로 보존**됩니다. `call_and_log()` 는 서킷 브레이커/티어링에 관여하지 않는
   순수 계측+패스스루입니다. 게이팅·라우팅이 필요한 호출부만 `guarded_create()` 로
   **명시적으로 opt-in** 합니다.

## 파일 위치

`claude_usage.py` 는 저장소 **root** 와 **`auto_trade/`** 두 곳에 **동일 사본**으로 존재합니다.

```
claude_usage.py            # root / GitHub Actions
auto_trade/claude_usage.py # 서버 엔진 (root 와 100% 동일)
```

> ⚠️ 한쪽을 고치면 다른 쪽도 **똑같이** 고쳐야 합니다.

사용량 DB(기본 `~/claude_usage.db`)는 `.gitignore` 의 `*.db` 규칙으로 **커밋되지 않습니다.**

## 환경변수 (전부 기본 OFF)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `CLAUDE_CB_ENABLED` | `0`(off) | 서킷 브레이커 마스터 스위치. |
| `CLAUDE_CB_DAILY_USD` | (없음) | 오늘(UTC) 누적 지출이 이 값 이상이면 트립. |
| `CLAUDE_CB_MONTHLY_USD` | (없음) | 이번 달(UTC) 누적 지출이 이 값 이상이면 트립. |
| `CLAUDE_CB_ON_TRIP` | `block` | 트립 시 동작: `block`(호출 차단, `None` 반환) / `downgrade`(저가 모델로 호출) / `raise`(예외). |
| `CLAUDE_CB_FALLBACK_MODEL` | `MODEL_CHEAP`(`claude-haiku-4-5`) | `downgrade` 시 사용할 저가 모델. |
| `CLAUDE_TIERING_ENABLED` | `0`(off) | 모델 티어링 마스터 스위치. |
| `CLAUDE_TIER_<TIER>` | (없음) | 티어별 모델 매핑. 예) `CLAUDE_TIER_SCREENING=claude-sonnet-5`. |
| `CLAUDE_USAGE_DB` | `~/claude_usage.db` | (1층과 공유) 사용량 SQLite 경로. |

- 서킷 브레이커는 `CLAUDE_CB_ENABLED=1` **그리고** 일/월 한도 중 하나 이상이 설정돼야
  실제로 트립됩니다. (스위치만 켜고 한도가 없으면 트립하지 않음)
- 지출 집계는 **1층이 기록한 `cost_usd`(SQLite `usage` 테이블)** 를 그대로 씁니다.
  1층 DB `ts` 가 UTC(SQLite `CURRENT_TIMESTAMP`)이므로 **일/월 경계도 UTC** 기준이며,
  이는 Anthropic 월 한도 리셋(UTC)과 정렬됩니다.

## 모델 단가 (참고용 추정치, USD / 백만 토큰)

1층의 `PRICING` 을 사용합니다. 서킷 브레이커가 동작하려면 단가가 `0`이 아니어야 하므로
현행(2026-07) 공개가 기준의 **추정치**를 채워 두었습니다.

| 모델 | input | output |
|---|---|---|
| `claude-opus-4-5` / `opus-4-8` / `opus-5` | 5 | 25 |
| `claude-sonnet-4-6` / `sonnet-5` | 3 | 15 |
| `claude-haiku-4-5` | 1 | 5 |
| `claude-fable-5` | 10 | 50 |

- 단가 미상 모델은 **보수적(비싼)** 기본값(5/25)으로 추정 → 비용 과소평가 방지.
- 날짜 접미사(예: `claude-haiku-4-5-20251001`)가 붙어도 접두 매칭으로 단가를 찾습니다.
- **정확한 청구는 Anthropic 콘솔이 기준**이며, 필요 시 콘솔 실단가로 갱신하세요.

## 공개 API (2층 추가분)

```python
import claude_usage as cu
```

### 서킷 브레이커
```python
cu.breaker_state() -> dict   # {enabled, tripped, reason, spend_today, spend_month, ...}
cu.is_tripped() -> bool      # 기본 OFF/오류 시 False
cu.today_cost() -> float     # 오늘(UTC) 누적 USD
cu.month_to_date_cost()      # (1층) 이번 달(UTC) 누적 USD
cu.config() -> dict          # 해석된 2층 설정
```

### 모델 티어링
```python
cu.pick_model(default_model, tier=None) -> str
# 티어링 OFF(기본) 또는 해당 티어 매핑 없음 → default_model 그대로.
```

### 통합 진입점
```python
cu.guard(default_model, tier=None) -> Decision(allow, model, reason, tripped)
cu.guarded_create(client, feature, model, tier=None, **kwargs)
# call_and_log 에 서킷 브레이커 + 티어링을 얹은 래퍼. 계측은 call_and_log 가 담당.
```

> 1층 API(`call_and_log`, `log_usage`, `MODEL_*`, `over_threshold`,
> `daily_report_line` …)는 그대로 유지됩니다.

## 통합 예시

### A) `call_and_log` → `guarded_create` 로 교체 (게이팅+티어링)

기존(1층 계측만):
```python
message = call_and_log(
    client, "stock_screener",
    model=MODEL_SCREENER, max_tokens=600,
    messages=[{"role": "user", "content": prompt}],
)
raw_ai = extract_text(message)
```

교체(2층: 예산 게이팅 + 티어링 + 계측):
```python
message = cu.guarded_create(
    client, "stock_screener",
    model=MODEL_SCREENER, tier="screening",   # 티어 라벨(선택)
    max_tokens=600,
    messages=[{"role": "user", "content": prompt}],
)
if message is None:
    # 브레이커 트립(block 모드)으로 호출이 차단됨 → 안전 폴백
    return safe_default_result()   # 예: HOLD/관망
raw_ai = extract_text(message)
```

- **모든 스위치 OFF(기본)** 상태에서는 `guarded_create` 가 `call_and_log` 와 **동일하게**
  동작하며 **절대 `None` 을 돌려주지 않습니다.** (`None` 체크는 트립 대비용)
- `feature` 인자를 그대로 넘기므로 계측 라벨링(1층)이 유지됩니다.

### B) 티어링만 — 모델 선택에만 개입
```python
model = cu.pick_model(MODEL_REPORT, tier="weekly")   # 기본 OFF → 그대로
msg = call_and_log(client, "weekly_review", model=model, max_tokens=400, messages=[...])
```

### C) 결정만 조회 (직접 호출 로직이 있을 때)
```python
d = cu.guard(MODEL_SCREENER, tier="screening")
if not d.allow:
    return safe_default_result()
msg = call_and_log(client, "stock_screener", model=d.model, max_tokens=600, messages=[...])
```

## 트립 시 동작 (`CLAUDE_CB_ON_TRIP`)

| 값 | `guarded_create` 반환 | `guard().allow` | 용도 |
|---|---|---|---|
| `block`(기본) | `None` | `False` | 호출을 건너뛰고 호출부의 안전 폴백 사용 |
| `downgrade` | 저가 모델로 실제 호출 | `True`(model=폴백) | 비용을 줄이되 AI는 계속 사용 |
| `raise` | `RuntimeError` | `False` | 명시적으로 예외 처리하고 싶을 때 |

> `block` 모드에서 호출부가 `None` 을 처리하지 않으면 크래시할 수 있으니, **반드시 `None`
> 체크와 안전 폴백을 함께** 두세요. (기본 OFF 상태에서는 `None` 이 나오지 않습니다.)

## 점진적 도입 권장 순서

1. **관측만.** 1층 `call_and_log` 계측이 이미 5개 호출부에 붙어 있으니,
   며칠간 `python claude_usage.py report` / `breaker` 로 실제 일/월 지출을 관찰.
2. **한도 설정(느슨하게).** 관찰된 지출보다 넉넉한 값으로 `CLAUDE_CB_DAILY_USD` /
   `CLAUDE_CB_MONTHLY_USD` 설정 + `CLAUDE_CB_ENABLED=1`, `CLAUDE_CB_ON_TRIP=downgrade`
   로 시작(차단보다 안전). 이때 게이팅을 원하는 호출부만 `guarded_create` 로 전환.
3. **티어링(선택).** 덜 중요한 작업(예: 주간 회고/전망)을 `CLAUDE_TIER_<TIER>` 로 저가
   모델에 매핑해 비용 상시 절감.
4. **필요 시 차단.** 신뢰가 쌓이면 `CLAUDE_CB_ON_TRIP=block` 으로 상향(호출부 `None` 폴백 필수).

## 안전성 요약

- `import` 부작용 없음 · 2층 전부 기본 OFF · 오류 시 fail-open(미차단).
- `call_and_log`(1층)은 브레이커 영향 없이 그대로 동작 → 기존 5개 호출부 무손상.
- 사용량 DB 실패는 매매를 멈추지 않음(지출을 0으로 간주).
- 단가 미상 모델은 비싸게 추정(과소평가 방지).
- root / `auto_trade` 사본은 반드시 동일하게 유지.

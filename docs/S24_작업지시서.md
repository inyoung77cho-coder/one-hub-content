## 0. 왜 이 스프린트인가

S22·S23에서 20항목을 실행했고 미이행은 0건이었습니다. 그런데 사용자 평가는 **"활용과 정확도, 자꾸 쓰고 싶은 디자인과 효용이 잘 안 느껴진다"** 였습니다.

체감을 세어보니 이유가 분명했습니다.

| | 건수 | 내용 |
|---|---|---|
| 오늘 화면에서 매일 보임 | **5** | 운용자산 헤드라인 · 세그먼트 탭 · 곡선(오작동) · 판단 버튼(조건부) · 읽을 거리 라벨 |
| 조건이 맞아야 보임 | **3** | 판단 버튼 · 목표 배분 · 교차 인사이트 |
| 오늘은 안 보임 | **12** | 주기 훅 · 절세 달력 · 성적표 · 주간 리포트 · 방문 기록 · 지연 로드 … |

동시에 **줄어든 것이 4건**입니다 — 절세 카드(9월엔 미렌더), 이야기 카드 4→1, 지역 증감 카드(이관), 체크박스(조치 0건인 날엔 누를 게 없음).

**순증이 사실상 0이고, 화면은 더 유용해진 게 아니라 더 조용해졌습니다.**

원인은 이전 지시서의 설계입니다. "데이터가 없으면 빈 카드 대신 렌더하지 마십시오"를 **여섯 기능에 동시에** 걸었습니다. 하나에 걸면 정직함이지만 여섯에 걸면 공허함이 됩니다.

### 이 스프린트의 원칙 — 이전 원칙의 교정

> **"없음"도 정보다.** 데이터가 없을 때 카드를 지우는 대신, **왜 없는지와 그래서 무엇을 하면 되는지**를 근거와 함께 보여준다. 지어내지 않는다는 원칙은 그대로다 — 빈 것을 채우지 말고, 빈 것을 설명하라.

# UA — 틀린 숫자부터

## S24-1 · 자산 곡선 절벽 수정 ★가장 급함

### 증거

T-4가 넣은 30일 곡선이 **단위가 섞인 시계열**을 그립니다.

```
today.js:532   h.operating != null ? h.operating : h.total
assets.js:338  h.operating != null ? h.operating : h.total
assetHistory.js:53  operating: num(b.operating_uk)   ← S23 TA 에서 처음 추가

→ 9/2 이전 스냅샷: operating 필드 없음 → 총자산(예: 57.87억)으로 그림
→ 9/2 이후 스냅샷: operating 있음     → 운용자산(예: 10.67억)으로 그림
```

사용자에게는 **"자산이 하루 만에 82% 증발한 그래프"** 로 읽힙니다. 그것도 매일 여는 화면의 첫 줄에서.

같은 이유로 `getDelta` 의 `operating` 도 이틀간 null이라 **전일 대비 숫자가 사라집니다.** 배포 직후 첫인상이 "변동 없음 + 무너진 그래프" 입니다.

### 할 일

1. **먼저 확인** — 실제 저장된 스냅샷을 열어 `operating` 이 없는 항목이 몇 건인지 세십시오. 판단 근거 없이 고치지 마십시오.
2. **표시 규칙을 하나로.** 다음 중 하나를 고르되, 고른 이유를 결과 문서에 쓰십시오.
   - **(권장) `operating` 이 있는 구간부터만 그린다.** 없는 구간은 아예 제외. 2건 미만이면 곡선 대신 `기록 중 · N일째` 안내. 가장 정직하고 가장 안전합니다.
   - 과거 스냅샷에 `operating` 을 **소급 계산해 채운다.** 단 과거의 실거주 평가액을 알 수 없으므로 **추정이 됩니다.** 이 앱은 사용자 값을 임의로 고치지 않는다는 원칙이 있으니, 하려면 `estimated: true` 를 남기고 곡선에 점선 구간으로 구분 표시하십시오.
3. **혼합 방지 가드** — 시계열을 그리기 전에 `operating` 유무가 섞여 있는지 검사하고, 섞여 있으면 앞 구간을 버리는 로직을 `components/shared/Sparkline.js` 가 아니라 **데이터를 만드는 쪽**에 두십시오. Sparkline 은 받은 배열을 그리기만 해야 합니다.
4. **전일 대비 폴백** — `operating` 델타가 null이면 총자산 델타로 떨어지되 **라벨에 기준을 밝히십시오**("총자산 기준"). 조용히 다른 숫자를 보여주지 마십시오.

### 합격선

- 곡선에 82% 급락 구간이 없다.
- `operating` 이 없는 계정에서도 그래프가 깨지지 않고 안내 문구가 나온다.
- 오늘·종합자산 두 화면의 곡선이 **같은 모양**이다.
- 결과 문서에 실제 스냅샷 개수와 선택한 규칙, 그 이유가 적혀 있다.

## S24-2 · "지난주 판단"에 기간 창 넣기

### 증거

```
todayCadence.js:40  title: "지난주 내 판단", text: `판단 ${sc.total}건…`
verdictStats.js:14  const list = getRecLedger(trader) || [];  → total: list.length
```

`getVerdictStats` 에 **기간 필터가 없습니다.** 판단이 120건 쌓인 사용자는 매주 월요일 "지난주 내 판단 · 판단 120건" 을 봅니다. 라벨이 사실과 다르고, 숫자가 매주 같아 **주간 훅의 효력도 사라집니다.**

### 할 일

1. `getVerdictStats(trader, opts)` 에 `opts.sinceTs`(또는 `days`)를 받아 원장 항목을 `ts` 로 거릅니다. **기본값은 무제한**(기존 호출부 회귀 없음).
2. `getVerdictScorecard` 도 같은 창을 받게 하고, **승률·AI 대비·놓친 수익도 같은 창**으로 계산합니다. 건수만 주간이고 승률은 누적이면 더 나쁩니다.
3. `todayCadence` 의 월요일 훅은 **지난 7일**을 넘깁니다.
4. 창을 적용한 곳에는 라벨에 기간을 씁니다 — `지난주(8/25~8/31)`.
5. 주간 건수가 0이면 훅을 반환하지 않는 기존 가드는 유지합니다.

### 합격선

- 월요일 카드의 건수가 **누적이 아니라 지난 7일**이다.
- `/pwa/record`(누적)와 월요일 카드(주간)의 숫자가 다르고, 각각 라벨로 기간이 구분된다.
- 기존 호출부(성적표·대결 카드)의 숫자가 변하지 않는다.

## S24-3 · 시세 온전성 가드

### 증거

S22-1은 6종목을 실측해 `.KS` 가 정답이고 133690의 −88.5%가 **Yahoo의 133690.KQ 유령 심볼(23,513원)** 때문임을 정확히 밝혔습니다. 그런데 결론이 "`.KS` 우선이 곧 유령 방어이므로 변경 불필요" 였습니다.

**이 논리는 성립하지 않습니다. 그 순서가 이미 적용된 상태에서 오류가 났습니다.**

```
quote.js:66  const candidates = isKr ? [`${base}.KS`, `${base}.KQ`] : […]
quote.js:67  for (…) { const y = await fromYahoo(ysym); if (y) { q=y; break } catch {} }

→ .KS 가 일시 실패하거나 null 이면 조용히 .KQ 로 폴백
→ 그 값이 s-maxage=300 으로 5분간 CDN 에 굳음
→ saneEtfAvg 는 '평단 대 현재가' 10배 기준. 이 경우 실제 8.7배 → 안 걸림
```

가드가 **평단**에 있는데 문제는 **시세**에 있습니다.

### 할 일

1. **직전 정상가 대비 급변 차단** — 마지막으로 성공한 시세를 티커별로 짧게 보관하고(서버 메모리 또는 기존 캐시 계층), 새 응답이 **3배 초과 또는 1/3 미만**이면 채택하지 않고 직전 값을 유지하며 응답에 `suspect: true` 를 실어 보냅니다.
2. **폴백 조건 제한** — `.KS` 가 **명시적으로 "그런 심볼 없음"** 을 답했을 때만 `.KQ` 를 시도합니다. 네트워크 오류·타임아웃·빈 응답은 폴백 사유가 아닙니다(그때는 그냥 실패로 두고 `missing` 에 넣으십시오 — S21-7이 만든 재조회 경로가 이미 있습니다).
3. **의심 시세는 캐시를 짧게** — `suspect` 가 있으면 `s-maxage` 를 30초로. 5분간 굳지 않게.
4. **화면 표기** — `suspect` 인 종목은 평가액 옆에 `시세 확인 중` 을 붙이고 총자산 합산에서 제외하십시오. `AvgPriceWarningCard`(S22-1) 와 같은 톤으로, 다만 **평단이 아니라 시세** 문제임을 문구로 구분하십시오.

### 함정

- 실제 급등·급락(상한가·액면분할)을 오탐할 수 있습니다. 3배는 하루 변동으로는 불가능한 폭이라 안전하지만, **액면분할·병합**은 정당하게 배수가 바뀝니다. 오탐 시 사용자가 "이 값이 맞습니다" 로 통과시킬 수 있어야 합니다(기존 `verified` 패턴 재사용).
- 캐시 계층이 어디인지 먼저 확인하십시오. Vercel CDN·`lib/quoteCache.js`·백엔드 중 어디에 보관할지 결정하고 결과 문서에 적으십시오.

### 합격선

- 133690에 대해 `.KQ` 값을 강제로 주입해도 화면에 23,500원이 뜨지 않는다.
- `.KS` 타임아웃 시 `.KQ` 로 넘어가지 않고 `missing` 으로 처리된다.
- 정상 시세는 종전과 동일(회귀 없음).

# UB — 손에 닿는 느낌

## S24-4 · 앱처럼 느껴지게 (화면 고정)

### 사용자 요구

> PWA 화면이 양손으로 크기가 조정되지 않고 고정 형태로 앱 느낌이 있도록

### 먼저 알아둘 것

"웹페이지 같다"는 느낌의 주범은 대개 핀치 줌 하나가 아니라 **다섯 가지**입니다. 핀치만 막으면 여전히 웹처럼 느껴집니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 위아래 끝에서 화면이 튕김 | rubber-band overscroll | `overscroll-behavior: none` |
| 위로 당기면 새로고침 | pull-to-refresh | 같은 속성 (`overscroll-behavior-y: contain`) |
| 스크롤할 때 주소창이 나타났다 사라지며 화면 높이가 출렁 | `100vh` | `100dvh` + `viewport-fit=cover` |
| 두 번 탭하면 확대 | double-tap zoom | `touch-action: manipulation` |
| 길게 누르면 텍스트 선택·복사 메뉴 | 기본 동작 | 비텍스트 요소에 `user-select: none` |
| 탭할 때 회색 사각형 번쩍 | tap highlight | `-webkit-tap-highlight-color: transparent` |
| 두 손가락으로 확대 | pinch zoom | `user-scalable=no, maximum-scale=1` |

### 할 일

1. **현재 상태 (확인 완료 — 다시 조사하지 마십시오)**
   - `pages/_document.js` 는 **없습니다.** `pages/_app.js` 에 전역 `<Head>` 가 있고(77~87행) 거기에 `apple-mobile-web-app-capable: yes` 등 PWA 메타가 이미 있습니다. **그런데 viewport meta 가 없습니다** — 지금은 Next.js 기본값(`width=device-width`)에 의존하고 있습니다.
   - 마케팅 페이지(`about.js`·`blog/*`·`daily/*` 등)는 각자 인라인으로 viewport 를 선언합니다. **그 페이지들은 건드리지 마십시오** — 확대가 필요한 일반 웹페이지입니다.
   - 전역 CSS(`styles/`)에 `touch-action`·`overscroll-behavior`·`dvh` 가 **하나도 없습니다.** 위 표의 조치가 전부 새로 들어갑니다.
   - → **`pages/_app.js` 의 기존 `<Head>` 에 viewport 한 줄**, 전역 CSS에 나머지. 한 곳에서 모든 PWA 화면이 해결됩니다.
2. **1단계(안전) 전부 적용** — 위 표의 앞 여섯 줄. 접근성 손해가 없고 체감이 큽니다. 스크롤 컨테이너에 `-webkit-overflow-scrolling: touch` 도 함께.
3. **2단계(핀치 차단) 적용하되 탈출구를 두십시오** — `user-scalable=no` 는 **WCAG 1.4.4 위반**이고 iOS Safari 10 이후로는 무시되는 경우도 있습니다. 그래도 요구사항이므로 적용하되:
   - `pages/pwa/settings.js` 에 **"화면 확대 허용"** 토글을 추가하고, 켜면 viewport meta 를 런타임에 바꿔 핀치를 되살립니다.
   - `text-size-adjust: 100%` 는 **유지**하십시오(OS 글자 크기 설정은 계속 반영되어야 합니다).
4. **홈 화면 추가 유도** — 진짜 앱 느낌의 8할은 **standalone 모드**입니다. 브라우저 탭에서 열면 무슨 짓을 해도 주소창이 남습니다.
   - `beforeinstallprompt` 를 잡아두고, 방문 3일차(`onehub_visit_days`, S23 T-10)에 **한 번만** "홈 화면에 추가하면 앱처럼 열립니다" 안내를 띄웁니다.
   - iOS는 이 이벤트가 없으므로 Safari 감지 시 **공유 → 홈 화면에 추가** 3단계 그림 안내로 대체합니다.
   - 거절하면 다시 묻지 않습니다(`onehub_install_dismissed`).

### 합격선

- 세로 끝에서 튕김·당겨서 새로고침이 없다.
- 스크롤 중 화면 높이가 출렁이지 않는다.
- 두 번 탭·길게 누르기·탭 하이라이트가 앱처럼 조용하다.
- 설정에 "화면 확대 허용" 토글이 있고, 켜면 핀치가 동작한다.
- 홈 화면 추가 안내가 3일차에 한 번만 뜬다.

## S24-5 · 스와이프로 탭 전환

이 구분이 이 항목의 핵심입니다. **하단 탭 이동은 절대 스와이프로 만들지 마십시오.**

### 현재 상태 (확인 완료)

저장소 전체에 `onTouchStart`·`touchstart` 핸들러가 **한 개도 없습니다.** 제스처 코드는 전부 새로 들어갑니다 — 기존 동작과 충돌할 것은 없지만, 반대로 참고할 선례도 없으니 아래 함정을 그대로 따르십시오.

### 적용 대상

페이지 안에 좌우 탭이 있는 화면만:
- **오늘** — 자산 · 부동산 · ETF · 이야기 (S23 T-3 세그먼트)
- **종합자산** — 세그먼트가 있으면 동일 적용
- **AI 트러스트 허브** — `?sec=` 섹션 순환이 있으면 동일 적용

### 함정 (전부 지켜야 함)

1. **iOS 뒤로가기 제스처** — 화면 **좌측 가장자리 24px** 안에서 시작한 터치는 무시하십시오. 브라우저 뒤로가기와 충돌합니다.
2. **가로 스크롤 영역** — `overflow-x: auto` 컨테이너(표·칩 행·차트) 안에서 시작한 터치는 무시하십시오. `e.target.closest()` 로 조상을 확인합니다.
3. **세로 스크롤 우선** — 첫 이동 판정에서 `|dx| > |dy| * 1.5` 일 때만 스와이프로 확정합니다. 애매하면 세로 스크롤에 양보하십시오. 대각선 손가락이 탭을 넘겨버리면 최악입니다.
4. **임계값** — 이동 거리 **60px 이상** 또는 속도 기준. 짧은 스와이프로는 안 넘어가야 합니다.
5. **양 끝에서 멈춤** — 첫 탭에서 더 오른쪽으로, 마지막 탭에서 더 왼쪽으로 밀어도 **페이지를 벗어나지 않습니다.** 살짝 저항(20px 정도 따라왔다 돌아옴)만 주십시오.
6. **history 오염 금지** — 스와이프로 탭을 바꿀 때 `router.push` 를 쓰면 뒤로가기를 열 번 눌러야 페이지를 벗어나게 됩니다. **`router.replace`** 를 쓰십시오. 탭 클릭도 동일하게 맞추고, 뉴스 모달(`?news=`)만 `push` 를 유지합니다.
7. **탭을 없애지 마십시오** — 스와이프는 **추가** 수단입니다. 스와이프로만 갈 수 있는 화면이 있으면 안 됩니다(접근성).
8. **`prefers-reduced-motion`** — 전환 애니메이션을 끄고 즉시 전환합니다.

### 구현 방향

`components/shared/useSwipeTabs.js` 훅 하나로 만들고 세 화면이 공유하십시오. 페이지마다 복제하면 함정 여덟 개를 세 번 틀립니다.

전환 애니메이션은 **손가락을 따라오는 방식**(translateX)이 앱 느낌에 결정적입니다. 손을 떼면 임계 초과 시 다음 탭으로 스냅, 미달이면 제자리로. 다만 4개 화면을 모두 DOM에 올리면 무거우니, **현재·다음 두 장만** 렌더하십시오.

### 합격선

- 오늘 화면에서 좌우로 밀면 자산 ↔ 부동산 ↔ ETF ↔ 이야기가 넘어간다.
- 좌측 가장자리에서 시작한 스와이프는 브라우저 뒤로가기로 동작한다.
- 표를 가로로 스크롤해도 탭이 넘어가지 않는다.
- 마지막 탭에서 더 밀어도 다른 페이지로 가지 않는다.
- 탭을 다섯 번 넘긴 뒤 뒤로가기 한 번에 이전 페이지로 나간다.

## S24-6 · 화면 위계 재배치

### 증거

"신문에서 장부로" 가 S23의 목표였는데, 오늘 화면(자산 탭) 카드 구성은 여전히 이렇습니다.

```
요약 1장  :  뉴스·시황 3장  :  판단 1장(맨 아래)
              ↑ 시황 브리핑 · 봇이 보낸 뉴스 · 주식 뉴스
```

**이 앱의 유일한 차별점인 판단 카드가 스크롤 맨 끝**에 있습니다. 그리고 다섯 장이 전부 같은 흰 배경·같은 테두리·같은 모서리·같은 그림자라, 무엇이 중요한지 화면이 말해주지 않습니다. **위계는 코드에서만 바뀌었고 시각적 위계는 그대로**입니다.

### 할 일

1. **순서 교체** — 오늘 화면(view 0) 카드 순서를 이렇게 바꾸십시오.
   ```
   ① 요약 (운용자산 · 곡선 · AI 변화)
   ② 오늘의 판단          ← 위로 올림. 조치 0건인 날도 항상 있음(S24-7)
   ③ 주기 훅              ← 발동한 날만
   ④ 읽을 거리            ← 뉴스 3장을 1장으로 묶고 기본 접힘
   ```
2. **뉴스 3장 → 1장** — 시황 브리핑·봇 뉴스·주식 뉴스를 **하나의 "읽을 거리" 카드**로 합치고 안에서 구분하십시오. 기본은 접힘, 헤더에 `오늘 12건` 정도의 건수만. **삭제가 아니라 접기입니다** — 내용은 다 유지하십시오.
3. **카드 다이어트** — 카드가 아니어야 할 것을 카드에서 빼십시오.
   - `AI 변화` 한 줄 → 요약 카드 안의 한 행 (이미 그렇다면 유지)
   - 대결 결과 배너 → 테두리 없는 한 줄
   - 판정 기준: **탭할 수 있는 독립 개체가 아니면 카드가 아닙니다.**
4. **판단 카드만 승격** — 다섯 장 중 **하나만** 시각적으로 들어올리십시오. 나머지는 낮춥니다.
   - 판단 카드: 배경 대비를 주거나 테두리를 강조. 그림자를 조금 더.
   - 나머지: 그림자 제거, 테두리만. 또는 배경만.
   - **전부 강조하면 아무것도 강조되지 않습니다.**
5. **기존 토큰만 사용** — 새 색을 만들지 말고 `var(--color-*)` 전역 토큰 안에서 해결하십시오. 다크 모드에서도 성립해야 합니다.

### 합격선

- 오늘 화면을 열었을 때 **스크롤 없이** 판단 카드가 보인다.
- 카드 수가 5장 → 4장(요약·판단·주기훅·읽을거리), 주기 훅 미발동 시 3장.
- 뉴스 기사 수가 줄지 않았다(접혔을 뿐).
- 다크 모드에서 위계가 같게 읽힌다.

# UC — 조용한 날에도 할 말이 있게

## S24-7 · 조용한 날의 오늘 ★효용의 본체

### 문제

할 일은 `deriveUrgency(p).rank <= 2`, 즉 **목표가 도달·손절 근접**인 종목만 올라옵니다. 모두 유지 구간이면:

```
조치 0건 → 기록할 판단 0건 → 월요일 카드 미발동 → 주간 리포트 미발송
```

**사슬 전체가 조용히 멈춥니다. 그리고 대부분의 날이 그런 날입니다.**

매일 들어오고 싶은 앱을 만들려는데, 설계상 **대부분의 날에 아무 말도 하지 않도록** 되어 있습니다.

### 해법의 방향

정직성을 버리는 게 아닙니다. **조용한 날에도 매일 바뀌는 진짜 콘텐츠가 이미 있습니다 — 과거 판단의 경과입니다.**

판단 원장은 각 판단의 `entry`(판단 시점 가격)와 `snaps` 를 갖고 있습니다. 조치할 종목이 없어도, **내가 지난주에 내린 판단들이 지금 어떻게 되고 있는지**는 매일 달라집니다. 이건 다른 앱이 흉내 낼 수 없고, 앱이 매일 새로울 이유가 됩니다.

### 할 일

판단 카드가 **항상** 렌더되고, 안에 채울 것을 우선순위 폭포로 고릅니다.

1. **조치가 있으면** — 지금처럼 손절 임박·목표 도달 종목 + `[매도][보유][관망]`.
2. **조치가 없으면 — 내 판단의 경과** (새로 만들 것)
   - `3일 전 보유 판단 · 삼성전자 +2.1%` 처럼 **최근 판단 3건의 이후 수익률**을 보여줍니다.
   - 채점 창(3거래일)이 찬 것은 정답/오답 표시, 아직 안 찬 것은 진행 중 표시.
   - 계산은 `verdictLedger` 의 `returnAt`·`matureLedger` 를 **재사용**하십시오. 새로 만들지 마십시오.
3. **판단 기록이 아예 없으면 — 오늘의 관찰**
   - 손절선 최근접 상위 3종목을 제시하고 각각 `[관망]` 버튼을 답니다.
   - 문구: `오늘 조치할 종목은 없습니다 · 12종목 모두 유지 구간` + `가장 가까운 종목을 관망으로 남겨두면 나중에 성적표에 잡힙니다`
   - 이렇게 하면 **조용한 날에도 판단 1건이 기록되어 사슬이 이어집니다.**
   - 원장 스키마 그대로(`decision: "pass"`, `source: "today"`)라 새 저장소가 필요 없습니다.
4. **보유가 아예 없으면** — 연동 안내 한 줄. 이때만 카드가 안내문이 됩니다.

### 함정

- **관망을 강요하지 마십시오.** 버튼은 제시하되 "기록하지 않아도 됩니다" 가 기본 태도여야 합니다. 매일 억지로 누르게 만들면 원장이 쓰레기가 되고 성적표가 무의미해집니다.
- 같은 종목에 대해 **하루 한 번만** 기록됩니다(`getTodayDecision` 기존 가드).
- 경과 표시에 쓰는 수익률은 `entry_backfilled` 항목이면 **"진입가 추정"** 표시를 남기십시오(S19-2에서 만든 필드).

### 합격선

- 조치할 종목이 0건인 날에도 판단 카드가 **비어 있지 않다.**
- 최근 판단 3건의 경과가 매일 갱신된다.
- 판단 기록이 0건인 신규 사용자도 누를 것이 하나는 있다.
- 아무것도 강요하지 않는 문구다.

## S24-8 · 성적표를 상시 진입로로

### 문제

가장 강력한 자산인 `/pwa/record` 로 가는 길이 **판단을 기록한 뒤에만 생기는 한 줄**입니다. 아직 기록이 없는 사용자는 그런 화면이 있다는 것조차 모릅니다. 닭이 먼저인가 달걀이 먼저인가입니다.

### 할 일

1. **판단 카드 하단에 상시 노출** — 기록 유무와 무관하게 한 줄을 답니다.
   - 기록이 있으면: `내 판단 24건 · 승률 58% · 성적표 →`
   - 30건 미만이면(소표본): `내 판단 8건 · 22건 더 쌓이면 승률을 판정합니다 · 성적표 →`
   - 0건이면: `아직 판단 기록이 없습니다 · 성적표가 어떤 화면인지 보기 →`
2. **0건 성적표 화면** — `/pwa/record` 에 기록이 없을 때 빈 화면 대신 **무엇이 보이게 될지**를 보여주십시오. 예시 수치를 쓰되 `예시` 라고 분명히 표시하고 실제 데이터인 척하지 마십시오.
3. **하단 탭 재검토는 하지 마십시오** — 탭을 늘리는 건 이 스프린트 범위가 아닙니다.

### 합격선

- 오늘 화면에서 성적표로 가는 길이 **항상** 보인다.
- 기록 0건인 계정에서 `/pwa/record` 가 빈 화면이 아니다.
- 예시 수치가 실제 수치로 오인되지 않는다.

# UD — 듣기

## S24-9 · 오늘 브리핑 읽어주기 (한국어)

### 사용자 요구

> 오늘의 내용 (…) 읽어주는 기능 추가

### 할 일

1. **먼저 확인** — `pages/api/english/speak.js` 와 백엔드 `:5005`(edge-tts)의 현재 계약을 읽으십시오. `VOICE_ALLOW` 맵이 있고 언어별 목소리가 지정돼 있습니다. **한국어 목소리를 이 맵에 추가**하면 됩니다(`ko-KR-*`). 새 TTS 스택을 만들지 마십시오.
2. **읽어줄 대본** — 오늘 화면의 **요약 3행 + 판단 카드**를 문장으로 엮습니다.
   - `9월 3일 오늘의 자산입니다. 운용자산 10억 6,700만원, 어제보다 1,200만원 늘었습니다. 오늘 조치할 종목은 없고, 12종목 모두 유지 구간입니다. 지난주 보유 판단한 삼성전자는 이후 2.1% 올랐습니다.`
   - 대본 생성은 `lib/briefingScript.js`(신규) **순수 함수**로. 화면이 쓰는 값과 **같은 소스**에서 만드십시오. 읽어주는 내용과 보이는 내용이 다르면 최악입니다.
   - 숫자는 **읽기 좋게** 변환하십시오("10.67억" → "10억 6천7백만원").
3. **서버에서 하루 1회 생성·캐시** — 대본은 사용자마다 다르지만, 매번 TTS를 부르면 `:5005` 가 죽습니다.
   - 대본 해시를 키로 오디오를 캐시하고, 같은 해시면 재생성하지 않습니다.
   - 동시 요청 폭주를 막는 큐 또는 락을 두십시오.
4. **재생 UI** — 요약 카드에 작은 `🔊 들려주기` 버튼 하나. 재생 중에는 진행 바와 정지 버튼.

### 함정

- **iOS Safari는 사용자 제스처 없이 `audio.play()` 를 허용하지 않습니다.** 자동 재생을 만들지 마십시오. 반드시 버튼 탭에서 시작해야 합니다.
- **MediaSession API** 를 설정하십시오(제목·아티스트·다음/이전). 안 하면 화면을 잠그는 순간 재생이 끊기거나 잠금화면에 아무것도 안 뜹니다. 출퇴근길에 듣는 게 목적이라면 이게 핵심입니다.
- 대본에 **틀린 숫자가 들어가면 화면보다 더 나쁩니다** — 눈으로 검증할 수 없으니까요. S24-1이 끝난 뒤에 붙이십시오.

### 합격선

- 버튼 한 번으로 오늘 요약이 한국어로 재생된다.
- 재생되는 숫자가 화면 숫자와 **완전히 일치**한다.
- 화면을 잠가도 재생이 이어지고 잠금화면에 제목이 뜬다.
- 같은 대본으로 두 번 요청해도 TTS가 한 번만 돈다.

## S24-10 · 외국어 기사 읽어주기 + 언어별 연속 재생

### 사용자 요구

> 외국어는 마지막에 그날 같은 언어를 모아서 연이어 들을 수 있는 기능
> 외국어 경제 주요 기사 읽어주는 기능

현장경제 페이지의 목적을 다시 확인합니다 — *"실시간 주요 뉴스나 정보를 습득하고 외국어로 직접적으로 이해하여 경제 지식과 외국어 활용을 동시에 증가"*. **듣기가 이 페이지의 본체**인데 지금은 개별 재생만 됩니다.

### 할 일

1. **현재 상태 (확인 완료)** — 언어 판정 문제는 없습니다. `pages/pwa/english.js` 는 이미 대메뉴가 **`en`(경제영어) · `zh`(중국어) · `gen`(일반영어)** 이고, 그 아래 `news`·`video`·`idiom` 트랙으로 나뉩니다. 그리고 **`SpeakButton({text, lang})` 컴포넌트가 이미 있어** `/api/english/speak?text=…&language=…` 로 개별 재생을 합니다. `Karaoke` 컴포넌트가 `/api/english/speak-timed` 로 타이밍 마크까지 받고 있습니다.
   → **이 항목은 새 TTS 를 만드는 일이 아니라, 이미 있는 개별 재생 위에 재생목록을 얹는 일입니다.** `SpeakButton` 을 재작성하지 말고 재생 로직만 공용으로 끌어올리십시오.
2. **언어별 재생목록** — 페이지 하단에 `오늘의 듣기` 섹션.
   - `🇺🇸 영어 6편 · 약 12분 [이어 듣기]`
   - `🇨🇳 중국어 4편 · 약 8분 [이어 듣기]`
   - 편수가 0인 언어는 표시하지 않습니다.
3. **연속 재생** — `components/shared/AudioPlaylist.js`(신규). 한 편이 끝나면(`ended`) 다음 편으로. 현재 재생 중인 항목을 목록에서 강조하고, 건너뛰기·이전을 제공합니다.
4. **경제 기사 읽어주기** — 오늘의 뉴스(`/api/today/news`) 중 **외국어 원문이 있는 항목**을 같은 재생목록에 넣습니다. 원문이 없으면 넣지 마십시오 — 한국어 기사를 기계 번역해 외국어로 읽어주는 건 학습에 해롭습니다.
5. **이어 듣기 위치 기억** — 어디까지 들었는지 로컬에 저장하고 다음 방문에 이어서. 동기화 대상은 아닙니다(기기별 재생 위치가 자연스럽습니다).

### 함정

- **MediaSession 은 여기서 필수입니다.** 연속 재생인데 잠금화면 제어가 없으면 쓸 수 없습니다.
- **미리 다 만들지 마십시오.** 10편을 한꺼번에 TTS로 돌리면 `:5005` 가 멈춥니다. 현재 재생 중 항목의 **다음 한 편만** 미리 준비하십시오.
- 중국어 기본 목소리는 이전 작업에서 **남성(`zh-CN-YunxiNeural`)** 으로 지정했습니다. 기존 오디오 파일이 여성 목소리로 남아 있으면 연속 재생 중 목소리가 바뀝니다. 재생성이 필요한지 확인하십시오.
- 셀룰러 데이터 소모 — 자동으로 여러 편을 내려받지 마십시오.

### 합격선

- 같은 언어 항목을 이어서 들을 수 있고, 한 편이 끝나면 자동으로 다음이 재생된다.
- 잠금화면에서 다음/이전/정지가 동작한다.
- 원문이 없는 기사는 재생목록에 없다.
- 앱을 껐다 켜면 듣던 위치가 기억된다.

# UE — 주기와 보상

## S24-11 · 부동산 주간 현황 주차별 발행

### 사용자 요구

> 부동산 주간 현황도 주차별로 발행

전략 문서에서 부동산의 주기는 **분기·연간**이라고 정의했습니다. 주간 발행은 그와 충돌하지 않습니다 — **분기 단위로 움직이는 시장의 주간 관찰 기록**이라는 성격이면 됩니다. 다만 **매주 큰 변화가 있는 척하지 마십시오.**

### 할 일

1. **현재 상태 (확인 완료 — 발행 틀이 이미 있습니다)**
   - `content/weekly/2026-W32.md` … `2026-W35.md` 가 이미 **ISO 주차 파일**로 쌓이고 있고, `pages/pwa/weekly.js`(74줄, `ReportShell` + `getStaticProps`)가 이걸 읽어 보여줍니다.
   - frontmatter 필드: `week` · `monday` · `friday` · `dominant_regime` · `avg_heat` · `total_trades` — **시장 주간 리포트**입니다.
   - 생성은 백엔드 스크립트가 마크다운을 커밋하는 방식입니다(`[auto] Daily report` 커밋과 같은 패턴).
   - → **새 발행 체계를 만들지 마십시오.** 같은 주차 파일에 부동산 블록을 더하는 것이 정답입니다. 한 주에 리포트가 둘로 갈리면 사용자는 둘 다 안 봅니다.
2. **같은 파일에 부동산 블록 추가** — `content/weekly/YYYY-Www.md` frontmatter 에 `realestate:` 블록을 더하고, `weekly.js` 에 부동산 섹션을 추가합니다. 화면에는 `2026년 36주차 (8/31~9/6)` 형태로 기간을 명시합니다.
3. **주간 스냅샷** — 매주 월요일, 지난주 부동산 지표를 한 건 적립합니다.
   - 내 단지 실거래 건수·평균가, 지역 대장 단지 가격, 저평가 단지 목록, 신고가 발생 건수.
   - 소스는 **기존 API 재사용**(`/api/pwa/re/feed`, `/api/pwa/re/briefing`, `/api/input/re-spot`). 새 수집기를 만들지 마십시오.
   - 적립은 서버(백엔드 크론)가 낫습니다 — 부동산 데이터는 사용자별이 아니라 지역별이므로.
4. **지난주 대비** — 이번 주 값과 지난주 값의 차이를 표시합니다. **거래가 없었으면 "지난주 실거래 없음" 이라고 정직하게** 쓰십시오. 이게 부동산의 정상 상태입니다.
5. **오늘 화면 연결** — S23 T-6의 `todayCadence` 에 **월요일 훅**을 하나 더 추가합니다: `지난주 부동산 · 내 단지 실거래 2건 · 평균 24.1억`. 데이터가 없으면 훅을 반환하지 않습니다.

### 합격선

- 주차 번호와 날짜 범위가 화면에 명시된다.
- 실거래가 없던 주에도 "없음" 이 표시되고 빈 화면이 아니다.
- 월요일 오늘 화면에 부동산 주간 훅이 뜬다(데이터가 있을 때).
- 새 데이터 수집기를 만들지 않았다.

## S24-12 · 활동 토큰과 외국어 테스트

### 사용자 요구

> 충실히 활용 시 토큰 발행하여 외국어 테스트 등 보너스 기능 부여

### 먼저 — 설계 원칙 (이걸 어기면 앱이 나빠집니다)

이 기능은 잘못 만들면 **자산관리 앱을 게임처럼 보이게 만들어 신뢰를 깎습니다.** 다음을 지키십시오.

1. **토큰은 '이미 한 일의 기록'이지 '더 하라는 압박'이 아닙니다.** 알림·배지·붉은 점으로 재촉하지 마십시오.
2. **연속 일수(streak) 금지.** S23 T-10에서 이미 정한 원칙입니다 — 하루 끊기면 오히려 이탈을 부릅니다.
3. **잔액을 홈 상단에 크게 띄우지 마십시오.** 자산 숫자 옆에 포인트가 크게 있으면 자산관리 앱이 아니라 적립 앱으로 보입니다. 성적표 화면이나 설정 근처가 적당합니다.
4. **금전 가치가 없음을 명시**하십시오. 환금성이 생기면 전자금융거래법 이슈가 됩니다. `앱 내 기능 이용에만 사용 · 현금 교환 불가`.
5. **하루 상한**을 두십시오. 무한 적립은 판단을 남발하게 만들고 원장을 오염시킵니다.

### 할 일

1. **`lib/activityToken.js`(신규)** — 키 `onehub_tokens_A`/`_B`, `SYNC_KEYS` 등록(S22-3·S23 T-10과 같은 방식).
   - **기존 `lib/gameWallet.js`(가상 대결 지갑)와 절대 섞지 마십시오.** 다른 개념입니다.
2. **획득 규칙** (하루 상한 포함)
   | 행동 | 토큰 | 하루 상한 |
   |---|---|---|
   | 판단 1건 기록 | 2 | 6 |
   | 외국어 1편 끝까지 청취 | 3 | 9 |
   | 오늘 브리핑 청취 | 1 | 1 |
   | 주간 리포트 열람 | 5 | 주 1회 |
   - **"끝까지"의 정의를 코드에 못 박으십시오** — 재생 시간의 90% 이상. 열자마자 닫는 것으로 적립되면 안 됩니다.
3. **사용처 — 외국어 테스트**
   - `pages/pwa/english-test.js`(신규) 또는 현장경제 페이지 내 섹션.
   - **그날 들은 기사에서 출제**하십시오. 일반 어휘 시험이 아니라 **오늘 들은 내용의 이해도 확인**이어야 목적("외국어로 직접적으로 이해")에 맞습니다.
   - 문항은 기존 기사 데이터로 만들 수 있는 것만 — 무리하면 백엔드에 LLM 호출이 필요해집니다. **1차는 규칙 기반**(핵심 용어 빈칸, 요약 문장 고르기)으로 하고, 어려우면 결과 문서에 한계를 적으십시오.
   - 응시 비용 10토큰. 결과는 성적표(`/pwa/record`)에 **외국어 항목**으로 함께 쌓입니다.
4. **표시 위치** — 현장경제 페이지와 성적표에만. 오늘·종합자산 화면에는 넣지 마십시오.
5. **위조 가능성 명시** — 지금은 클라이언트 저장이라 조작 가능합니다. **자기 기록용으로는 문제없지만**, 나중에 실제 보상(할인·현금성)과 연결하려면 서버 검증이 필요합니다. 이 사실을 결과 문서에 남겨 나중에 함정에 빠지지 않게 하십시오.

### 합격선

- 판단 기록·청취 완료 시 토큰이 적립되고 하루 상한이 동작한다.
- 오늘·종합자산 화면에 토큰이 노출되지 않는다.
- 외국어 테스트가 **그날 들은 기사**에서 출제된다.
- `현금 교환 불가` 문구가 있다.
- 연속 일수 배지가 없다.
- `gameWallet` 과 키·개념이 분리돼 있다.

1. **CRLF** — 저장소 전체가 CRLF. 파일을 통째로 다시 쓰지 말고 부분 편집하십시오.
2. **`next build --webpack`** — Turbopack 프로덕션 빌드는 하이드레이션을 깨뜨려 PWA 전체가 먹통이 됩니다.
3. **N1 단일 원장** — 총자산·운용자산 합산은 `lib/ledger.js` 하나뿐. 화면은 읽기만.
4. **UI 중복 금지** — 두 화면에 필요하면 `components/shared/` 로 추출(`KisHoldingsCard`·`Sparkline` 선례).
5. **`alert()` 금지** — 결과는 인라인으로.
6. **없으면 없다고 말한다** — 단, **이번 스프린트에서는 카드를 지우지 말고 왜 없는지를 쓰십시오.** 이것이 S24의 핵심 교정입니다.

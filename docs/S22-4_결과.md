## 왜
도넛은 정보일 뿐 판단이 아니다. 목표가 있어야 이탈이 생기고, 이탈이 있어야 조치가 나온다.

## 한 것
1. **자산군 단위 목표(신규 축)** — `lib/targetClass.js`: 키 `onehub_target_class`(`{stock,etf,realestate,cash}` 합 100). 기존 `onehub_target_alloc`(ETF 내부 국내/해외)와 **다른 축**. 프리셋 안정형/중립형/공격형. `SYNC_KEYS` 에 등록(기기 간 동기화).
2. **실거주는 분모에서 제외** — `computeClassDrift(op, target)` 의 op = 운용 breakdown(주식·ETF·**투자용** 부동산·현금). assets.js 의 기존 운용 분리(`invRealtyUk`·`opTotal`, 실거주 제외)를 그대로 사용. 이탈은 **비중이 아니라 차이(%p)** 로 표시.
3. **종합자산 노출** — `pages/pwa/assets.js` 에 목표 배분 카드: 설정 시 "ETF가 목표보다 +15%p 많습니다" 형태 한 줄 + 자산군별 현재%/목표%/이탈. 미설정이면 "목표 배분을 정하면 이탈을 알려드립니다" + 프리셋 버튼(추측 기본값 없음).
4. **온보딩 스텝** — `pages/pwa/onboarding.js` 성향 결과 화면에 프리셋 3개 택1(건너뛰기 허용). 스텝 인덱스 재번호 없이 삽입(회귀 위험 최소).
